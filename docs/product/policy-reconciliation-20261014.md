2026-10-14, 검토용·미게시. 제품 소스 `57599bc` 이후 제품 코드 변경 없음 기준. [Figma 원문 3종](figma-policy-source-20261013.json), [가입 계약](../development/signup-consent.md), [S5·S6 계약](../development/achievements-support.md)을 대조했다. 이 문서는 확정된 처리 사실과 교체 문안 후보이며 최종 이용약관·처리방침·위치 약관이나 실제 동의 이력이 아니다. 운영 DB에 본문을 등록하지 않았다.

## 구현 사실에 맞는 교체 문안 후보

다음 문장은 운영자 정보와 기간을 확정할 때 사용할 초안이다. 법적 처리 근거·필수/선택 구분·위탁/국외 이전·권리 행사·분쟁 조항을 대신하는 완성 약관은 아니다.

**기록 보관·동기화:** “RunPen은 코스와 러닝 기록을 먼저 이용자의 기기에 저장합니다. 로그인만으로 기기의 기존 기록을 계정에 연결하거나 서버에 업로드하지 않습니다. 이용자가 개인 기록 동기화를 켜면 해당 계정의 코스와 종료한 러닝 기록을 서버에 저장하고 복원할 수 있습니다. 로그아웃하거나 동기화를 끄는 것만으로 이미 저장한 기록이 삭제되지는 않습니다.”

**위치와 계산:** “내 위치 확인과 러닝 기록에는 기기의 위치 권한을 사용합니다. 러닝 중에는 위도·경도·시각·정확도를 기록하고 거리와 안내 상태를 계산합니다. 온라인 코스 계산에는 선택한 계산 중심·거리·도형 또는 윤곽을 계산 서버로 전달하며, 경사 조회에는 코스의 표본 좌표를 고도 제공 서비스로 전달합니다. 위치 권한은 기기 설정에서 변경할 수 있습니다.”

**이미지·사진:** “코스용 이미지 윤곽은 기기에서 추출하며 이미지 원본을 외부 AI 서비스로 보내지 않습니다. 프로필 사진 업로드는 별도 기능입니다. 이용자가 저장을 선택한 프로필 사진은 기기에서 크기와 형식을 변환하고 위치 메타데이터 등을 제거한 뒤 비공개 저장소로 전송합니다.”

**공유:** “링크 공유를 선택하면 제목·거리·활동 시간과 경로 좌표를 포함한 공유 사본을 만들고, 해당 링크를 가진 사람이 조회할 수 있습니다. 이미지 카드에는 경로 윤곽·거리·시간·페이스와 기본으로 닉네임·날짜가 표시되며, 닉네임과 날짜는 숨길 수 있습니다. 링크 공유 중단은 이미 다른 앱으로 전달하거나 내려받은 이미지·GPX·복사본까지 회수하지 않습니다.”

**탈퇴:** “탈퇴가 완료되면 RunPen 계정과 서버의 해당 개인 자료를 삭제합니다. 현재 정책에서는 이 기기에 저장한 코스와 러닝 기록을 비로그인 기록으로 보관합니다. 서버에만 있던 자료는 복원할 수 없으며, 기기에 남은 기록은 이용자가 별도로 삭제할 수 있습니다. 다른 계정으로 로그인해도 보관된 기기 기록이 자동으로 해당 계정에 업로드되지는 않습니다.”

**문의:** “문의 전송 시 계정 식별값·문의 유형·제목·내용과 이용자가 선택해 입력한 이메일을 문의 처리에 사용합니다. GPS 경로나 사진은 자동 첨부하지 않습니다. 접수 결과를 확인하지 못한 경우 같은 요청번호로 재확인하며, 서버에서 접수를 확인한 뒤 접수번호를 표시합니다.” 문의 보유 기간·답변 담당/채널은 확정 후 이어서 명시한다. 운영 SQL 적용 전에는 이 기능이 운영 접수 가능하다고 게시하지 않는다.

## 게시 전 남은 사실·결정

1. 운영자 법적 명칭/주소, 문의 연락처, 개인정보·위치정보 책임자/연락처, 실제 공고·시행일을 확정한다. 현재 요청한 운영자명·문의 이메일·시행일 답변은 대기다.
2. 문의·인증/서버 접근 로그·삭제 표식·백업별 보유 기간과 실제 정리 담당/방법을 확정한다. 문의의 기한 삭제를 택하면 정리 구현/검증까지 포함한다. 기간 숫자를 문구에만 넣지 않는다.
3. Supabase·Google Cloud·Cloudflare·MapTiler 및 소셜 제공자의 실제 계약 주체·처리 업무·처리 국가/재수탁·로그/백업 조건을 확인해 위탁/제공/국외 이전 표를 완성한다. [10-02 설정 기록](../planning/cloud-services-and-accounts.md)의 Supabase 서울과 [Cloud Run 서울 기록](../development/cloud-run-routes.md)만으로 전체 처리가 국내라고 결론 내리지 않는다.
4. 대상 연령과 위치정보 관련 동의·운영 절차를 확정한다. OS 권한·필수 가입 동의·위치정보 처리 문안을 구분한다.
5. 문안 확정 후 S1의 불변 정책 버전과 S6의 공개 처리방침/위치 약관을 같은 실제 처리 기준으로 게시한다. 현재 이용약관 뷰어는 S1 활성 버전 본문을 재사용하지만 개인정보 동의문과 전체 처리방침은 별도 문서다.
6. 기존 수동 배포 이력/구조를 대조한 다음 지원 SQL과 게시 데이터를 적용한다. 실제 로그인 계정의 문안 열람·필수 동의·문의 접수/중복 복구·공지 게시/오프라인 복귀를 확인하고 시험 자료를 정리한다. 최종 정책이 없는 상태에서 동의를 대리 생성하거나 예시 공지를 운영 게시하지 않는다.

현재 단계는 기술 정합성 대조와 교체 문안 준비까지다. 운영자 결정·최종 문안 검토·게시/실제 운영 검증이 남아 있으므로 S6 운영 완료로 분류하지 않는다.
