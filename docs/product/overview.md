## 제품과 출처

- 서비스명 **RunPen**, 저장소·기술 프로젝트명 Running Art. 원하는 도형을 실제 길 위의 러닝 코스로 만들고, 달린 기록을 작품과 성취로 남기는 모바일 앱이다.
- [Figma UI](https://www.figma.com/design/QYRGII8OdvQB1SrtH3BA08?node-id=0-1)가 화면 기획의 1차 기준이다. prototype은 이동 흐름 참고, component는 공통 표현 원본, 보관함은 과거 시안이다.
- 개인 Figma 연결로 UI의 **51개 최상위 프레임**을 조회했다. 화면·상태·공유 결과 시안 41개, 별도 상품 비교표 1개, 구역 표제 9개다. 화면의 텍스트 909개 + 보조 프레임 36개 + 최상위 주석 51개 = 페이지 TEXT **996개 전체**를 원문과 노드 ID로 보존했다. 41개가 모두 독립 앱 경로라는 의미는 아니다.
- [UI 조회 근거](figma-ui-inventory-20261011.json), [prototype 연결 근거](figma-prototype-links-20261011.json). prototype의 반응 노드 152개·중복 제거 화면 연결 133개를 보조로 확인했다. 구매와 추천 화면은 스크린샷도 대조했다. 전체 화면의 픽셀 검수·모든 인터랙션 실행 검증을 했다는 의미는 아니다.
- 우선순위는 **사용자의 명시적 최신 결정 → 확정 제품 문서 → 현재 UI → 보조 prototype/과거 시안**이다. 화면의 예시 데이터·문구만으로 결제 정책이나 알고리즘 규칙을 확정하지 않는다.

## 전체 사용자 경험

첫 진입/가입 또는 게스트 → 홈 → 위치·거리·도형 설정 → 생성 확인 → 후보 비교/상세 → 저장 또는 러닝 준비 → 지도/집중 안내 → 중도 종료 또는 완주 → 기록·배지 → 이미지/링크 공유 → 재도전.

## 과금 정책 — 현재 기준, 변경 가능

2026-10-11 사용자가 [현재 비즈니스 모델 이미지](assets/business-model-20261011.png)를 제공하며 계속 바뀔 수 있다고 명시했다. **아래 표가 현재 개발 기획 기준이며 Figma의 다른 수치보다 우선한다.** 최종 불변 가격이나 지금 결제를 배포하라는 지시가 아니다. 변경 이력과 미정 동작은 [비즈니스 모델](business-model.md)에서 관리한다.

| 상품 | 가격 | 추가 생성 횟수 | 구매 후 보관함 한도 |
| --- | --- | --- | --- |
| 무료 회원 | 무료 | 가입 시 5회 | 3개 |
| 기본 팩 | 1,900원 | 10회 | 5개 |

생성 횟수는 추가되는 횟수, 보관함은 구매 후 한도로 구분한다. 기본 팩을 보관함 5개 추가로 해석하지 않는다. 현재 UI의 단건 구매·자동 갱신 없음·Google Play·계정 귀속은 흐름 기획으로 유지하되, 표에 없는 재구매/하위 팩 구매/환불 처리까지 확정하지 않는다. 1회 생성 시 최대 5후보·조건 변경 후 재생성 추가 차감은 UI 제안이다. 실패/취소/재시도 차감, 유효기간, 비로그인·오프라인 규칙은 D-03~D-04에서 정한다.

다른 제안의 출처를 폐기하거나 섞지 않는다.

- [10-03 사용자 제공 검토안](assets/billing-policy-draft-20261003.png): 최초 생성 5회·저장 3개, 매일 충전량/상한 미정, 월 2,900원 무제한 구독·추가 이용권 검토.
- UI의 별도 비교표 `153:14524`: 무료 매월 3개·Plus 매월 30개, 월 4,900원으로 검증 시작, 맞춤 코스 첫 1회 체험과 추가 창작 기능.
- UI 구매 화면 `268:9405`: 무료 보관함 5개·기본 10개로 적혀 있으나 현재 표는 각각 3개·5개다. 성공 화면의 기본 팩 15개 및 구매 내역의 10개도 수정 대상이다.
- 이용약관 `47:7114`: 구독 정의와 AI 기능용 선불 이용권 설명이 혼재.

**D-02의 현재 상품 수치는 반영 완료, D-03~D-04의 처리 규칙은 후속이다.** 상품 카탈로그·정책 버전과 화면/권한 로직을 분리해 변경 가능하게 설계한다. 이번 문서 작업에서 결제나 이용 제한을 적용하지 않으며 기존 자료를 소급 삭제·제한하지 않는다. 현재 Cloud Run 전체 보호 한도는 상품 횟수와 별개다. 상세 쟁점은 [결정 목록](figma-service-analysis.md#결정-목록)을 따른다.

## 데이터·서버 경계

- 앱은 화면과 로컬 자료·실시간 GPS·안내를 담당한다. 새 서비스 화면에서 기존 저장/안내 엔진을 다시 구현하지 않는다.
- Cloud Run은 온라인 코스 계산, R2는 전국 도로 파일, MapTiler는 지도·필요 시 고도, Supabase는 인증·계정별 자료·사진·동기화다. 공개 공유는 기존 Cloudflare/Supabase 경로를 사용한다.
- 동의 이력·다일 도전·배지·상품 권한·문의는 별도 도메인 설계가 필요하다. 이번에 DB 테이블·서버를 만들지 않는다.
- AI 브리핑/생성 이미지는 약관에 있으나 현재 전용 화면과 확정 구현 범위가 없다. 기존 Gemini 미도입 결정을 유지하고 D-13에서 정리한다. 도형 이미지 업로드는 생성형 AI와 별개의 입력 기능이다.
- 시뮬레이션은 기존 기능으로 보존하고 서비스 노출 위치는 별도 결정한다. 주소 검색·혼잡도·칼로리처럼 근거 없는 값을 화면 예시로 채우지 않는다.
- 앱/지도 전체 다크 모드, 접근성·큰 글씨·권한 거부·빈 화면·오류·오프라인·재진입을 각 기능의 완료 조건에 포함한다.
