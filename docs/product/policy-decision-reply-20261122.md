- 원본: 「RunPen 정책 확정 및 피그마 정정 요청」(2026년 11월 22일)
- 상태: 기획자 순차 확인 결과 반영 완료. 기술·계약·개인정보·결제 경로의 사실 검증은 아래 후속 과제로 관리
- 용도: 개발·디자인·운영 반영 기준. 고객에게 그대로 게시할 이용약관은 아님
- 적용일: 실제 구현 및 필수 검증 완료 후 별도 확정. 작성일을 고객 대상 시행일로 사용하지 않음

## 1. 상품 및 공통 기준 — 확정

| 구분 | 현재 가격 | 생성권 | 저장권 | 런칭 종료 후 적용 예정가 |
| --- | ---: | ---: | ---: | ---: |
| 가입 최초 무료 혜택 | 무료 | 5회 | 10회 | 해당 없음 |
| 기본 팩 | 1,900원 | 10회 | 20회 | 2,500원 |
| 플러스 팩 | 2,900원 | 30회 | 60회 | 3,900원 |
| 확장 팩 | 4,900원 | 60회 | 120회 | 7,500원 |

- 유료 상품은 일회성 충전 상품이다. 월 구독·자동결제·매월 무료 추가 지급·잔액 초기화는 제공하지 않는다.
- 플러스 팩 저장권은 60회다. 이전 50회 표기를 모두 수정한다.
- 저장권은 보관 공간이 아니라 저장 횟수다.
- 생성권·저장권의 유효기간은 없다. 회원 탈퇴와 환불에 따른 정산은 각 절을 따른다.
- 생성권과 저장권은 별도 잔액이다. 금액 가치의 비율은 상호 교환 기능을 의미하지 않는다.
- 가입·이용 대상은 만 19세 이상이다.
- 고도 정보는 제공하지 않는다. 관련 UI·혜택 설명·자동 API 조회를 제거한다.
- 출시 초기 유료 상품의 판매 대상 국가는 대한민국, 결제 통화는 원화(KRW)다. 해외에서의 앱 이용 가능 여부를 일괄 제한한다는 뜻은 아니다.
- 모든 표시 가격은 부가가치세를 포함한 최종 결제금액이다. 결제 단계에서 별도 세금을 추가하지 않는다.

## 2. 가격 표시와 변경 — 확정

- 런칭 종료일은 현재 정하지 않는다.
- ‘런칭 특별가’와 ‘런칭 종료 후 적용 예정가’를 구분해 표시한다.
- 판매 이력이 없는 예정가를 과거에 판매한 정상가처럼 표시하지 않는다. 취소선이나 ‘기존 정상가’ 표현으로 과거 판매 이력을 암시하지 않는다.
- 예시: ‘런칭 특별가 2,900원 / 런칭 종료 후 적용 예정가 3,900원’.
- 종료 결정 시 최소 14일 전에 앱 내 공지 및 구매 화면으로 종료일과 변경 가격을 안내한다.
- 기존에 구매한 이용권의 잔여 수량·무기한 조건은 가격 변경 후에도 유지한다.
- 허위 마감·반복 초기화되는 카운트다운 등 실제와 다른 긴급성을 표시하지 않는다.

확정 범위는 두 가격의 구분 표시와 종료 전 사전 공지다. 할인율 표시까지 확정한 것은 아니다. 예정가의 실제 적용 계획과 비교가격 설명의 적정성은 게시 전 확인한다. 예정가라는 명칭만으로 가격 비교의 적법성이 보장되는 것은 아니다.

## 3. 이용권 지급·차감·합산 — 확정

### 3.1 무료 혜택과 계정

- 가입 최초 무료 생성 5회·저장 10회를 지급한다.
- 동일 이용자가 탈퇴 후 재가입하는 경우 무료 혜택을 재지급하지 않는다.
- 동일 이용자 판별 방법, 식별자 보관 근거·항목·기간은 별도 검증한다. 이 결정은 개인정보 무기한 보관이나 추가 본인인증 도입을 승인한 것이 아니다.
- 이용권은 RunPen 계정에 귀속한다.
- 기기 변경·앱 재설치 후에도 동일 RunPen 계정으로 로그인하면 잔여 이용권을 복원한다.
- 다른 계정으로 양도·선물·잔액 이전은 불가하다.

### 3.2 차감 순서와 추가 구매

- 생성권·저장권에 각각 ‘무료 먼저 → 유료는 먼저 구매한 순서’로 차감한다.
- 추가 구매 시 기존 잔여 수량에 새로 구매한 수량을 합산한다.
- 사용자에게는 총 잔여 생성권·저장권을 표시한다.
- 내부에서는 구매 건별 지급·사용·잔여·환불 내역을 구분한다.
- 예: 생성 7회·저장 12회가 남은 상태에서 플러스 팩 구매 → 생성 37회·저장 72회.

### 3.3 생성권 차감

- 코스 생성이 성공하여 결과를 제공했을 때 1회 차감한다.
- 한 번의 생성으로 후보 코스 여러 개를 제공해도 1회 차감한다.
- 생성 실패·결과 없음·시스템 오류는 차감하지 않는다.
- 정상 제공된 결과가 단순히 마음에 들지 않는 경우에는 차감을 유지한다.
- 서버 처리 성공과 앱 결과 전달 실패, 재시도·중복 요청의 판정은 기술 검증 항목이다. 동일 생성 요청의 중복 차감과 결과 미제공 차감을 방지한다.

### 3.4 저장권 차감

| 상황 | 처리 |
| --- | --- |
| 새 코스가 내 코스에 정상 저장됨 | 1회 차감 |
| 저장 실패·시스템 오류 | 차감 없음 |
| 이미 저장된 코스의 이름·메모 수정 | 추가 차감 없음 |
| 같은 코스에 대한 중복 저장 요청 | 중복 저장·추가 차감 방지 |
| 저장 코스 삭제 | 사용한 저장권 반환 없음 |
| 삭제한 코스를 다시 저장 | 새로운 저장으로 1회 차감 |

동일 코스 판별과 요청 중복 방지는 개발자가 구현·검증한다.

### 3.5 잘못 차감된 이용권 복구

- 잘못 차감된 종류와 횟수 그대로 복구한다.
- 생성권은 생성권으로, 저장권은 저장권으로 복구한다.
- 유료 이용권은 원래 구매 건의 잔여 수량으로 복구하여 환불 계산에 반영한다.
- 오차감 복구를 별도의 무상 보상권으로 대체하지 않는다. 원래 무료·유료 지급 출처를 유지한다.

## 4. 환불 기준 — 확정

### 4.1 금액 배분과 계산식

생성 1회의 금액 가치를 저장 2회와 같게 둔다. 현재 모든 팩은 저장 수량이 생성 수량의 2배이므로 상품 금액 중 생성권과 저장권의 전체 가치는 각각 50%다. 각 횟수의 단가는 동일하지 않다.

각 구매 건별로 다음 값을 사용한다.

- P: 해당 구매 건의 실제 결제금액. 예정가나 표시 정상가를 사용하지 않음
- G, S: 해당 구매 건으로 유료 지급한 생성권·저장권 총수량
- g, s: 해당 구매 건의 미사용 생성권·저장권 수량

```text
저장 1회 금액 = P / (2G + S)
생성 1회 금액 = 2P / (2G + S)

환불 산정액 = P × (2g + s) / (2G + S)
최종 환불액 = 환불 산정액의 원 미만 올림
```

- 회당 단가를 미리 반올림하지 않는다. 정수 분자·분모 등 정확한 연산으로 마지막에 올림한다.
- 최종 환불액은 해당 구매 건의 실제 결제금액에서 이미 환불한 금액을 뺀 금액을 초과할 수 없다.
- 별도 위약금·수수료를 공제하지 않는다. Google Play 수수료도 고객 환불액에서 공제하지 않는다.
- 가입 무료권·별도 무상 보상권은 현금 환불 대상이 아니다. 유료권 오차감 복구는 무상 보상과 구분한다.
- 구매 건마다 그 구매의 실제 결제금액과 수량을 사용한다. 다른 구매의 단가를 일괄 적용하지 않는다.
- 이는 RunPen의 잔여권 가치 배분 기준이며, 법이 정한 유일한 환불 공식이라는 뜻은 아니다.

| 기본 팩 | 95원 | 47.5원 |
| 플러스 팩 | 48.3333…원 | 24.1666…원 |

| 모두 사용 | 0회 | 0회 | 0원 |

### 4.2 환불 단위·기한·접수

- 구매 건별로 남은 생성권·저장권 전체를 함께 환불한다.
- 특정 구매 건의 생성권만, 저장권만 또는 일부 수량만 선택하여 환불하는 방식은 제공하지 않는다.
- 다른 구매 건의 잔여 이용권에는 영향을 주지 않는다.
- 환불 신청의 별도 기한은 없다. 미사용 유료 이용권이 남아 있으면 신청할 수 있다.
- 앱 내 문의하기에서 환불을 접수·처리한다.
- 접수 후 3영업일 이내 환급 처리한다. 임의의 승인일을 기준으로 처리 기한을 새로 계산하지 않는다.
- 실제 결제 취소·입금 반영 시점은 결제수단·금융기관에 따라 다를 수 있음을 안내한다. 이 안내로 법정 환급 의무를 유예하지 않는다.
- 오래된 구매 건의 스토어 처리 제한은 개발·운영 확인 사항이다. 처리 제한을 이용권 임의 소멸이나 환불 일괄 거부의 근거로 사용하지 않는다.

### 4.3 환불 중 이용권과 기존 코스

- 접수 시 환불 신청한 구매 건의 미사용 이용권만 일시 사용 제한한다.
- 환불 처리 중 다른 구매 건의 이용권·무료 이용권·기존 코스는 계속 사용할 수 있다.
- 환불 성공 시 해당 미사용 이용권을 회수한다.
- 신청 취소·환불 실패 시 사용 제한을 해제한다.
- 외부 결제 처리 결과가 불명확한 상태를 확정 실패로 오판하여 중복 환불·중복 사용이 발생하지 않도록 정합성을 검증한다.
- 환불 후에도 이미 생성·저장한 코스는 유지한다. 미사용 권리 환불만을 이유로 기존 결과물을 삭제하지 않는다.
- 회원 탈퇴에 따른 데이터 삭제는 별도 기준을 따른다.

## 5. 결제 오류·고객 문의 — 확정

### 5.1 결제 성공 후 이용권 미지급

- 결제 내역을 확인하고 누락 이용권을 지급하는 것을 우선한다.
- 사용자가 다시 결제하도록 유도하지 않는다.
- 지급이 불가능하거나 사용자가 환불을 요청하면 해당 결제를 전액 환불한다.
- 이미 지급·사용된 거래를 미지급 거래로 오인하지 않도록 주문별 지급·사용 여부를 검증한다.

### 5.2 중복 결제

- 같은 상품을 연속 구매하는 경우도 있으므로 연속 구매 자체를 자동 취소하지 않는다.
- 사용자가 중복 결제로 신고하면 각 구매 건의 사용 여부를 확인한다.
- 미사용 구매 건은 전액 환불한다.
- 일부 사용한 구매 건은 잔여 이용권 환불 기준을 적용한다.
- 한 결제 건의 중복 지급 방지와 서로 다른 실제 결제 건의 처리를 구분한다.

### 5.3 접수·안내

- 고객 문의·환불 신청은 앱 내 문의하기에서 접수·처리한다.
- 일반 문의는 접수 후 3영업일 이내 최초 답변한다.
- 추가 확인이 필요하면 최초 답변 기한 안에 진행 상황과 예상 완료일을 안내한다.
- 일반 문의의 최초 답변 기한과 환불의 환급 처리 기한은 별개다. 최초 답변만 하고 환급 처리를 미루지 않는다.
- 탈퇴 후 문의·환불 결과는 접수 시 확인한 이메일로 안내한다.
- 운영 책임자·접수 알림·주말 및 공휴일 처리·실제 지원 연락처는 출시 전 운영 설정으로 확인한다. 미확인 이메일 주소를 문서에 임의 기재하지 않는다.

## 6. 회원 탈퇴·삭제·보존 — 확정 및 검증 구분

### 6.1 탈퇴 시 이용권 정산 — 확정

- 잔여 생성권·저장권과 예상 환불액을 안내한다.
- 사용자는 ‘환불 신청’ 또는 ‘환불 없이 탈퇴’를 선택한다.
- 환불 신청을 선택하면 탈퇴 후에도 필요한 구매·처리 기록을 보존하여 환급을 진행한다.
- 환불 없이 탈퇴하면 잔여 이용권 소멸·복구 불가를 명확히 안내하고 확인받는다.
- 잔여 이용권이나 진행 중인 환불을 이유로 탈퇴 자체를 불필요하게 차단하지 않는다.
- 법정 청약철회·환급 등 소비자의 권리를 일괄 포기시키는 문구로 사용하지 않는다.

### 6.2 공유 링크와 서비스 데이터 — 확정

- 탈퇴 완료 즉시 해당 계정이 발급한 공유 링크를 모두 비활성화한다.
- 링크 수신자도 해당 링크로 코스·러닝 기록을 열람할 수 없도록 한다.
- 이미 제3자가 내려받거나 캡처한 자료까지 회수할 수 있다고 약속하지 않는다.
- 탈퇴 완료 시 일반 서비스에서 즉시 접근을 차단한다.
- 삭제 대상 개인정보·코스·러닝 기록은 지체 없이 삭제한다.
- 법정 보존 기록과 진행 중인 환불·분쟁 처리에 필요한 최소 기록은 일반 서비스 데이터와 분리한다.
- 거래 기록 보존을 근거로 전체 GPS·코스 데이터를 일괄 보존하지 않는다.

### 6.3 법정 보존 — 확정

| 기록 구분 | 법정 보존 기간 |
| --- | ---: |
| 계약 또는 청약철회 등에 관한 기록 | 5년 |
| 대금결제 및 재화 등의 공급 기록 | 5년 |
| 소비자의 불만 또는 분쟁 처리 기록 | 3년 |
| 표시·광고 기록 | 6개월 |

- 필요한 최소 정보만 분리 보관하고 해당 보관 기간 종료 후 삭제한다.
- 한 기록이 여러 보존 근거에 해당하면 필요한 범위·기산점·기간을 항목별로 검토한다.
- 서비스 목적에 계속 필요한 계정별 잔여 이용권 원장과 법정 보존 기록을 구분한다. 유효기간 없는 잔여 유료권의 증빙을 일괄 삭제하여 권리가 사라지지 않도록 설계한다.
- 기록별 정확한 기산점과 저장 항목은 개인정보처리방침에 반영하기 전 확인한다.

### 6.4 아직 검증해야 할 사실

- 동일 이용자의 재가입 판별 방식과 최소 식별자, 보관 근거·기간, 다른 로그인 수단 간 식별 가능 범위.
- 개인정보를 임의로 무기한 보관하는 방식은 적용하지 않는다. 적법한 중복 지급 방지 구현이 불가능하면 기획자에게 대안을 재검토 요청한다.
- 백업·로그의 실제 보관 설정과 삭제 주기, 복원 시 삭제 요청 재반영 절차.
- 탈퇴 후 이메일 안내에 필요한 정보의 보관 범위와 종료 후 삭제 기준.
- 기존 미성년 계정이 있다면 결제·잔여권·데이터 처리 방법. 기존 계정을 확인 없이 일괄 삭제하지 않는다.

## 7. 가입·체중·위치정보

### 7.1 연령 확인 — 확정

- 회원가입 시 ‘만 19세 이상입니다’ 필수 체크박스를 둔다.
- 기본 선택하지 않으며 사용자가 직접 선택해야 한다.
- 미선택 시 가입을 완료할 수 없다.
- 이 연령 확인을 위해 생년월일·신분증을 별도로 수집하지 않는다.
- 이는 자기확인 방식이다. 본인인증으로 실제 나이를 검증했다고 표시하지 않는다.
- 가입 화면·약관·도움말·스토어 설명의 대상 연령을 일치시킨다.

### 7.2 체중과 칼로리 — 확정

- 체중은 선택 입력이다. 입력하지 않아도 가입·이용할 수 있다.
- 미입력 시 계산 기준값 60kg을 적용한다.
- 입력 화면과 칼로리 화면에 기본값 적용 여부를 안내하고 칼로리는 추정치임을 표시한다.
- 사용자는 설정에서 체중을 변경할 수 있다.
- 과거 기록의 칼로리를 체중 변경 시 소급 재계산할지와 기록별 계산 기준값 보존은 구현 사양 확인 과제다. 본 결정에서 소급 변경을 승인한 것은 아니다.

### 7.3 위치 처리·동의 — 실제 구성 확인 후 반영

- GPS·위치·코스 공유의 실제 수집·이용·제공·보관 흐름과 필요한 법적 절차를 확인한다.
- 앱의 OS 위치 권한과 서비스 약관·개인정보 관련 동의를 동일한 절차로 간주하지 않는다.
- 동의 항목·필수 또는 선택 여부·위치정보 관련 신고와 약관 적용 범위는 실제 기능 및 법률 검토 결과에 맞춘다.
- 확인되지 않은 수집 항목·업체·국가를 임의로 고객 문서에 기재하지 않는다.

## 8. 외부 처리·국외 이전 확인 절차 — 확정

1. 개발자가 실제 기술 구성과 데이터 흐름을 정리한다.
2. 운영자가 계약 법인·계약 조건과 대조한다.
3. 개인정보·법률 검토 후 약관·개인정보처리방침·필요한 동의 화면에 반영한다.

확인 항목:

- 외부 업체의 실제 법인명·이용 목적·역할.
- 전달·저장하는 개인정보 항목.
- 처리·저장 국가, 이전 시기·방법.
- 보관·삭제 기준, 재위탁·지원 접근·로그·쿠키 등.
- 국외 이전 적용 여부와 적법한 근거, 고지 또는 동의 등 필요한 절차.

확정한 것은 확인 절차다. 특정 업체·국가·보관 기간이나 모든 국외 이전의 별도 동의 필요 여부를 일괄 확정한 것이 아니다.

## 9. 약관 변경·정책 게시 — 확정

- 일반 약관 변경: 시행 최소 7일 전 공지.
- 이용자에게 불리한 변경: 시행 최소 30일 전 공지하고 앱 알림 또는 이메일로 개별 안내.
- 위 기간은 RunPen의 운영 기준이다. 모든 변경에 공통 적용되는 유일한 법정 기간이라는 뜻은 아니다.
- 법령상 별도 동의가 필요한 변경은 공지만으로 대체하지 않는다.
- 런칭 특별가 종료는 별도의 최소 14일 전 안내 기준을 적용한다. 약관까지 함께 변경하면 해당 약관의 공지 기간도 충족한다.
- 실제 구현·계약·개인정보·결제 검증 후 공고일과 시행일을 정한다.
- 기존 사업자·주소·연락처는 확인 없이 변경하지 않는다.
- 개인정보 열람·정정·삭제 등 권리 요청 절차·법정 처리 기한도 개인정보 문서 작성 시 별도 대조한다.

## 10. 러닝 시작 방식 — 확정

- GPS 위치 확인 → 사용자가 시작 버튼 선택 → 현재 위치에서 러닝 기록 시작 → 추천 코스에 합류.
- 추천 코스 시작점에 도착하기 전에도 기록을 시작할 수 있다.
- 합류 전 이동 구간도 실제 러닝 기록에 포함한다.
- 최초 합류와 일시정지 후 재개·코스 이탈 후 복귀를 구분해 안내한다.
- 자동 합류 판정의 거리 기준·알림·GPS 불량 시 동작과 기존 재개·복귀 동작은 실제 구현을 대조한다. 본 문서가 해당 세부 동작의 검증 완료를 의미하지 않는다.

## 13. 개발·운영 최종 회신 요청

다음 항목은 기획자에게 임의의 기술 사실을 선택하게 하는 대신, 담당자가 실제 근거와 검증 결과를 회신한다.

1. Google Play 부분 환불 지원 범위와 결제수단별 제약, Console·API 구분, 오래된 주문의 처리 제한과 필요한 대체 환급 경로. 법정 의무와 확정한 신청 기한 없음 정책을 충족하는 운영안.
2. 결제 검증·지급·차감·복구·환불 잠금·해제·회수의 정합성, 중복 요청과 동시 사용 방지. 소비형 상품의 스토어 조회만으로 복원을 가정하지 말고 계정별 서버 원장으로 검증.
3. 무기한 유료권의 장기 원장 보존, 탈퇴 후 환급 처리와 최소 정보 보관, 재가입 무료 혜택 방지의 적법하고 실행 가능한 방식.
4. 외부 처리·국외 이전·위치정보·백업·로그·개인정보 권리행사의 사실 및 법률 검증. 서비스 종료 시 정산 등 공개 약관에 필요한 추가 조항은 법률 검토 과정에서 제시하며, 미확정 내용을 승인된 정책으로 넣지 않음.
5. 운영 책임자·결제 취소 권한·앱 내 접수 알림·결과 이메일·법정 기록 접근통제 및 기간별 삭제 설정.
6. F01~F04 및 공통 항목별 반영 범위·완료 일정·화면 링크·검증 결과.
7. 고객 공개 문서 최종본, 게시·시행 일정, 미해결 쟁점과 필요한 추가 기획 결정 목록.

본 문서는 기획자 의사결정을 정리한 최종 회신서다. Figma·GitHub·운영 서버 수정이나 고객 정책 게시를 수행한 결과가 아니다.
