# Figma 전체 서비스 기획 분석

기준일: 2026-10-11. [제품 개요](overview.md)와 [현재 비즈니스 모델](business-model.md)을 함께 읽는다. **기존 기술 기능을 재사용해 실제 서비스 흐름을 만드는 분석**이다. 아래 “필요”는 신규 구현 요구이지 완료 보고가 아니다.

## 조회 범위와 해석

[UI 원본](https://www.figma.com/design/QYRGII8OdvQB1SrtH3BA08?node-id=0-1)의 최상위 화면/상태 41프레임, 상품 비교표 1개, 구역 표제 9개와 페이지 TEXT 996개 전체를 [조회 JSON](figma-ui-inventory-20261011.json)에 보존했다. prototype은 [152개 반응 노드·133개 화면 연결](figma-prototype-links-20261011.json)을 확인했다. component는 [완료된 공통 UI](../development/common-ui.md)를 재사용하며 보관함 페이지는 새 요구사항으로 편입하지 않는다.

스크린샷으로 추천 카드·도형 점선 토글·하단 탭과 구매 상품 선택/혜택/안내를 대조했다. 보이지 않는 동작·계산식·에러 상태를 그림만으로 확정하지 않는다. 텍스트 추출은 숨겨진 텍스트도 원문 근거에 포함하며, 전체 픽셀·프로토타입 클릭 검증과 구분한다.

프레임명이 중복되어 **노드 ID가 식별 기준**이다. `LOG-13`은 구매·구매 성공·구매 내역에 반복되고 `MY-11`은 주변 “구매내역” 주석과 달리 로그아웃 확인이 겹친 마이페이지다. 예전 문서의 구역 ID 대신 아래 실제 화면 ID를 사용한다.

## 기능별 분석

### 1. 진입·가입·로그인

**UI 의도:** 최초 가입 화면에서 소셜 또는 게스트 선택. 기존 회원은 로그인, 소셜 신규 사용자는 이메일 표시·선택 닉네임/사진·필수 이용약관/개인정보 동의·선택 마케팅 동의 후 완료한다. 게스트의 코스 생성에는 별도 가입 유도 화면이 있다.

**기반:** `modules/auth`, `features/auth`, `modules/account`의 3종 소셜·세션 복원·프로필/사진·계정별 접근. 신규 가입의 제품 완료 상태와 동의 이력은 별도다.

**필요:** 미가입/가입 진행/완료/세션 만료를 구분하고 소셜 취소·이메일/사진 미제공·재시작·오프라인·계정 변경을 처리한다. 필수 전체 동의가 선택 마케팅까지 켜지지 않게 한다. 가입 도중 이탈 후 재진입과 동의 정책 버전 변경을 설계한다. OS 위치 권한 허용은 제품 약관 동의 이력이 아니다. 가입 완료/보너스 지급은 중복 복귀에도 한 번만 처리하도록 설계한다.

**확인:** 현재 비로그인 계산 허용과 가입 유도(D-01), 닉네임 선택 입력의 빈값 처리(D-12), 동의 항목·내용/재동의(D-05). 소셜 이메일 표시는 이메일 로그인 기능 요청이 아니다.

### 2. 홈·내비게이션

**UI 의도:** 첫 방문은 도형 선택, 미완료 코스가 있으면 마지막 러닝 날짜·달린 거리/목표·진행률·이어달리기, 반복 이용자는 최근 기록·연속 일수·월간 누적·최근 코스·오늘 추천을 본다. 상단은 생성/저장 현황과 안내 메뉴, 하단은 5탭이다.

**필요:** 계정/자료 로딩 중을 “첫 방문”으로 잘못 표시하지 않는다. 활성 러닝 복귀, 미완료 도전 선택, 일반 홈의 우선순위를 정한다. 실시간 탭을 열었다고 GPS를 자동 시작하지 않으며 진행 중 러닝이 있으면 해당 세션에 연결한다. 탭 이동·뒤로 가기·딥링크가 생성 입력과 활성 러닝을 잃지 않아야 한다.

**간극:** 현재 `app/index.tsx`는 기능 테스트 메뉴다. 총 거리/시간/완주 집계는 있지만 월간·연속일·추천 공급 기준은 별도다. “8일 전, 59%”는 제품상 다일 도전으로 해석될 여지가 있으며 현재 체크포인트 재개만으로 완료 처리하지 않는다(D-06).

### 3. 코스 입력·생성·후보

**UI 의도:** 현재 위치/장소 검색, 1~10km 눈금과 더 먼 거리, 12도형, 직접 그리기/이미지 업로드. 생성 직전 조건/남은 횟수/차감 확인. 결과는 지도와 원본 도형 점선 토글, 최대 5후보의 유사도·거리·달리기/도보 시간·난이도 비교, 조건 수정·상세·러닝 진입이다.

**기반:** Cloud Run→기기 fallback, 전국 도로/캐시, 3/5/7km·9도형·사용자 한 획, 후보/저장/GPX. UI의 12도형은 하트·별·강아지·고양이·사람·물고기·뼈다귀·거북이·아이스크림·딸기·구름·왕관이다. 현재 기본 ID는 heart/star/cat/rabbit/house/diamond/bolt/fish/arrow다. 도형 이름/아이콘만 교체하지 않고 윤곽·정규화·저장 호환을 검증한다.

**필요:** 위치 선택·권한 거부·지도 이동 후 계산 기준, 거리 입력/상한, 그리기 취소/적용, 이미지 선택/윤곽 추출/미리보기/오류/파일 제한. 후보 부족/0개, 서버 지연·429·기기 전환·취소/재계산과 중복 탭을 지원한다. 선택 후보와 상세/저장/러닝이 같은 결과 사본을 사용해야 한다.

**확인:** 장소 검색은 기존 제외 결정 유지. 목표 거리 UI 확장·도형 범위(D-07), 점수→유사도%와 예상 시간/난이도(D-08), 차감/후보 부족(D-03). 현재 점수에 %만 붙이거나 5개를 가짜로 채우지 않는다. Figma “출발지”는 탐색 중심과 실제 코스 시작점/합류 지점을 구분해 표시한다.

### 4. 상세·보관함·기록 관계

**UI 의도:** 생성 후보 상세와 저장 코스 상세에 지도·코스명·주소·거리·예상 시간·난이도·참고 사항, 저장/GPX/시작 또는 삭제. 보관함은 저장 코스/완주 기록 탭, 진행중 표시·용량, 기록은 월별 날짜와 상세/재도전이다.

**기반:** `modules/courses`·`modules/running`의 저장 CRUD/기록/코스 사본, `modules/sync`의 계정별 동기화, `modules/terrain`의 고도. 러닝 코스 사본은 원본 이름 변경/삭제에 영향받지 않는다.

**필요:** 후보(임시)·저장 코스(재사용 설계)·도전(진행 목표)·러닝 세션(실제 이동)·완주 성취를 분리한다. 하나의 코스를 여러 번 달릴 수 있으므로 코스와 기록은 1:1이 아니다. 러닝 기록 삭제를 “코스 삭제”와 혼용하지 않는다. 재도전은 기존 기록을 수정하지 않고 새 세션을 만든다. 중도 종료 기록을 완주 탭에서 어떻게 찾을지 정한다(D-09).

**확인:** 저장하지 않고 러닝 시작하는 경우의 보관/용량, 저장 코스 삭제 시 진행 중 도전, 완료 기록/배지 삭제 범위(D-09), 한도 대상(D-04). GPX와 실제 GPS 기록 내보내기는 대상 경로를 구분한다. 원본의 “GTX”는 GPX 오기로 정리 대상이다.

### 5. 러닝·종료·이어달리기

**UI 의도:** 지도/집중 전환, 정상/이탈 안내·진동, 남은 거리·시간·페이스·다음 회전, 일시정지/종료. 설정에서 음성·기본 화면·화면 잠금, 저장하고 종료. 정상 완주는 축하/공유로 간다.

**기반:** 임의 지점·양방향 출발·도로 합류/복귀·연속 한 바퀴, 실시간 GPS·네이티브 백그라운드·중단 체크포인트·음성/진동. 실제 이동/장시간 배터리 검증은 기존 확인 범위를 넘어선 후속이다.

**필요:** 준비→접근→달리기↔일시정지→종료/완주 확인의 명시적 상태와 복원. 코스 이탈, GPS 불안정·위치 OFF·권한 해제·잠금·앱 종료·동기화 지연을 표시한다. 종료 버튼은 완주 성공 자체가 아니다. prototype의 종료→축하 연결은 시연이며 현재 판정 결과에 따라 분기한다. 접근 거리/실제 이동 거리와 코스 진행률을 구분한다.

**확인:** 여러 날짜의 도전/한 바퀴 완주 관계(D-06), “화면 잠금”이 앱 내 터치 잠금인지 OS 백그라운드 설정인지(D-10). 배경 추적 스위치를 문구만 바꿔 화면 잠금으로 쓰지 않는다. 러닝 탭/홈 복귀 시 네이티브 세션을 중복 생성하지 않는다.

### 6. 완주·배지·통계·공유

**UI 의도:** 완주 도형/배지·거리·시간·평균 페이스·칼로리, 축하·공유. 내 배지와 횟수, 기록 재도전으로 재방문을 유도한다. 공유는 Story 1080×1920, 피드 1080×1350, 정사각 1080×1080 선택안이다.

**기반:** 실제 기록/완주 결과·코스 스냅샷·계정 집계·공개 중단 가능한 링크·OS 공유. 배지 지급, 연속일, 칼로리, 이미지 렌더링은 별도다.

**필요:** 배지 기준/중복 획득/소급 적용/삭제 후 통계 규칙과 시간대·활동시간 정의. 확정 전의 칼로리는 가짜 숫자로 채우지 않는다. 이미지 미리보기→저장/OS 전달은 같은 렌더링 결과를 사용하고 실패/공유 취소를 처리한다. 앱 미설치 수신자용 링크 기능과 카드 이미지 생성은 각각 유지한다. Instagram 등 외부 앱 아이콘이 직접 게시 API 구현 요구를 뜻하지는 않는다.

**확인:** 성취·칼로리(D-11), 공유할 위치/닉네임·날짜·출발점 공개 범위(D-14). 경로 원본·계획·실제 GPS는 섞지 않는다. AI 생성 이미지와 실제 코스로 만든 카드 렌더링을 구분한다.

### 7. 마이페이지·설정·운영 안내

**UI 의도:** 프로필/소셜 계정, 상품/잔량, 총 거리/완주/시간·배지, 음성·위치·화이트/다크, 구매/환불 안내·로그아웃·탈퇴. 서비스 소개·FAQ 10문항·문의 유형/제목/내용/선택 이메일·공지 목록/상세·약관 3종.

**기반:** 프로필 사진/닉네임, 계정 설정/집계, OS 권한 상태, 로그아웃·탈퇴/보관·동기화. 소셜 사진 없음을 오류로 취급하지 않는다. 테마 설정 저장은 전체 앱/지도 테마 적용 완료와 다르다.

**필요:** 설정 즉시 반영/재시작, 계정 전환 시 전 사용자 통계 제거, 탈퇴 진행 중 차단/재개·삭제 결과 확인, 문의 실제 접수/중복 방지/실패, 공지·FAQ 공급과 갱신 책임. 문의 완료 버튼만 누르고 가짜 성공을 표시하지 않는다. 예시 출시일·버전·공지·주문번호·이메일은 실제 데이터가 아니다.

**확인:** 고객지원 채널·운영 주체·공지 공급(D-15), 법적 문안과 실제 수집/보관/제공 구조 일치(D-05). 개인정보 초안의 브라우저 쿠키·Nominatim/Overpass·AI 공급자와 현재 앱의 Supabase/Cloud Run/R2/MapTiler 구조가 맞지 않는다. 빈 사업자/책임자/시행일·조항 참조 오류를 포함해 확정 문안 검토가 필요하다. 이 분석은 법률 적합성 검토가 아니다.

### 8. 상품·이용 현황

사용자가 후속 제공한 [현재 표](business-model.md)가 우선이다. 무료 5회/한도 3개, 기본 1,900원/+10회/한도 5개, 플러스 4,900원/+30회/15개, 확장 6,900원/+50회/30개. 계속 변경 가능하므로 버전이 있는 카탈로그와 실제 지급/사용 원장을 분리한다.

**제품 흐름:** 상단 현황·보관함 공간 추가·마이페이지 구매 진입→상품 선택→스토어 결제→서버 검증→권리 적용→완료/구매 내역. 스토어 취소·보류·응답 유실·중복 통지·앱 재설치·다른 기기·환불까지 필요하다. 결제 화면에서 성공을 클릭했다고 권리를 지급하지 않는다.

생성횟수는 작업의 결과/취소/재시도와 연결하고 저장 제한은 대상 자료/초과 상태와 연결한다. 현재 서버 전체 호출 제한을 회원 상품 한도로 재사용하지 않는다. 단건 팩에 “현재 이용 중” 배지가 있어도 구독 상태로 모델링하지 않는다.

## 원본 정리·누락 상태

- Figma의 “GTX”→GPX, “좋은 페이예요” 등 오기·3/5 사용과 40% 불일치, 상품 용량 불일치, 탈퇴 안내 중복 문장, 음성과 같은 화면 잠금 설명은 이관 시 정리한다.
- prototype 일부 탭/시작 연결은 목적 화면과 다르다. 예: 생성 화면의 마이페이지 링크가 보관함으로, 저장 코스 “러닝 시작”이 조건 설정으로 연결되는 시연이 있다. 데이터 계약 없이 그대로 복제하지 않는다.
- 화면에 없는 필수 상태: 가입/권한/계정 데이터 로딩, 빈 코스·빈 기록, 후보 없음, 서버 지연·오프라인·취소, 이미지 처리 실패, 저장/동기화 실패, 재인증, GPS 불량, 중도 종료, 결제 취소/보류/복원, 문의 실패. 단계별 설계에 포함한다.
- 현재 Figma의 밝은 화면이 중심이며 전체 다크 대응은 토큰·지도·상태 대비 검증이 필요하다. 412px 시안을 고정 너비로 복제하지 않고 Android 안전 영역·키보드·작은 폭/큰 글씨를 확인한다.
- 문의의 화면 이미지 첨부는 FAQ 문구에만 있고 폼에는 전용 입력이 보이지 않는다. 첨부 포함 여부/용량은 운영 단계에서 정한다.
- 커뮤니티·도형 팩/세부 편집·카드 꾸미기는 설명/비교표에 있더라도 독립 상세 흐름이 없다. 현재 단계의 필수 구현으로 확대하지 않는다.

## 이어서 개발할 때

[서비스 개발 계획](../planning/service-implementation.md)의 S0부터 진행한다. 매 단위는 화면 ID→실제 모듈→필요한 정책 ID→정상/실패 상태→검증→상태 갱신으로 닫는다. 이미지 예시 수치 대신 실제 저장/계산 결과를 사용하고, 단위 완료와 전체 서비스 출시 완료를 구분한다.
