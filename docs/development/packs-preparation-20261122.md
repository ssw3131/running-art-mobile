# 유료 팩 화면 준비 계약

2026-11-22, 실제 결제 연결 전 단계. 사용자가 승인한 [실행 계획](https://github.com/ssw3131/running-art-mobile/blob/dd64075735ba8ae4b77ee1de88534b270d47e5cf/docs/history/executed-plans/2026-11-22-1016-course-packs-policy.md)에 따른다. Cloud PR #90의 변경은 그 채팅에서 병합하며, 공통 진입점 연결은 병합 후 최신 main에서 진행한다.

## 상품과 화면 경계

[내부 카탈로그](../../src/modules/packs/catalog.ts)가 표시명·설명·가격·추가 횟수의 단일 원본이다. Google Play 상품 ID나 서버 계약을 정의하지 않는다.

| 팩 | 가격 | 추가 생성 | 추가 저장 |
| --- | ---: | ---: | ---: |
| 기본 | 1,900원 | 10회 | 20회 |
| 플러스 | 2,900원 | 30회 | 60회 |
| 확장 | 4,900원 | 60회 | 120회 |

무료 혜택은 가입 최초 생성 5회·저장 10회다. 매월 무료 추가·초기화가 없으며 무료 카드의 숫자를 사용자의 현재 잔량으로 표시하지 않는다. 현재 적용 중인 유료 팩은 아직 조회할 수 없으므로 표시하지 않는다.

- 팩 선택은 기본적으로 플러스를 선택하며 세 팩을 비교할 수 있다. 선택만으로 사용량을 바꾸지 않는다. 구매 버튼은 항상 비활성인 `구매 준비 중`이다.
- 구매 내역은 `구매 내역 연결 준비 중`이다. 가짜 주문이나 확정적인 빈 구매 이력을 표시하지 않는다.
- 완료 컴포넌트는 신뢰할 수 있는 구매 검증기가 전달할 `ConfirmedPackPurchase`의 상품 스냅샷을 표시한다. 현재 카탈로그가 달라져도 실제 구매 스냅샷의 가격·혜택을 보존한다. 이 타입 자체가 영수증을 검증하지는 않는다.
- 완료 화면의 앱 경로·진입 버튼·결제 이벤트·서버 지급은 만들지 않는다. 테스트에서만 명시적인 합성 구매 결과를 사용한다. URL 파라미터나 단순 상품 선택으로 완료 자료를 구성해서는 안 된다.
- 계정별 사용량·동기화·DB·API·원장·실제 구매/환불·정책 게시를 변경하지 않는다. 결제 전후 금액 차감 검증이 아니라 **결제 전 화면 탐색으로 현재 잔량이 바뀌지 않는지** 검사한다.
- 화면 프레임은 기존 상단 바·하단 메뉴와 탭 이동 함수를 재사용한다. 헤더/화면의 뒤로가기는 이전 화면이 있으면 복귀하고 직접 열린 경우 마이페이지로 이동한다. 하드웨어 뒤로가기도 같은 직접 접근 예외를 처리한다.

## 디자인과 접근성

[선택 268:9405](https://www.figma.com/design/QYRGII8OdvQB1SrtH3BA08?node-id=268-9405), [플러스 완료 795:2394](https://www.figma.com/design/QYRGII8OdvQB1SrtH3BA08?node-id=795-2394), [내역 305:11162](https://www.figma.com/design/QYRGII8OdvQB1SrtH3BA08?node-id=305-11162)를 읽었다. 기존 Noto Sans KR·주황색·테마·버튼·보관함/생성 아이콘을 재사용한다. 고정 높이로 내용을 자르지 않고 스크롤을 허용한다. 작은 화면·큰 글씨에서는 혜택을 한 열로 배치하고 가격 행은 줄바꿈한다. 완료의 +120회가 단위만 다음 줄로 넘어가지 않도록 좁은 화면에서는 한 열로 바꾼다.

현재 구현 단계에 맞춰 ‘즉시 결제·지급’ 문구를 준비 안내로 바꾸고, 구매 내역의 가상 주문·현재 이용 팩은 표시하지 않는다. 정상 상품 설명과 가격·혜택은 원본을 따른다. 과거 50회 메모보다 이번 승인된 플러스 60회를 우선한다.

## 검증과 후속

[UI 검사](../../tests/components/packs.test.tsx)는 세 상품 선택·완료 수치, 과거 구매 스냅샷, 비활성 구매·명시적 이동, 가짜 이력 부재를 검사한다. [Android 검사](../../scripts/qa/packs_preparation.py)는 회원의 마이페이지 진입·선택·내역/뒤로가기·320dp/1.6배 글씨와 화면 탐색 전후 격리 서버 사용량 및 기기 기록 보존을 확인하도록 준비한다.

현재 준비 결과와 남은 검증은 [품질 기록](../quality/packs-preparation-20261122.md)에 남긴다. 최종 진입점 연결·회원/게스트 접근·필수 Android 29·36·main 반영은 후속 확인 전까지 완료로 표시하지 않는다.

## 2026-11-22 통합 후속

PR90/main f5e73ff를 병합하고 마이페이지 두 팩 버튼·구매 내역, 홈 이용 안내 및 생성/저장 횟수 추가 버튼을 연결했다. /packs와 /purchase-history는 회원 화면이며 명시적 게스트 탐색에서는 가입 안내만 표시한다. 마이페이지는 확인되지 않은 유료 기본 팩 이용중 표시 대신 실제 남은 이용 횟수·코스 저장 회수를 표시한다. 구매 완료 경로는 추가하지 않았다. 뒤로가기 및 하단 메뉴는 기존 프레임을 사용한다. CI 전체/호환 시나리오에 격리 팩 탐색 검사를 연결했으며 실행 결과는 품질 기록을 따른다.
