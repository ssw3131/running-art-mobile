# 코스 생성 Figma 계약 — 2026-10-24

상태: 사용자 후속 승인에 따른 로컬·API36/API29 핵심 검증 완료. 로컬 커밋까지 승인된 범위이며 배포·배포 검증은 다른 작업과 합쳐 후속으로 진행한다. [검증 보고서](../quality/course-generation-figma-20261024.md)와 [체크리스트](../quality/course-generation-figma-checklist.md)의 근거를 따르며, 이 계약 자체는 실행 성공 증거가 아니다.

## 입력과 흐름

- Figma GEN-1(10:2785), GEN-11(23:3469, 예상 러닝 시간 추가), 상세(191:14560)를 기준으로 한다. 실제 지도/응답을 사용하고 Figma 예시 숫자·주소·상품 잔량은 상수로 넣지 않는다.
- 장소·주소를 MapTiler geocoding으로 명시적 검색한다. 한국어/대한민국, 현재 중심 우선, 최대 5개, 10초 제한, 늦은 응답·이탈/백그라운드 취소, 검색 실패 시 지도 선택 유지. 검색 기록과 응답은 디스크에 저장하지 않는다.
- 1~10km 슬라이더, 11~20km 정수 입력. 지도 중심은 탐색 중심이며 실제 출발/합류는 저장 후 러닝 준비에서 선택한다.
- 결과의 러닝 버튼은 미저장 후보라면 상세 저장 단계로 이동한다. 저장 성공 ID가 있어야 러닝 준비 가능. 최초 확인/조건 수정과 같은 조건 재생성 확인을 구분하며 재생성이 다른 결과를 보장하지 않는다.
- 사용자별 생성/저장 제한·차감 없음, 서버 공통 보호와 중복 저장 방지 유지.

## 도형과 계산

12도형은 하트·별·구름·왕관 / 아이스크림·딸기·물고기·뼈다귀 / 고래·거북이·냥냥이·댕댕이 순서다. `whale`은 새 ID이며 `person`은 기존 데이터 지원용으로 남긴다.

`assets/generation/figma-20261024`는 2026-10-24 Figma 원본 48×48 SVG다. 원본은 수정하지 않는다. 사용자가 실제 도형 윤곽 일치를 요청하여 표시 path의 M/L/H/V/Z 좌표를 추출·중심/크기 정규화하고 Figma 부모의 왕관·뼈다귀 가로 반전을 적용했다. `scripts/generate-figma-contours.mjs`는 이 소스 변환 과정을 보존한다. 기존 도형은 버전 없이 호출할 때 기존 윤곽을 유지한다.

- 새 서비스 옵션: `shapeVersion: figma-20261024`, `maxRouteKm: 20`. 엔진 점수 버전은 0.2 유지.
- 반경: 목표≤10km는 2km, 11~20km는 목표/4km. 실제 경로는 목표×0.75 이상, min(목표×1.25,20km) 이하. 최종 후보 선정 전에 원래 경로 길이로 거부하며 경로를 잘라 맞추지 않는다.
- 상한이 기존 목표×1.25 범위를 줄이면 처음부터 전체 도형 0.88·0.8배 배치를 함께 탐색하고 추가 탐색 하한을0.75배로 둔다. 도로 우회 길이를 위한 보완이며 허용 실제 거리·점수 공식은 그대로다. 상한 비적용 기존 탐색은 유지한다.
- 점수는 윤곽 45%+흐름25%+꺾임20%+거리 적합도10%−반복 구간 감점이다. 원시 점수 내림차순, 표시만 정수%. 난이도는 순위에 사용하지 않는다.
- 지형은 기존 보정/표본/고도 API를 재사용한다. 길이 가중 평균 절대 경사도 <3% 초급, <6% 중급, 그 외 상급. 앱 초기 기준이며 공인 러닝 난이도나 거리까지 포함한 전체 운동 강도를 뜻하지 않는다. 총 오르막과 6% 이상 구간 길이를 상세에 표시한다.
- 후보 지형은 순차 조회하며 결과·저장을 지연시키지 않는다. 조회 중/확인 불가/재시도, 실행 중 메모리 캐시만 사용한다.
- 예상 시간: 실제 km×390초를 분 반올림. `예상 러닝 시간 : 약 N분`을 카드의 거리 아래와 상세에 표시한다. 휴식·신호·합류·개인/경사 보정 제외. 5.12km=33분, 6.38km=41분, 20km=130분.

## 계약과 저장 호환

- HTTP 경로 `/v1/routes`는 유지한다. JSON의 `runpen-routes-v1`은 기존 1~10km/반경2km/이전 도형을 지원한다. 새 `runpen-routes-v2`는 1~20km와 정확한 거리/반경 조합, 도형 버전과 20km 상한을 요구한다. worker는 수신한 계약을 그대로 응답한다.
- 응답도 계약 일치·실제 좌표 길이·20km 제한·점수 거리 일치를 확인한다. 새 앱이 구 서버에 요청해 실패하면 기존 기기 전환 경로를 사용하며 결과를 구 도형으로 조용히 바꾸지 않는다.
- 새 서비스 코스는 snapshot v4에 도형 기준 버전을 기록한다. 기존 v1~v3 정규화 필드·해시는 그대로 유지한다. 기존 코스의 좌표·점선·점수·이름은 재작성하지 않는다. 구 앱은 v4를 newer-format으로 안내한다.
- SQLite 테이블/운영 SQL 변경은 없다. 현재 동기화는 snapshot payload를 전달하므로 새 앱의 codec으로 일반/사용자 윤곽·러닝 사본을 읽는다. 실제 왕복 검증은 대기한다.
- 배포 묶음 목록에 `figma-contours.ts`를 추가했다. 독립 패키징 검사와 에뮬레이터용 release APK 빌드를 통과했다. 서버 배포·휴대폰 적용은 하지 않았다.
