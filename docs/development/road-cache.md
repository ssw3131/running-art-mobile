# 영구 도로 캐시

2026-09-30 사용자 요청으로 실제 서버 준비와 휴대폰 연결 테스트를 보류하고, 4-3 중 서버 없이 구현할 수 있는 저장 모듈·검증 화면을 먼저 만들었다. 일반 **코스 계산 테스트 → 주변 OSM**은 기존 API·메모리 캐시를 사용한다. 운영 공급 주소·포인터 탐색·일반 계산 연결은 후속이다.

## 저장 계약

`src/modules/road-data/persistent-cache.ts`는 UI·Expo·네트워크와 분리된 모듈이다. 공급자 ID, 요청 영역, 취소 신호와 다운로드 함수를 받는다. `cache-database.ts`는 Expo SQLite 연결을 지연 초기화하고 한 연결·작업 큐를 공유한다. `running-art-road-cache.db`를 사용하므로 기존 `running-art.db`의 테스트 메모와 마이그레이션은 영향을 받지 않는다. 웹은 Android 확인 안내를 표시한다.

스키마 버전은 1이다. `road_cache_datasets`에 공급자·매니페스트 SHA-256·원본 바이트·확인/사용 시각, `road_cache_tiles`에 같은 공급자·해시·격자 ID의 gzip BLOB, `road_cache_current`에 공급자별 현재 매니페스트 해시를 저장한다. WAL과 배타적 트랜잭션을 사용하고, 더 높은 스키마는 보존한 채 앱 업데이트를 안내한다.

매니페스트와 필요한 모든 파일의 SHA-256·크기·형식·버전·노드 연결을 확인하고 완전한 영역을 병합한 후 저장한다. 기존 파일을 읽을 때도 압축 전후 해시를 검사한다. 같은 계산에 서로 다른 릴리스 파일을 섞지 않는다. 손상·누락 파일은 온라인 조회 때 다시 받으며 전체 검증이 끝나기 전에는 DB에 쓰지 않는다.

| 조회 모드 | 동작 |
| --- | --- |
| `prefer-cache` | 확인 후 7일 이내 목록을 우선 사용하고 필요한 누락·손상 파일만 받는다. 만료하면 새 목록을 확인한다. 갱신 실패 시 요청 영역 전체가 검증된 이전 자료만 반환하며 `stale`·`updateFailed`로 상태를 알린다. |
| `refresh` | 새 목록을 반드시 확인한다. 같은 해시의 정상 파일은 재사용한다. 실패를 숨기지 않고 이전 저장 자료를 유지한다. |
| `offline` | 다운로드 함수를 호출하지 않는다. 저장된 현재 목록·필요한 파일이 부족하거나 손상되면 오류를 반환한다. 만료 자료는 오래된 상태임을 표시한다. |

캐시 적중으로 7일 확인 시각을 연장하지 않는다. 현재 버전이 바뀌어도 이전 자료는 용량 정리 전까지 남지만, 다른 버전의 파일을 섞거나 과거 버전을 자동 탐색하지 않는다. 새 버전에서 받지 않은 영역은 오프라인 조회가 불가능할 수 있다. 앱 삭제·데이터 초기화는 캐시도 삭제한다.

## 실패·취소·용량

다운로드·전체 입력 검증과 저장 트랜잭션의 마지막 취소 검사까지 중단되면 이전 정상 버전을 유지한다. SQLite 커밋이 시작된 뒤 도착한 취소는 완료된 저장까지 되돌릴 수 없으며 결과의 화면 표시만 막는다. 미완료 트랜잭션의 프로세스 종료와 쓰기 오류는 SQLite 롤백으로 이전 상태를 유지한다. 저장 실패와 캐시 용량 초과에는 오래된 자료로 성공 처리하지 않는다.

기본 한도는 매니페스트·gzip BLOB 합계 **64 MiB**, 한 조회의 선언된 압축 해제 바이트 합계도 **64 MiB**다. 매니페스트는 최대 2 MiB이고 개별 파일 한도는 [공급 계약](road-samples.md)을 따른다. 이 값은 잠정 개발 기본값이며 실기기 측정 후 조정한다. SQLite 페이지·WAL·인덱스를 포함한 실제 디스크 크기 또는 JavaScript 객체 메모리의 상한은 아니다. 삭제된 DB 페이지는 재사용되며 자동 VACUUM은 하지 않는다.

한도를 넘으면 가장 오래 사용하지 않은 파일부터 정리한다. 같은 버전의 다른 격자도 정리 대상이며, 현재 요청 영역은 보호한다. 빈 과거 목록과 해당 포인터도 정리한다. 정리로도 한도를 지키지 못하면 전체 트랜잭션을 롤백한다. 조회·상태·비우기·종료는 단일 큐로 직렬화해 읽는 도중 파일을 지우지 않는다. 결과는 독립적인 메모리 입력이므로 반환 후 DB 정리와 분리된다. 앱 내 전용 연결 하나를 전제로 하며 여러 캐시 인스턴스가 같은 DB를 동시에 관리하는 방식은 지원하지 않는다.

## PC 자동 검증

프로젝트 루트에서 실행한다. 실제 표본 재현에는 [표본 가공](road-samples.md)의 `build/road-data/` 생성물이 필요하다.

```powershell
. .\scripts\env.ps1
npm run test:road-cache
npm run roads:cache-rehearse
powershell -ExecutionPolicy Bypass -File .\dev.ps1 check
```

`cache-rehearse.mjs`는 실제 표본을 loopback HTTP로 받아 모바일용 gzip·SHA codec으로 검증한 뒤 실제 SQLite에 저장한다. HTTP 서버·DB를 닫고 별도 Node 프로세스에서 세 지역을 오프라인으로 읽어 분할 전 전체 입력·그래프와 비교한다. DB·보고서는 `build/road-cache/` 아래에 남으며 Git에서 제외한다. 실제 기기·클라우드 성능 측정은 아니다. [검증 결과](../quality/road-cache-verification.md)

## Android 확인 절차 — 사용자 재개 시

이번에는 연결·설치·강제 종료 테스트를 실행하지 않았다. 최신 코드를 빌드한 뒤 홈의 **영구 도로 캐시 검증**에서 다음을 확인한다. 이전 배포 APK에는 새 화면이 없다.

1. PC에서 `npm run roads:serve`를 켜고 선택한 Android 기기에 `adb -s <serial> reverse tcp:8766 tcp:8766`을 적용한다. 자세한 도구·연결 방법은 [도로 표본 안내](road-samples.md)를 따른다.
2. 서울·부산·경계를 각각 선택하고 **받아 저장·갱신**을 실행한다. 파일 수·새 다운로드·도로 개수·버전을 확인한다.
3. PC 표본 서버를 종료하고 앱을 강제 종료·재실행한다. **네트워크 없이 저장 자료 읽기**로 같은 결과와 새 다운로드 0개를 확인한다. 개발용 APK 재실행에는 Metro가 별도로 필요하다.
4. 취소·재조회와 **도로 캐시 비우기**를 확인한다. 비운 뒤 오프라인 조회는 부족 안내를 표시해야 하며 테스트 메모는 유지돼야 한다.

검증 화면은 현재 위치를 사용하지 않고 세 공개 표본 좌표만 선택한다. 다운로드 주소는 고정 loopback이며 30초 제한과 취소, Content-Length·압축 전송 헤더·실제 바이트 크기를 검사한다. 네이티브 `fetch`가 스트림을 제공하지 않으면 본문 할당 후 크기를 확인하므로 이 전송기는 신뢰하는 로컬 검증 전용이다. 운영 CDN 연결에는 HTTPS·현재 포인터 검증·다운로드 중 크기 제한을 별도로 구현해야 한다. 도로 오프라인 재사용과 배경 지도 오프라인 표시는 별개다.
