# 시험 정책 등록 준비 (미실행)

**2026-10-24 시험 약관 게시 완료:** 사용자 지시로 가입용 정책과 이용약관·개인정보·위치약관을 `runpen-test-20261024-v2`로 게시하고 공개 API HTTP200/본문 해시 일치·기존 자료 보존을 확인했다. 앱 재설치 불필요. 실제 폰 로그인/동의 완료는 사용자 후속이며 정식 시행일/문안은 미정이다. 지원 SQL 중 정책 테이블/조회 함수만 수동 부분 적용했으므로 나중에 전체 migration을 재실행하지 말고 대조한다. 아래 약관 미게시로 가입 불가 표현은 이 결과로 대체한다.


2026-10-24 사용자가 현재 계정은 모두 테스트 계정이고 기존 초안을 시험용으로 먼저 사용한 뒤 수정하도록 승인했다. 원문은 [정책 초안 폴더](../product/policies-draft-20261024/README.md)의 세 문서를 그대로 복사해 보존했다. 조항·빈 표·시행일 미정을 수정하지 않았다. 화면에 본문을 하드코딩하지 않는다.

## 나중에 실행할 순서

현재는 아래 명령도 실행하지 않았다. 다른 기능 소스 구현이 끝나고 사용자 검증·배포 지시가 있으면 진행한다.

1. 기본 모바일의 원본 초안과 이 작업 폴더 사본을 대조한다. 내용 변경이 있으면 사용자의 최신 초안을 선택하고 새 버전 ID를 정한다.
2. 기존 운영 스키마와 수동/CLI 이력부터 대조한다. `20261013003500_membership_consent.sql`의 회원 API와 `20261014003000_service_support.sql`의 정책 API/테이블이 모두 필요하다. 이미 적용한 마이그레이션을 재실행하지 않는다. 운영 지원 SQL 미반영 이력은 별도 해결한다.
3. 아래 생성기를 사용한다. `--published-at`은 **실제 시험 게시에 사용할 시각**을 ISO8601+시간대로 전달한다. 정식 출시 시행일을 정하는 값이 아니다. 아래 예시는 플레이스홀더이며 임의 날짜를 정하지 않았다.

```powershell
. .\scripts\env.ps1
node scripts/policies/prepare-test-policies.mjs --published-at '<시험 게시 시각 ISO8601>' --version runpen-test-20261024-v1 --out '<새 SQL 출력 경로>'
```

4. 생성한 SQL을 검토하고 격리 DB에서 먼저 실행/검증한다. 생성기는 네트워크/DB 연결이 없으며 기존 출력 파일을 덮지 않는다. 트랜잭션 안에서 중복 버전을 거부하고 기존 활성 membership 정책만 비활성화한 뒤 새 버전을 추가한다. 본문 맨 앞에 시험용 표시를 붙이며 뒤의 초안 원문은 그대로 둔다. `service_policies`에는 privacy/location만 추가한다. terms 조회는 기존 `get_service_policy('terms')` 계약대로 membership 본문을 사용한다.
5. 승인된 서버 반영 단계에서 같은 검토된 SQL을 적용한다. membership `published_at` 및 service `effective_at`에 동일한 시험 게시 시각을 사용한다. 게시 시각이 미래이면 그때까지 조회되지 않는다. 기존 service 정책의 effective_at보다 이후 시각이어야 새 정책이 선택된다. 화면은 `runpen-test-` ID를 보고 “시험 게시 / 정식 출시 시행일 미정”을 표시한다.
6. 익명 정책 조회 세 종류·가입 정책 본문/버전과 활성 선택을 확인한다. 테스트 사용자가 앱에서 필수 두 동의를 직접 선택하여 가입한다. SQL로 memberships/member_consents를 채우거나 자동 동의를 만들지 않는다. 위치약관은 별도 열람이며 마케팅은 없다.
7. 게시 전에 이전 활성 membership ID·service 공개 상태/시각과 기존 자료 행 수/해시를 기록한다. 복구는 새 시험 버전을 비공개/비활성화하고 기록한 이전 정책을 다시 선택하는 명시적 트랜잭션으로 수행한다. 동의 이력과 게시된 본문을 지우거나 고치지 않는다. 새 정책 철회 후에는 가입/재동의가 다시 필요할 수 있다.

## 교체 규칙

이 생성기는 기존 ID에 upsert/update하지 않는다. 재실행에서 중복 ID 오류이면 이전 성공 여부부터 조회하고 새 버전 발급이 필요한지 판단한다. 이미 게시한 버전의 본문을 변경하지 않고 `runpen-test-...-v2` 등 새 ID로 교체한다. 서비스 정책 테이블에는 불변 트리거가 없으므로 이 등록 경로에서 insert만 사용하고 운영자도 동일 규칙을 따른다. 정식 출시 시에는 확정된 문안/시행일의 **새 정식 버전**을 별도로 게시한다. 현재 초안의 법률 문안이나 날짜를 임의로 완성하지 않는다.

등록 준비본과 회귀검사 소스만 작성했다. 생성기 실행·SQL 적용·정책 조회 검증·실제 사용자 동의·배포는 모두 대기다.
