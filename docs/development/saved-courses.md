# 코스의 기기 저장·목록·다시 열기

5단계 중 서버 없이 사용할 수 있는 로컬 코스 기능이다. 계산 결과의 경로를 기기에 보존하며 회원·동기화·커뮤니티 공유·러닝 기록은 포함하지 않는다. 파일 공유인 [GPX 내보내기](gpx-export.md)는 후속으로 구현했다. 서버 배포 보류는 유지한다. 2026-09-30 SM-S942N에 코스 저장 APK를 설치하고 저장·오프라인 재실행·삭제를 확인했다. 2026-10-01 후속 GPX APK의 실제 휴대폰 설치·파일 전달과 기존 코스·메모 보존도 확인했다.

## 사용 방법

1. **코스 계산 테스트**에서 계산을 마치고 저장할 후보를 선택한다. 서버가 없어도 **합성 격자**로 기능을 확인할 수 있다. 가상 코스는 실제 달릴 길과 구분해 표시한다.
2. 결과 아래 **선택한 코스 저장**에서 이름을 입력하고 저장한다. 이름은 1~80자다. 계산 이후 지도·도형·목표 거리를 바꿔도 저장에는 완료 당시의 좌표와 조건을 사용한다.
3. 저장 완료 후 **저장한 코스 열기**, 또는 홈의 **저장한 코스**로 이동한다. 목록은 최신 저장 순서이며 30개씩 읽고 **더 보기**로 이어진다.
4. 상세는 저장한 경로·목표 도형·거리·점수·계산 기준을 재계산 없이 보여준다. 기본값은 배경 지도 없는 경로 표시다. GPS·도로 서버를 호출하지 않는다. 실제 OSM 코스에서 **배경 지도 보기**를 선택할 때만 MapTiler 지도를 요청한다.
5. 상세에서 이름을 바꾸거나 삭제할 수 있다. 이름 변경은 경로·ID·최초 저장 시각을 유지한다. 삭제는 확인창을 거치며 해당 코스만 삭제한다.

같은 경로·계산 조건의 결과를 다시 저장하면 기존 코스를 반환하고 이름도 유지한다. 후보 순위가 달라도 스냅샷 내용이 완전히 같으면 하나의 코스다. 다른 조건·경로·출처는 별도 코스로 저장한다. 삭제 후 다시 저장하면 새 ID와 저장 시각을 부여한다.

오프라인 경로 표시는 배경 지도의 오프라인 저장과 다르다. 앱 제거·데이터 초기화 시 저장 코스가 함께 삭제된다. 현재 서버 동기화·앱 자체 백업은 없다. **저장 코스의 [GPX 내보내기](gpx-export.md)**를 후속 구현했으며 실제 휴대폰 파일 전달도 확인했다. 다음 서버 독립 앱 작업은 코스 시뮬레이션이다. 예전 공개 APK에는 이번 화면이 없다. GPX를 포함한 최신 로컬 `build/install/running-art-0.1.0-20261001-gpx.apk`는 PC 없이 실행하며 [설치 안내](android-test-apk.md)를 따른다. 개발 APK를 사용할 때만 로컬 Metro가 필요하다.

## 데이터와 모듈

기존 `running-art.db`에 마이그레이션 **2**를 추가했다. 버전 1의 테스트 메모 SQL은 바꾸지 않았고 별도 도로 캐시 DB도 그대로다. `saved_courses`는 SQLite에서 생성한 32자리 임의 ID, 이름·목록용 요약·최초 저장/수정 시각, 스냅샷 JSON과 SHA-256을 보관한다. 해시는 중복 방지와 손상 확인용이며 암호화나 외부 변조 방지 서명이 아니다. 사용자 코스에는 캐시와 같은 자동 만료·용량 정리를 적용하지 않는다.

스냅샷 형식 버전은 1, 계산 버전은 현재 0.2다. 원점 `{lat,lng}`, 도형 ID, 목표/실제 거리, 표시 점수, `osm`/`synthetic` 출처, 경로와 목표 도형의 `[경도, 위도]` 배열을 저장한다. 반올림 없이 좌표·실제 거리를 보존한다. 엔진의 그래프·모든 후보·GPS 추적·실시간 도로 공급 응답은 저장하지 않는다.

저장 전에 유한 수·좌표 범위·형식·출처·도형·길이를 검사하고 호출자가 전달한 객체를 복사한다. 각 좌표 배열은 2~20,000점, 스냅샷 JSON은 2 MiB 이내다. JSON 필드는 고정된 ASCII 식별자·숫자·배열이므로 현재 형식에서 문자열 길이가 바이트 한도와 같다. 이름은 별도로 저장한다. 한도를 넘는 자료를 잘라 저장하지 않는다.

- `modules/courses/model.ts`: 형식·입력 검증·정규화·SHA-256·저장 경로의 지도 표시 데이터.
- `modules/courses/repository.ts`: 실제 SQL 저장·중복·목록·상세·이름 변경·삭제. 전용 작업 큐와 저장 트랜잭션을 사용한다.
- `modules/storage/client.ts`: 메모와 코스 저장소가 DB 초기화·마이그레이션을 공유한다. 기존 메모 API와 `courses` 저장소를 함께 반환한다.
- `features/route-lab/session.ts`, `saved-course.ts`: 계산 시작 시점의 원점·옵션·도로 종류를 보존하고 선택한 완료 후보를 스냅샷으로 변환한다.
- `features/courses/SaveCoursePanel.tsx`, `app/courses/`: 계산 결과 저장 폼·목록·상세. 저장 중 중복 제출과 이전 후보의 늦은 화면 갱신을 막는다.

손상된 JSON·해시·요약 불일치는 상세에서 오류를 알리고 다른 코스의 목록을 계속 사용할 수 있게 한다. 손상된 코스도 사용자 확인 후 삭제할 수 있다. 더 최신 형식은 덮어쓰지 않고 앱 업데이트를 안내한다. 저장 실패 시 성공 메시지를 표시하지 않는다. 이름 변경 후 재읽기만 실패하면 저장 자체의 성공과 조회 실패를 구분한다.
