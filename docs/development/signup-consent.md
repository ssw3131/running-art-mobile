# S1 가입·동의

2026-10-13. 이번 단위는 가입 정책과 가입·동의 연결이다. 홈 3상태와 상품/보너스 지급은 후속이다.

## 확정한 제품 계약

- 게스트 가입 안내는 홈·마이페이지에만 둔다. 코스 생성 전 가입 유도 팝업이나 비로그인 계산 제한은 추가하지 않는다.
- 필수 이용약관·개인정보 수집/이용 동의 두 항목만 받는다. 마케팅 선택 동의는 이번에 수집하지 않는다. 전체 동의는 두 필수 항목을 함께 선택/해제한다.
- 위치 권한은 기존 위치 기능 진입 시 요청한다. OS 위치 권한을 가입 동의로 간주하지 않는다.
- 기존 계정도 같은 회원 상태 체계로 이관한다. 동의 이력이 없으면 `policy_id/completed_at/consented_at = NULL`인 대기 상태다. 신규 Auth 계정도 같은 상태로 생성한다. 다음 로그인·세션 복원 시 게시된 약관을 확인하도록 안내한다. 활성 러닝은 자동 화면 전환으로 방해하지 않는다.
- 닉네임은 기존 RunPen 값→소셜 이름→러너 순으로 제안한다. 선택 입력이 비어 있으면 해당 제안을 사용하고 저장은 기존 1~20자/중복 허용 규칙을 따른다. 프로필 사진은 소셜/기본 이미지·Figma 러너 이미지·사용자 사진을 기존 비공개 사진 저장으로 연결한다.
- 별도 계정 연결/병합을 추가하지 않고, 로그인만으로 게스트 기록을 자동 귀속하지 않는다. Supabase가 이미 연결한 기존 identity는 유지한다.

## 화면과 데이터

`account-entry`는 실제 3종 소셜 SDK 진입을 재사용하고 게스트 복귀·가입/로그인 문구 전환·인증 오류를 처리한다. `account-signup`은 서버 상태 조회→프로필 선택→게시된 본문/버전 열람→필수 동의→가입 완료를 연결한다. 미배포 서버·게시된 약관 없음·통신 오류는 가입 완료로 표시하지 않는다.

Figma `253:7200`, `253:7124`, `229:2153`에서 컨텍스트와 스크린샷을 확인했다. 원본 로고·소셜 아이콘·러너 이미지·갤러리·잠금 아이콘은 `assets/signup/`에 보존한다. 사진/이메일 예시는 실제 계정 데이터 또는 기본 이미지로 치환한다. 가입 5회 보너스 홍보는 실제 지급을 구현하는 S7까지 표시하지 않는다. 10-13 결정으로 마케팅 체크박스와 게스트 생성 유도 화면을 제외했다. 약관 열람 버튼과 추가 오류/재시도·상태 설명은 작은 폭/접근성을 고려해 배치한다.

`modules/membership`는 인증과 분리된 단일 상태 저장소다. 계정이 바뀌면 이전 정책/상태/오류를 즉시 지우고 늦은 응답을 무시한다. 동의 제출 전 요청 ID를 계정별 SecureStore에 보관하며 실패 뒤 명시적 재시도에서 같은 ID를 쓴다. 체크박스는 재시작/새 정책에서 다시 확인한다. 가입 완료는 서버 확인값이며 Auth 메타데이터에 성공 플래그를 저장하지 않는다.

## DB와 기존 계정 이관

새 마이그레이션 `20261013003500_membership_consent.sql`:

- `membership_policies`: 버전별 본문·게시 시각, 현재 정책 한 개. 이미 저장한 본문/시각은 수정 불가하며 새 버전을 만든다.
- `memberships`: Auth 사용자별 가입 대기/최초 완료·현재 동의 버전. 기존 계정을 모두 대기로 채우고 신규 계정은 트리거로 초기화한다.
- `membership_consents`: 계정·요청 ID·실제 동의 버전·서버 시각. 클라이언트 직접 쓰기를 허용하지 않는다.
- `get_membership_policy`, `get_membership`, `accept_membership`: 게시 본문 읽기, 본인 회원 상태, 필수 동의/버전·요청 중복 확인. 기존 탈퇴 공유 잠금과 회원별 저장 잠금으로 탈퇴/동시 제출을 정합하게 처리한다.

마이그레이션은 기존 Auth 메타데이터·코스/러닝/Storage를 바꾸지 않는다. 기존 회원에게 과거 동의를 만들어 주거나 새 보너스를 지급하지 않는다. 실제 Auth 삭제 시 회원 상태와 동의 이력을 함께 제거하며 기존 기기 기록 보관 정책은 유지한다.

## 약관 원문과 실제 게시 전 남은 값

[Figma 약관 원문](../product/figma-policy-source-20261013.json)은 10-13에 `47:7114/7118/7122`에서 다시 조회했다. 다음은 원문에 실제로 남아 있는 미정/불일치이며 본 작업에서 임의로 확정하지 않는다.

- 운영자·주소·지원 이메일·개인정보/위치정보 책임자·시행일의 대괄호 빈칸.
- 브라우저 쿠키 보관함, Nominatim/Overpass, AI 생성·구독/이용권 설명과 현재 모바일/Supabase/Cloud Run/R2/MapTiler 및 최신 상품 계획의 차이.
- 개인정보 수집/이용 동의 대상 항목·목적·보유 기간에 맞는 최종 문안, 위치정보 문안의 실제 구현/보관 정책 정합성.

SQL에 시험/미확정 본문을 seed하지 않는다. 실제 운영 DB 적용 전 [기존 구조와 배포 이력 대조](../planning/database-improvement-direction.md)를 수행하고 확정 본문을 별도 버전으로 게시한다. 그 전에는 기존 로그인·기능이 동작하고 새 가입 완료 처리는 준비 상태다. 문안/법률 적합성 검토를 통과했다는 의미가 아니다.

## 검사

`npm run qa:fast`는 타입·린트, 로직/UI, PGlite 이관/정책 검사를 포함한다. `supabase/tests/membership.sql`은 격리 PostgreSQL에서도 실행한다. `tests/integration/membership.test.mjs`는 loopback 실제 Auth/RPC의 동시 제출·응답 재전송·소유권·탈퇴 cascade를 확인한다. 시험 문안과 계정은 격리 스택에서만 생성하고 정리한다.
