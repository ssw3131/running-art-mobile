# S2a 코스 생성 화면 계약

2026-10-13. 기존 계산 엔진·서버·저장 형식을 유지하며 조건 설정, 생성 확인, 추천 후보, 임시 후보 상세를 서비스 화면으로 연결한다. [실행 계획](../history/executed-plans/2026-10-13-1747-course-generation-ui.md)·[검증](../quality/course-generation-20261013.md).

## 범위와 표시

- 기존 9도형·3/5/7km·직접 그리기를 유지한다. 12도형/거리 확대는 S2b, 이미지 윤곽 추출은 S2c다. 장소 검색은 추가하지 않는다.
- 지도 십자는 탐색 중심이다. 실제 도로는 중심 주변 반경 2km에서 찾고, 저장한 코스의 실제 출발/합류·진행 방향은 러닝 준비에서 선택한다.
- D-08의 유사도% 환산·ETA·난이도 기준은 미확정이다. 이번 UI는 실제 길이(km)와 엔진의 후보 순위만 표시한다. 선택 질문에 답이 없는 동안 적용한 S2a 기본값이며 영구적인 제품 결정으로 간주하지 않는다. 원시 엔진 점수는 개발 검증 정보에서만 보인다.
- 후보 개수는 실제 응답을 사용한다. 최대 5개, 0개·소수 후보도 그대로 표시한다. 혼잡도·AI 설명·주소·차감 횟수·잔량을 생성하지 않는다. 이용권 차감은 S7이다.

## 상태와 자료 수명

1. 조건과 마지막 성공 결과는 분리된다. 위치·거리·도형 수정은 진행 중 작업을 취소하지만 마지막 결과 사본은 유지한다. 새 계산을 확정하면 이전 결과를 비우고 새 작업을 시작한다.
2. 확인창은 중심·거리·도형·사용자 윤곽을 복사한다. 확인 중 조건이 바뀌면 새 조건을 다시 확인해야 한다. 취소는 계산/저장을 하지 않는다.
3. 계산은 기존 작업 세션의 취소/늦은 응답 거부·서버 우선/기기 전환·오프라인 도로 캐시를 재사용한다. 화면 이탈·백그라운드 전환은 계산을 취소한다. 생성 중 중복 시작은 차단한다.
4. 결과 지도 이동은 다음 탐색 중심을 바꾸지 않는다. 점선 토글은 목표 도형 레이어만 숨긴다. 선택 후보의 실제 거리·조건은 계산 당시 사본을 사용한다.
5. `/course-candidate`에는 불투명한 임시 식별자만 전달한다. 메모리 저장소는 최대 5개, 계정/게스트 범위와 검증된 경로 해시로 격리한다. 같은 후보를 다시 열면 편집 이름과 명시적으로 저장한 ID를 유지한다. 앱 재시작/다른 계정/만료 ID는 재선택·보관함 안내로 이동한다.
6. 저장은 기존 SQLite 저장소의 검증·중복 제거·소유권/동기화 계약을 따른다. 저장 전 GPX·러닝 준비는 비활성이다. 저장 후 정확히 같은 saved ID로 GPX 선택창 또는 실제 러닝 준비를 연다. 선택창 닫힘을 파일 저장 성공으로 표시하지 않는다. 가상 검증 도로에는 실제 러닝 버튼이 없다.
7. 상세는 기존 경사 조회/그래프를 사용한다. 고도와 난이도를 혼동하지 않는다. 데이터 모델·SQL·운영 API 변경은 없다.
