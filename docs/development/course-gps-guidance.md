# 코스 생성과 실제 GPS 안내

**2026-10-04 자유 출발 규칙:** 새 코스 추천은 지도 중심 반경 2km의 양방향 보행 순환 경로다. 중심 100m 도로·중심 출발/복귀 조건을 없앴다. 실제 러닝은 코스 중간 합류·자동 방향 인식·한 방향 한 바퀴를 지원한다. [실행 계획](../history/executed-plans/2026-10-04-1451-free-loop-guidance.md)·[검증](../quality/free-loop-guidance-verification.md)을 우선한다. 아래 SQLite v5는 최초 기능 도입 시점이며 현재 사용자 DB는 기존 v7을 유지한다.

현재 앱의 코스 만들기·저장 코스·GPS 러닝을 연결한다. [실행 계획](../history/executed-plans/2026-10-03-1600-course-gps-guidance.md)과 [검증 상태](../quality/course-gps-guidance-verification.md)를 함께 확인한다. 휴대폰 설치·야외 검증은 사용자 요청으로 후속이다.

## 사용 흐름

1. 홈의 **코스 만들기**에서 지도 중심/내 위치·3/5/7km·기존 도형을 선택한다. 기본은 전국 실제 도로이며 개발용 가상 격자·표본·측정은 접힌 개발 검증 정보에서 연다.
2. 후보를 누르면 경로와 목표 도형이 함께 표시된다. 점수는 후보 비교용 종합 점수이며 일치율이 아니다. 지도 십자는 탐색 중심이며 고정 출발점은 없다. 목표 거리는 접근 구간을 제외한 순환 경로 길이다.
3. 이름을 정해 코스를 저장하고 **이 코스로 러닝 준비**를 누른다. 저장 코스 상세에서도 같은 준비 화면으로 진입한다. 가상 코스는 실제 러닝에 사용할 수 없다.
4. 수신 후 5초 이내·정확도 30m 이내의 위치를 확인한다. 코스 밖이면 **보행 도로 합류 경로 준비**로 경로를 확보해야 시작할 수 있다. 준비 중에는 기록하지 않고, 시작 버튼 이후 접근 구간도 거리·활동 시간에 포함한다. 코스 가까이에서 3초간 위치가 확인되면 합류하며 원하는 방향으로 달리면 방향을 자동 인식한다. 접근 구간은 한 바퀴 진행률에서 제외한다.
5. 지도·집중 모드, 음성, 화면 꺼짐 안내/기록을 설정할 수 있다. 화면 꺼짐을 끄면 다른 앱·잠금 전환 때 일시정지하며 직접 재개한다.
6. 합류 지점을 기준으로 한 방향의 코스 전체를 연속 통과해 돌아오면 자동 일시정지한다. **완주 확인·저장**으로 종료하거나 **계속 달리기**로 기록을 이어간다. 계속 달린 뒤 종료해도 완주 이력은 유지하며 완주로 다시 자동 정지하지 않는다. 왕복·역주행 거리를 더해 완주로 인정하지 않는다.
7. 종료한 기록의 코스 이름·완주 여부·실제 GPS 거리/시간/페이스·궤적을 러닝 상세에서 확인한다. 계정 동기화를 켠 경우 기존 동기화가 종료 기록을 전송한다.

## 저장·안내 계약

- SQLite v5는 기존 테이블/좌표를 재작성하지 않고 러닝 세션에 선택적 코스 ID·이름·경로 사본·안내 체크포인트·설정·결과를 추가한다. 자유 러닝과 과거 기록은 코스 정보가 비어 있는 상태로 유지한다.
- 시작 시 현재 계정의 코스를 읽고 검증한 사본을 고정한다. 원래 코스의 이름 변경·삭제가 과거 러닝에 영향을 주지 않는다.
- 같은 Expo Location 수신 배치를 안내와 기록에 전달한다. 안내는 정지 좌표도 판단에 사용하고, 실제 거리 계산은 기존 GPS 흔들림·공백 필터를 유지한다. 시간 표시에는 활동 시간을 사용하며 안내의 시각은 시작 이후 수신 시각이다.
- GPS 좌표·요약과 안내 체크포인트는 하나의 SQLite 트랜잭션으로 저장한다. 저장에 성공한 다음 음성/진동을 실행한다. 쓰기 실패 시 마지막 저장 상태를 보존하고 추적을 중단한다.
- 안내 상태에는 진행 위치·이탈 복귀 지점·발화 중복 방지·완주 보류 상태를 보존한다. 새 JS 프로세스는 중단 상태로 복원하며 자동 재개하지 않는다. 재개 후 마지막 진행 지점에서 벗어났다면 건너뛴 경로를 완주로 인정하지 않는다.
- 새 안내 체크포인트 v2는 접근/방향 확인/코스 진행/복귀/완주/계속 상태, 합류 위치·선택 방향·현재 위치·최대 연속 진행량·접근 경로를 저장한다. 기존 진행 중 v1 안내는 기존 정방향 엔진으로 복원한다. 완료 기록의 체크포인트가 없으면 이전 표시 방식으로 읽으며 실행을 재개하지 않는다.
- 접근은 현재 위치에서 연결 가능한 코스 구간 중 보행 거리 최단 경로, 이탈·중단 후 복귀는 마지막 정상 진행 위치까지의 최단 경로다. 2→5→10km 반경의 기존 도로 공급·캐시를 사용하며 10km 밖의 장거리 안내는 지원하지 않는다. 시작 전 자료/경로가 부족하면 시작을 막고, 진행 중 복귀 실패 시 GPS 기록을 보존하면서 사유·재시도를 표시한다. 도로 I/O·계산은 GPS 저장 큐와 SQLite 트랜잭션 밖에서 수행한다.
- 보행 도로의 방향·접근 제한과 OSM 식별자를 지킨다. 가까운 도로를 임의 직선으로 잇지 않는다. 기존 코스 원본의 접근 구간은 자동 제거하지 않으며 저장된 전체 순서를 한 바퀴로 사용한다. 닫히지 않은 경로는 새 코스 러닝을 시작할 수 없다.
- 이탈 25m/5초·복귀 12m/3초·완주 잔여 10m/도착 반경 15m/3초, 부정확도 30m·공백 5초는 초기 시험값이다. 교차로·도로명 대신 코스 좌표 변화로 방향을 안내한다. 야외 측정 전 최종 정책으로 확정하지 않는다.
- 실제 GPS의 백그라운드 실행은 기존 위치 foreground service가 담당한다. 한국어 오프라인 TTS·진동은 로컬 모듈의 별도 실행부로 연결한다. 모의 안내의 `specialUse` 서비스는 실제 GPS 러닝에서 시작하지 않는다.

## 동기화 호환성

새 추천 코스 사본은 schemaVersion 2로 OSM way·양끝 원본 node ID·세분 구간 비율·양방향 가능 여부를 보존한다. v1도 계속 읽고 기존 코스·기록·해시를 일괄 변경하지 않는다. 새 형식의 코스와 이를 포함한 러닝은 새 앱에서 복원해야 한다. 서버 테이블·SQLite 열은 추가하지 않는다.

기존 자유 러닝 파일은 좌표 배열 형식을 유지한다. 코스 연결 러닝은 `{schemaVersion:2, points, course:{id,name,snapshot}, outcome}` 파일로 저장하고 작은 요약에 코스 ID·이름·결과를 추가한다. 버전 2와 기존 배열 형식을 모두 읽고 무결성·소유자·좌표 수·거리·코스 사본의 일관성을 검증한 뒤 복원한다. 안내 체크포인트는 진행 중인 기기의 로컬 상태이며 다른 기기에서 실행을 자동 재개하지 않는다.

기존 Supabase 테이블·RLS·비공개 버킷·RPC를 유지한다. 새 코스 연결 파일을 읽지 못하는 이전 APK에서는 동기화 오류가 표시될 수 있으므로 함께 사용하는 기기도 새 APK로 업데이트한다. 기존 기록은 새 형식으로 일괄 재업로드하거나 삭제하지 않는다.

## 남은 범위

실제 휴대폰의 GPS 정확도·장시간 잠금·진동 체감·배터리, 야외 이탈/복귀와 완주 임계값 조정은 후속이다. 장소 검색·직접 그리기·이미지 입력·배지·공유·과금·전체 탭 전환은 이번 기능과 분리한다.
