# 코스 계산 테스트

홈의 **코스 계산 테스트**에서 v0.2 계산을 실행합니다. **주변 OSM**은 [현재 위치·지도 중심 기준 조회](route-center.md)를 사용하고 합성 격자·단절 테스트는 고정 표본을 사용합니다. 테스트 화면은 최종 서비스 디자인이 아닙니다.

## 확인 순서

1. [독립 실행 테스트 APK](android-test-apk.md)를 엽니다. 최신 소스의 개발용 앱을 쓰면 Metro를 실행합니다.
2. 홈 → **코스 계산 테스트**로 이동합니다.
3. **합성 격자** 또는 **주변 OSM**, 도형, 목표 거리(3·5·7km)를 선택합니다.
4. 주변 OSM에서는 현재 위치 또는 지도 이동으로 중심을 선택한 뒤 **코스 계산하기**를 누릅니다. 주변 도로 조회 후 실제 배치 비교·경로 검증·미세 조정 단계를 실행합니다.
5. 계산 중 **화면 반응 확인**을 눌러 횟수가 바뀌는지 확인합니다. **취소** 또는 **처음부터 다시 계산**을 사용할 수 있습니다. 화면 이탈·앱 백그라운드 전환도 계산을 취소합니다.
6. 완료 후 순위별 코스를 선택하면 지도에 초록 실선으로 표시합니다. 갈색 점선은 목표 도형, 점은 도로에 붙인 출발·도착점입니다. 목표 거리에는 원본의 ±25% 허용 범위가 적용됩니다.
7. 최신 개발 앱과 9월 30일 코스 저장 APK에서는 선택한 후보에 이름을 붙여 **선택한 코스 저장**을 누릅니다. 홈의 **저장한 코스**에서 목록·상세를 열고 이름 변경·삭제를 할 수 있습니다. 경로는 재계산 없이 복원하며 자세한 절차는 [로컬 코스 저장](saved-courses.md)을 확인합니다. 이전 공개 APK에는 이 기능이 없습니다.
8. **단절 테스트**는 짧고 서로 분리된 가상 도로입니다. 유효 후보 없음 안내가 나오는지 확인합니다.

진행 문구는 **기본 경로 탐색 → 크기·위치 추가 탐색 → 우수 후보 미세 조정**입니다. 하나의 v0.2 계산 안에서 최대 200개·140개·80개 배치를 차례로 평가하고 최종 후보를 최대 5개 고릅니다. 화면의 진행 숫자는 각 단계에서 평가하는 배치 수입니다. 버전별 검사를 따로 실행하는 것으로 오해하지 않도록 2026-09-27에 단계 이름에서 v0.1·v0.2 표기를 제거했습니다.

합성 격자는 실제 지도 타일 없이 표시하는 가상 도로입니다. 주변 OSM에서는 지도 타일과 새 위치의 도로 조회에 인터넷이 필요합니다. 조회한 도로로 코스를 계산하는 과정은 기기 내부에서 실행합니다. 완료 화면에 도로 조회·코스 계산·전체 시간을 표시합니다. 점수는 후보 비교 지표이며 실제 일치율이나 통행 보장이 아닙니다.

## 원본 비교

`tests/reference/v02/`는 v0.2 독립 묶음을 보존한 테스트 전용 자료입니다. 원본 파일은 수정하지 않고 `SHA256SUMS.txt`의 LF 정규화 SHA-256으로 검사합니다. 앱은 이 폴더나 형제 프로젝트를 런타임 import하지 않습니다.

- Node 회귀는 고정 입력의 모든 결과 필드를 원본과 정확히 비교합니다. 경로·순위·반올림 전 점수·총거리·탐색 통계가 포함됩니다.
- 앱은 고정 합성 하트 5km·다이아몬드 3km에 한해 Hermes 결과와 원본 결과를 비교합니다. 움직이는 주변 OSM 입력에는 고정 원본 비교를 적용하지 않습니다. 고정 서울 하트 3/5km·다이아몬드 3km 기준 자료와 Node 전체 회귀는 유지합니다.
- Hermes/V8의 마지막 부동소수점 자리 차이를 위해 앱 비교에는 절대 오차 `1e-6`을 사전에 지정했습니다. 좌표는 미터, raw 점수는 점수 단위입니다. 배열 순위·길이·객체 구조는 그대로 비교하며 결과 차이를 숨기지 않습니다.
- 원본의 9개 도형과 사용자 도형 계산 API를 보존했습니다. 직접 그리기 UI는 후속 사용자 기능 단계입니다.

## 실행과 검증 명령

```powershell
. .\scripts\env.ps1
npm.cmd run test:route-engine
npm.cmd test
npm.cmd run check
npm.cmd run export:android
powershell -ExecutionPolicy Bypass -File .\dev.ps1 build
```

기준 자료 재생성이 필요한 경우에만 다음을 실행합니다. 이 명령은 보존 원본의 해시를 검사하고 원본 엔진으로 기준 결과를 다시 작성합니다. 일반 테스트·앱 실행에는 원본 프로젝트가 필요하지 않습니다.

```powershell
. .\scripts\env.ps1
node scripts/prepare-route-reference.mjs ../running-art
```

도로 표본 추출 방법·수집일·라이선스·원본 및 표본 해시는 `assets/route-lab/provenance.json`에 있습니다. OSM way 전체 좌표·태그·노드 ID를 유지하고 표본에 포함되는 way를 ID로 중복 제거·정렬합니다. 계산 반경 적용은 v0.2 그래프 생성 함수가 담당합니다.

## 계산과 측정

`src/modules/route-engine/engine.ts`는 원본의 계산 순서를 유지하며 그래프 생성·A*·배치·추가 탐색에 generator 체크포인트를 둡니다. `runner.ts`는 입력 검사도 분할하고 기본 8ms 연산 예산 후 호스트에 제어를 돌려주며 체크포인트에서 취소를 확인합니다. 앱의 `src/features/route-lab/scheduler.ts`는 `scheduler@0.27.0`의 낮은 우선순위 작업을 사용합니다. Metro는 이 패키지의 React Native 실행기를 선택하며, 입력·렌더링 작업이 다음 연산 구간보다 먼저 실행될 수 있습니다. Node의 기본 실행기는 타이머 방식입니다.

별도 스레드는 아니며, 개별 체크포인트 구간이나 GC 때문에 8ms를 초과할 수 있습니다. UI의 요청 번호 검사는 취소·교체된 작업의 늦은 진행률·결과·오류 표시도 막습니다. 첫 에뮬레이터 측정에서 `setTimeout(0)` 사이의 대기가 전체 시간 대부분을 차지해 앱 실행기를 변경했으며, 비교 수치는 검증 기록에 남깁니다.

화면에는 계산 경과 시간, 최대 연속 연산 구간, 50ms 타이머의 최대 지연을 표시합니다. 로그의 `ROUTE_LAB_METRICS`에는 고정 표본 이름·도형·목표 거리·그래프 크기·계산 측정·원본 비교 결과가 남습니다. GPS 개인 위치나 지도 키를 기록하지 않습니다. 메모리는 별도로 Android `dumpsys meminfo`로 앱 전체 PSS·RSS를 확인하며 엔진 전용 메모리와 구분합니다.

검색별 A* 상태 재사용·상한 있는 경로 캐시·거리 연산 생략을 적용했습니다. 전략과 재현 명령, 웹 원본 비교는 [성능 개선](route-engine-performance.md)을 확인합니다. 실행 로그의 `routing`은 요청·캐시 적중·실제 A* 횟수와 최대 캐시 사용량이며 원본 결과 객체와 별개입니다.

실제 결과와 미검증 항목은 [코스 계산 검증](../quality/route-engine-verification.md)을 확인합니다. USB 휴대폰에서 개발용·배포용 JavaScript와 독립 실행 릴리스 APK를 각각 3회 계산하고 입력·취소·메모리를 확인했습니다. 중앙값은 개발 모드 58.44초, 개발 APK + 배포용 JavaScript 44.27초, 릴리스 APK 24.83초입니다. PC 없이 실행할 때는 [테스트 APK 안내](android-test-apk.md)를 따릅니다. 스토어 배포·야외 사용·장시간 성능은 별도 검증이 필요합니다.
