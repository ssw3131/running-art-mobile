# 지도 중심으로 코스 계산하기

코스 계산 테스트의 **주변 OSM**(이전 이름: 서울 OSM)은 선택한 지도 중심으로 주변 도로를 조회하고 v0.2 코스를 계산한다. 서울 밖에서도 같은 흐름으로 조회한다. 영구 저장·오프라인 지역 파일은 후속 단계다.

## 사용 순서

1. 홈 → 코스 계산 테스트 → **주변 OSM**을 누른다. 전경 위치 권한을 확인하고 현재 위치를 한 번 요청한다.
2. 가운데 십자 표시와 **계산 중심** 좌표를 확인한다. 위치를 얻기 전 기본 좌표는 광화문이다. 권한 거부·기기 위치 꺼짐·15초 시간 초과 시 안내하고 지도로 직접 선택할 수 있게 한다.
3. 지도를 움직이고 손을 놓으면 중심 좌표가 갱신된다. GPS 응답이 늦어도 수동 선택을 덮어쓰지 않는다. **내 위치**를 누르면 다시 위치를 요청한다. 설정을 열었다 돌아오면 권한·기기 위치 상태를 재확인한다.
4. 도형과 거리를 고르고 **코스 계산하기**를 누른다. 선택 중심 주변 2km 도로를 준비한 뒤 휴대폰 내부에서 계산한다. GPS 확인·지도 로딩·지도 이동 중에는 계산을 시작하지 않는다.
5. 완료 후 **도로 조회 / 코스 계산 / 전체 소요 시간**과 **계산 기준** 좌표를 확인한다. 결과의 기준 좌표는 버튼을 누른 순간의 중심이다. 후보를 선택해도 계산 중심은 유지한다.

지도 이동·내 위치 재요청·도형/거리 변경은 진행 중 작업을 취소하지만 **완료된 경로·후보 선택·소요 시간·계산 기준 좌표는 유지한다.** 현재 십자 표시와 계산 중심은 다음 탐색에 사용할 위치이고, 표시 중인 경로는 이전 계산 기준에 그대로 놓인다. **코스 계산하기를 다시 누르면** 이전 결과를 지우고 새 중심·조건으로 조회한다. 합성 격자 등 다른 데이터 종류로 전환할 때도 결과를 초기화한다. 화면 이탈·백그라운드 전환은 진행 중 도로 조회와 계산을 취소한다. 결과 표시 때 카메라를 자동 이동하지 않으며, 완료 후에도 경로를 보면서 지도를 이동·확대할 수 있다.

## 지도와 계산용 도로 데이터

배경 지도는 MapTiler 타일이고 계산용 자료는 OSM 도로다. 지도 이동만으로 계산용 도로를 요청하지 않는다. 계산 버튼을 누를 때 아래 순서로 준비한다.

1. 선택한 중심 주변 2km 전체를 포함하는 유효한 메모리 캐시가 있으면 재사용한다.
2. 없으면 기존 웹 프로토타입의 `https://running-art-seoul-mobile.alo-ha.chatgpt.site/api/roads`로 중심 좌표·반경·데이터 버전을 보낸다. `EXPO_PUBLIC_ROAD_DATA_URL`로 호환 공급자를 설정할 수 있다.
3. 공급자는 서울 도심에서 2026-09-20 저장 OSM 자료를 제공하고 저장 범위 밖에서는 Overpass 조회를 사용한다. 기본 공급자가 시간 초과·HTTP 오류·불완전한 응답을 반환하면 앱에서 `overpass-api.de`, `overpass.private.coffee` 순서로 같은 지역의 도로를 직접 조회한다. 각 조회는 본문 읽기까지 25초로 제한하고 전체 조회·검사는 최대 90초다. 일부 도로만 받은 응답은 계산·캐시에 사용하지 않는다.
4. 받은 OSM way 전체 좌표·태그·노드 ID를 보존해 v0.2 엔진에 전달한다. 원형 반경 적용과 코스 계산은 기기 내부에서 수행한다. 계산 서버·Gemini 호출을 추가하지 않는다.

기존 웹 중계 서버도 저장 자료·캐시가 없으면 같은 두 Overpass 서버를 사용한다. 따라서 직접 조회는 중계 서버를 우회하는 보완이며 독립적인 공급원 세 개를 확보한 구조가 아니다. Overpass 자체가 병목이면 같은 서버를 재조회하면서 대기·요청이 늘어날 수 있다. 이번 검증은 중계 서버를 차단한 상황의 우회 성공이며, Overpass 자체 장애 해소나 조회 속도 개선을 입증하지 않는다. 영구 캐시·지역별 사전 도로 파일 제공은 후속 검토 범위다.

`X-Road-Area` 헤더의 사각 범위가 요청 반경 전체를 포함해야 캐시를 재사용한다. 기본 공급자의 헤더가 없으면 요청의 정확한 외접 사각형까지만 재사용한다. 직접 Overpass 조회는 실제 요청한 바깥쪽 0.02도 격자 사각형을 사용하고 전체 way geometry·노드 ID를 보존한다. 선택한 위치의 조회가 실패해도 광화문 고정 표본으로 대신 계산하지 않는다. 직접 요청에는 앱을 식별하는 User-Agent를 포함한다. 사용자 지정 `EXPO_PUBLIC_ROAD_DATA_URL`에는 다른 공급자로의 자동 전환을 적용하지 않는다.

캐시는 프로세스 메모리에 **최대 2개 영역·15분**, 원문 문자 수 합계 **2천만**을 상한으로 보관한다. 응답 하나도 2천만 문자·10만 요소를 초과하면 거절한다. 객체 메모리의 정확한 바이트 제한은 아니다. 앱 프로세스가 종료되면 캐시는 사라진다.

모든 공급자가 실패하면 HTTP 오류·부분 응답·손상된 노드/좌표·범위 부족·시간 초과를 안내하고 실패·취소 응답을 캐시에 넣지 않는다. 이동/취소 시 다음 공급자로 전환하지 않고 중단하며, 늦게 도착한 응답도 결과·캐시에 반영하지 않는다. 공개 Overpass 가용성에 의존하므로 모든 지역에서 항상 성공하는 것을 보장하지 않는다. 도로 파일 영구 저장·버전 마이그레이션·오프라인 복원은 아직 구현하지 않았다.

## 시간과 원본 비교

| 표시 | 측정 범위 |
| --- | --- |
| 도로 조회 | 캐시 확인 또는 다운로드·JSON 해석·데이터 검사 |
| 코스 계산 | 그래프 구성·탐색·화면 응답을 위한 실행 양보를 포함한 경과 시간 |
| 전체 소요 시간 | 위 두 단계 합계 |

지도 타일 로딩과 GPS 대기는 계산 버튼을 누르기 전이므로 포함하지 않는다. `ROUTE_LAB_METRICS.timing`은 `roadMs`, `calculationMs`, `totalMs`를 밀리초로 기록하고 `cached`로 캐시 사용을 구분한다. 기존 `elapsedMs`는 엔진만의 경과 시간이다. 선택 좌표·GPS 좌표·지도 키는 측정 로그에 추가하지 않는다.

합성 격자·단절 테스트는 고정 표본을 유지한다. 합성 하트 5km·다이아몬드 3km는 앱에서 원본과 비교한다. **서울 OSM의 이동 가능한 입력은 고정 광화문 원본과 비교하지 않는다.** 고정 서울 표본과 전체 결과 회귀는 Node 테스트에 보존했다. 이전 고정 입력의 휴대폰 24.83초와 새 위치의 조회 포함 시간을 직접 성능 비교하지 않는다.

구현은 `src/modules/road-data/client.ts`, `src/features/route-lab/center-controller.ts`, `session.ts`, `src/modules/map/MapSurface.tsx`, `src/app/route-lab.tsx`에 나뉜다. 자동 검사는 `tests/route-center-road.test.mjs`, 실제 확인 결과는 [검증 기록](../quality/route-center-verification.md)에 있다.
