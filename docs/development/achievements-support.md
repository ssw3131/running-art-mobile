# S5 성취·공유 / S6 계정·지원 계약

2026-10-14 구현 후 검증 중. [검증/실패 이력](../quality/achievements-support-20261014.md)·[실행 기록](../history/executed-plans/2026-10-14-0908-achievements-service.md)을 따른다. 운영 문의·공지 SQL과 약관은 미배포다.

## 성취

- 현재 소유자의 SQLite 종료 기록 전체를 읽어 누적 거리·활동 시간·러닝/완주 횟수·연속일·도형 배지를 재집계한다. 별도 배지 발급 행은 만들지 않는다. 기존 기록·동기화 복원도 같은 기준이고 삭제하면 즉시 다시 집계한다.
- 도형 배지는 코스 사본의 유효한 도형과 `course_outcome=finished`인 종료 기록이 필요하다. 재도전은 별도 러닝이다. 자유 러닝·중도 종료는 완주 배지에 포함하지 않는다. 직접 그리기/이미지 윤곽은 기존 저장 형식의 `custom` 배지로 묶는다.
- 연속일은 실제 거리 0 초과인 종료 기록의 시작일을 기기 달력으로 센다. 같은 날 여러 번 달려도 하루이고, 자정을 넘긴 러닝도 시작일에 귀속한다. 오늘 또는 어제까지 이어진 일수를 현재 연속일로 표시한다. 기기 시간대가 바뀌면 표시 일수도 재계산된다.
- 칼로리·체중 입력은 사용자 결정으로 제외했다. 회원별 집계가 비로그인/다른 계정에 노출되지 않도록 화면 및 저장소 소유권을 함께 확인한다.

## 결과와 이미지 카드

- 종료·저장 뒤 결과 화면에서 배지/통계·기록 상세·카드·홈으로 이동한다. 기존 기록 상세와 링크 공유는 유지한다.
- 카드 비율은 9:16(1080×1920) 및 4:5(1080×1350) PNG다. 실제 거리·활동 시간·평균 페이스, 닉네임·러닝 시작 날짜를 기본 표시한다. 닉네임/날짜는 끌 수 있다.
- 코스 연결 기록은 ‘계획 코스 윤곽’, 자유 러닝은 ‘실제 러닝 윤곽’으로 구분한다. GPS 구간의 공백을 연결하지 않는다. 지도·주소·코스의 개인 이름·원본 좌표/EXIF는 카드 데이터에 넣지 않는다. 경로는 비율이 유지된 픽셀 좌표로 정규화한다.
- 원본 Figma 이미지/아이콘 및 실제 글꼴이 로드된 후 네이티브 캡처를 수행한다. 출력 크기를 확인하고 생성된 PNG를 미리보기로 보여준다. 저장/OS 공유는 이 파일을 그대로 사용한다. 옵션 변경 후에는 이전 미리보기를 보낼 수 없다.
- 공유창 종료는 전달 성공이 아니다. 저장은 Android 폴더 선택기의 실제 생성/쓰기 완료 뒤 성공을 표시한다. 취소·실패·다중 터치·계정 변경·화면 이탈을 구분한다. 수신 앱이 읽는 공유 PNG는 캐시에 남기고 다음 카드 생성 때 하루가 지난 카드만 정리한다.

## 계정과 테마

- 기존 프로필·사진 처리·연결 계정·로그아웃·탈퇴·동기화 계약을 재사용한다. 탈퇴 안내 확인과 최종 확인 후 기존 복구 가능한 탈퇴 절차를 실행한다. 기기 기록은 비로그인으로 보관한다.
- 계정별 기기 테마(system/light/dark)를 서비스 루트와 지도에 연결한다. 저장 후 알림과 앱 재진입/재시작 읽기로 갱신하며 계정 전환 후 이전 계정 팔레트를 사용하지 않는다. 카드 이미지는 테마와 별개다.
- 지도는 기존 Streets v2의 [공식 dark 변형](https://docs.maptiler.com/sdk-js/api-reference/variables/Externals.MAP_STYLE_CONFIG/)을 사용한다. 공급자는 v4로 이전을 권고하지만 기존 지도 전체 이전은 이번 범위가 아니다.

## 안내·문의·공지·정책

- 소개/사용법/FAQ는 앱에 포함해 오프라인에서 읽는다. 미구현 AI/예상 시간/난이도·커뮤니티·칼로리를 제공한다고 쓰지 않는다.
- 공지는 운영자가 `service_notices`에서 게시한 최근 100개만 읽는다. 미래 게시/초안은 제외한다. 마지막 정상 목록을 기기 캐시에 보관하고 오프라인이면 확인 날짜와 저장본임을 표시한다. 예시 공지나 출시일은 시드하지 않는다.
- 문의는 로그인 계정 식별값, 유형/제목/본문과 선택 이메일을 저장한다. 이메일 미입력도 허용하고 GPS/사진은 자동 첨부하지 않는다. 제출 전 고유 요청번호와 내용 사본을 암호화 저장한다. 응답 유실·재시작 후 같은 내용/번호로만 재전송해 중복 접수를 방지한다.
- 서버는 본인·활성 계정만 제출을 허용하고 한 시간 신규 5건으로 제한한다. 같은 요청 재시도는 제한에 포함하지 않으며 다른 내용으로 재사용하면 거부한다. 타인/익명 읽기·직접 쓰기는 금지한다. 계정 삭제 시 문의도 cascade 삭제하고 기기의 미확인 문의 사본을 정리한다.
- 문의 접수는 Supabase 영수증 수신으로 판정한다. 실제 답변 운영자·연락처/보존 기간·운영 채널 확정과 운영 SQL 적용은 별도 완료 조건이다. 미정 상태에서 운영 접수나 메일 발송 완료를 주장하지 않는다.
- 이용약관은 S1 동의에 사용하는 활성 버전과 같은 본문을 읽는다. 개인정보 처리방침·위치 약관은 별도 게시 문서다. 미게시/읽기 실패를 명확히 표시하고 Figma 초안 placeholder는 제품에 노출하지 않는다. 운영자·시행일 등의 확정/법적 검토를 대신하지 않는다.
