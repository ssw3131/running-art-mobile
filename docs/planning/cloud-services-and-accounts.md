# Running Art 서버 서비스와 가입 준비 안내

작성일과 공식 자료 확인일: 2026-09-30 (Asia/Seoul)

Running Art 운영에 추천한 Cloudflare R2·Supabase·MapTiler의 역할, AWS와의 비교, 향후 서버 이전 가능성, 미리 준비할 계정을 정리한다. 서버 서비스를 처음 사용하는 프로젝트 소유자가 준비 순서를 확인하기 위한 안내다.

**2026-10-01 Cloudflare·Supabase 가입 보고 후 사용자가 R2 버킷을 생성했다.** `running-art` 버킷(APAC·Standard)에 개발용 공개 주소를 연결하고 최초 표본 25개와 현재 버전 포인터를 배포·검증했고, 후속으로 판교를 포함한 33개 객체로 확장했다. 후속 사용자 결정으로 도메인 구매는 미루고 개발용 `r2.dev` 주소와 버킷 한정 업로드 접근 설정으로 먼저 검증한다. 배포 도구의 개발용 모드·로컬 검사·실제 S3/공개 HTTP 검사는 완료했으며 4-3 앱 연결·휴대폰 캐시 검증도 완료했다. 다음 데이터 작업은 4-4 전국 공급·갱신 운영이다. 결제 수단 세부 정보는 열람하지 않았고 Supabase 프로젝트 생성 여부는 미확인이다. 스토어·메일·소셜 로그인 계정은 해당 기능을 구현하거나 출시할 때 준비한다.

이 문서는 대화에서 설명한 내용을 보존한 안내다. 계정 가입·버킷 생성은 사용자가 완료했다. 이후 사용자 확인을 받아 버킷 한정 키를 발급하고 개발용 표본을 업로드·검증했다. 결제·도메인 구매는 실행하지 않았다. 최신 구현 상태는 [현재 상태](../handoff/status.md), 서버 방향은 [독립 서버 전략](server-strategy.md), 개발 순서는 [로드맵](roadmap.md)을 우선한다. 요금과 가입 조건은 실제 신청 시 다시 확인한다.

**2026-10-01 후속 결정:** 사용자가 계정 가입 전에 가능한 작업을 먼저 요청해 GPX 내보내기를 구현·에뮬레이터 검증했다. 아래 가입 준비는 서버 작업을 재개할 때의 안내이며 현재 앱 작업의 선행 조건이 아니다. [GPX 사용법](../development/gpx-export.md)

## 대화 당시 완료한 일과 다음 작업 — 2026-09-30

- **4-1 도로 표본 검증 완료:** SM-S942N에서 27회 입력·그래프 비교, 메모리·취소를 확인했다. 표본 공급 형식은 0.02도 격자·gzip level 6다.
- **4-2 배포 도구 준비 완료:** 실제 전용 R2 버킷·HTTPS 도메인 구축과 업로드는 아직 보류 상태다.
- **4-3 영구 캐시 일부 완료:** 캐시 모듈과 PC 검증은 완료했고 일반 계산의 새 공급 연결·휴대폰 캐시 검증은 남아 있다.
- **로컬 코스 저장 완료:** 저장·목록·다시 열기·이름 변경·삭제와 휴대폰 독립 실행·오프라인 복원을 확인했다. 서버와 독립적인 앱 후속은 저장 코스의 GPX 내보내기다.

서버 작업을 재개하면 **전용 버킷·도메인 준비 → 표본 배포와 버전 전환·복구 검증 → 앱 공급 전환·휴대폰 캐시 검증 → 전국 공급 확대** 순서로 진행한다. 대화 당시에는 기존 API를 사용했으며 현재 코드·설치 APK는 R2 표본으로 전환했다. [실제 배포 절차](../development/road-deployment.md)를 따른다.

## 각 서비스가 맡는 역할

아래는 모바일의 목표 구성이다. 서비스가 제공하는 기반 위에 앱 연결·데이터 구조·접근 권한을 구현해야 하며, 가입만으로 기능이 완성되지는 않는다.

| 서비스 | 쉬운 설명 | Running Art에서 맡길 일 |
| --- | --- | --- |
| Cloudflare R2 | 공용 파일 창고 | 우리가 가공한 지역별 보행 도로 파일을 보관하고 휴대폰에 제공 |
| Supabase | 회원과 개인 기록을 관리하는 서버 기반 | 로그인, 코스·러닝 기록 동기화, 공개 코스·게시글·댓글, 개인 파일 관리 |
| MapTiler | 화면에 보이는 지도 공급자 | 도로·건물·지명이 표시되는 배경 지도 자료 제공 |
| 휴대폰 내부 알고리즘 | 코스를 찾는 계산기 | 내려받은 도로의 연결 관계를 이용해 도형을 닮은 코스 계산 |

R2의 **버킷**은 파일을 담는 보관함이고, **도메인**은 파일을 받으러 가는 인터넷 주소다. CDN은 파일 사본을 여러 곳에 저장해 가까운 곳에서 전달하는 배포망을 뜻한다. 여기서 우리 서버란 우리 계정으로 설정·관리하는 클라우드 자원을 포함하며, 직접 서버 컴퓨터를 보유해야 한다는 의미는 아니다. [R2 소개](https://developers.cloudflare.com/r2/) · [Supabase 데이터베이스](https://supabase.com/docs/guides/database/overview) · [Supabase 로그인](https://supabase.com/docs/guides/auth) · [MapTiler API](https://docs.maptiler.com/cloud/api/)

### MapTiler와 계산용 도로 파일의 차이

**앱은 MapTiler 서버에서 배경 지도를 직접 받는다. R2가 MapTiler 요청을 중개하지 않는다.** 화면용 지도 자료와 알고리즘에 넣을 도로 연결 자료는 용도가 다르다.

우리 계획에서는 OSM 원본을 독립 가공해 길의 식별자·연결 관계·보행 속성을 보존한 파일을 R2에 올린다. 휴대폰은 이 자료로 코스를 계산한다. MapTiler 자료에서 우리 계산용 파일을 추출하는 구조가 아니다.

예를 들어 사용자가 주변의 하트 모양 5km 코스를 요청하면 다음과 같이 동작하도록 연결할 계획이다.

1. R2에서 필요한 지역의 도로 파일을 받고, 저장된 정상 자료가 있으면 재사용한다.
2. 휴대폰 내부 알고리즘이 코스를 계산한다.
3. 앱이 MapTiler 배경 지도 위에 코스를 표시한다. 지도 자료는 지도 표시 과정에서 별도로 요청한다.
4. 회원 기능을 구현한 뒤에는 사용자의 코스·러닝 기록을 Supabase에 동기화한다.

도로 파일이 휴대폰에 쌓여도 배경 지도가 함께 저장되는 것은 아니다. 화면에 필요한 지도 자료가 캐시에 없으면 MapTiler 요청은 계속 필요하다. 배경 지도의 오프라인 저장은 별도 기능이며 저장 용량과 공급자 이용 조건을 검토해야 한다. 현재 저장 코스 상세의 기본 경로 표시는 외부 배경 지도 없이도 동작한다.

## AWS와 비교한 선택 이유

AWS로도 같은 기능을 만들 수 있다. 아래는 가능한 대응 예시이며 AWS 구성을 확정한 것은 아니다.

| 필요한 기능 | 현재 권장 구성 | AWS 구성 예시 |
| --- | --- | --- |
| 공용 도로 파일 저장·배포 | R2와 사용자 도메인·캐시 | S3와 CloudFront |
| 회원 로그인 | Supabase Auth | Cognito |
| 기록·커뮤니티 데이터와 서버 처리 | Supabase Postgres·서버 함수 | 요구에 맞는 데이터베이스·API·Lambda |

AWS의 Amplify도 로그인·데이터·파일 저장·서버 함수 구성을 돕는다. AWS를 선택한다고 항상 서버 운영체제를 직접 관리해야 하는 것은 아니다. [Amplify 공식 안내](https://docs.amplify.aws/react-native/build-a-backend/)

**현재 프로젝트에서는 R2와 Supabase가 초기 개발·운영 부담을 줄이기 좋은 조합이라고 판단했다.** 이는 우리 작업 범위를 기준으로 한 추천이며 모든 앱에서 더 쉽다는 보장은 아니다. Supabase는 회원과 관계형 데이터를 한 제품 안에서 다룰 수 있고, R2는 공용 도로 파일 배포에 집중할 수 있다. AWS는 세밀한 구성과 다른 AWS 서비스 연동이 필요할 때 선택지가 넓다. AWS 경험이나 기존 운영 환경이 있다면 판단이 달라질 수 있다.

비용도 AWS가 항상 더 비싸다고 단정하지 않는다. 2026-09-30 확인 기준은 다음과 같다.

- **R2:** 인터넷 전송량에 대한 요금이 없고 저장 용량과 요청 횟수 등으로 과금한다. Standard에는 월 저장 10GB·쓰기 등 Class A 100만 회·읽기 등 Class B 1천만 회의 무료 제공량이 있다. 다른 유료 서비스를 연결하면 그 요금은 별도다. [R2 요금](https://developers.cloudflare.com/r2/pricing/)
- **Supabase:** 무료 개발 요금제가 있고 Pro는 월 25달러부터다. 추가 프로젝트·컴퓨팅·사용량 등에 따라 달라지며 앱 전체 운영비의 상한이 아니다. [Supabase 요금](https://supabase.com/pricing)
- **AWS CloudFront:** 무료와 정액 요금제도 제공하므로 전송량 과금만으로 R2와 비교하면 부정확하다. CloudFront 요금제가 회원·DB 등 AWS 전체 비용을 포함하는 것은 아니다. [CloudFront 요금](https://aws.amazon.com/cloudfront/pricing/)

전체 비용에는 지도 사용량, 도메인, 메일, 백업 등이 함께 들어간다. 사용자 수가 늘었다는 이유만으로 AWS 이전이 필수가 되지는 않으며 실제 사용량·성능·운영 요구로 판단한다.

## Supabase를 쓰다가 다른 서버로 옮길 수 있는가

**가능하다. 다만 데이터 복사와 서비스 기능 이전을 함께 계획해야 한다.** Supabase가 사용하는 PostgreSQL은 널리 쓰이는 데이터베이스다. 다른 PostgreSQL 환경으로 데이터를 옮기거나 Supabase를 직접 운영하는 선택지도 있다. 버전·확장 기능·권한 정책의 호환성은 확인해야 한다. [데이터베이스 안내](https://supabase.com/docs/guides/database/overview) · [직접 운영하는 환경으로 복원](https://supabase.com/docs/guides/self-hosting/restore-from-platform)

| 이전 대상 | 필요한 작업 |
| --- | --- |
| 코스·러닝 기록·게시글 | 데이터 구조와 데이터를 이전하고 회원별 소유 관계·검색·접근 권한 검증 |
| 사진·GPX 등 파일 | 실제 파일을 별도로 복사하고 파일 주소·접근 설정 변경. DB 백업만으로 파일 내용이 복원되지는 않음 |
| 로그인 계정 | 새 로그인 체계와 기존 회원·기록을 연결하고 비밀번호·소셜 로그인·세션 전환 검증 |
| 서버 함수·API·실시간 기능 | 새 환경에 배포하거나 다시 구현하고 앱 연결 수정 |

파일과 DB의 백업 범위는 다르다. Cognito에는 사용자가 로그인할 때 기존 비밀번호로 인증하면서 계정을 이전하는 방식도 있으므로, 이전이 곧 모든 회원의 비밀번호 재설정을 뜻하지는 않는다. 실제 적용 가능성은 선택한 로그인 방식과 이전 조건에 따라 확인한다. [백업 범위](https://supabase.com/docs/guides/platform/backups) · [Cognito 회원 이전](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools-import-users.html)

앞으로 회원 기능을 구현할 때 서버 연결 코드를 모으고, 회원·코스의 고유 번호를 안정적으로 유지하며, 데이터 구조 변경과 백업·복원 절차를 기록하면 이전 부담을 줄일 수 있다. 이는 후속 구현 시 적용할 방향이며 회원 서버가 이미 구현됐다는 뜻은 아니다. 휴대폰 내부 코스 계산과 공용 도로 공급은 회원 서버와 별도로 유지할 수 있다.

## 가입과 사전 준비 목록

기존 계정이 있다면 새 계정을 무조건 만들 필요는 없다. 모바일 전용 버킷·프로젝트·키를 준비하고 기존 테스트 프로젝트의 운영 자원·자격 증명을 공유하지 않는 방향이다. 표의 준비 항목은 체크 대상이며 이번 대화에서 완료 여부를 확인한 목록은 아니다.

### 지금 준비하거나 접근을 확인할 계정

| 대상 | 지금 할 일 | 이어서 설정할 일 |
| --- | --- | --- |
| [Cloudflare](https://dash.cloudflare.com/) | 가입·R2 사용 활성화·사용자 생성 `running-art` 버킷 확인(2026-10-01 브라우저). 결제 수단 세부 정보는 미열람 | 개발용 공개 URL·버킷 한정 키·실제 표본 배포 검증 완료. 다음은 앱 연결. R2 무료 제공량 초과 시 사용량 과금 |
| 서비스용 도메인 | 보유 도메인 없음. 2026-10-01 사용자 결정으로 구매를 운영 단계로 연기 | 운영 시 R2와 같은 Cloudflare 계정에 도메인을 등록하고 도로용 하위 주소 연결. `roads.example.com`은 형식 예시 |
| [MapTiler](https://cloud.maptiler.com/) | 앱에 연결된 키를 관리하는 기존 계정에 로그인 가능한지 확인 | 모바일 전용 키, 사용량과 운영 요금제 확인 |
| [Supabase](https://supabase.com/dashboard) | 가입 완료(2026-10-01 사용자 보고). 프로젝트 생성 여부는 미확인 | 회원 기능 구현 시 모바일 전용 프로젝트·지역·요금제 결정. 지금 도로 배포의 선행 조건은 아님 |
| [GitHub](https://github.com/) | 기존 모바일 저장소 계정의 접근 확인 | 현재 소스·APK 관리에 사용. 기존 공개 이력이 있으므로 신규 가입 필요 여부부터 확인 |

R2는 대시보드의 `Storage & databases → R2 → Overview`에서 사용 설정을 시작한다. 사용자 도메인을 연결하려면 해당 도메인이 R2 버킷과 같은 Cloudflare 계정에 등록되어 있어야 한다. 개발용 `r2.dev` 주소는 요청량 제한·Cloudflare 캐시 미지원이며 테스트에 사용한다. 배포 도구에서 `publicUrlMode: "r2-dev"`를 명시하면 허용하고 기본 운영 모드는 사용자 도메인을 요구한다. [R2 시작 안내](https://developers.cloudflare.com/r2/get-started/) · [도메인 연결](https://developers.cloudflare.com/r2/buckets/public-buckets/) · [배포 설정](../development/road-deployment.md) · [MapTiler 키 관리](https://docs.maptiler.com/guides/credentials/api-key/)

### 기능 구현이나 출시 때 준비할 계정

| 대상 | 필요한 시점 | 가입과 준비 내용 |
| --- | --- | --- |
| Google Play Console | Android 스토어 테스트·출시 전 | Google 계정으로 개발자 등록, 개인·조직 유형 선택, 신원·기기 확인 등 해당 요건 완료. 등록비 1회 25달러. [등록 안내](https://support.google.com/googleplay/android-developer/answer/6112435?hl=ko) |
| 이메일 발송 서비스 | 가입 인증·비밀번호 재설정 메일을 실제 사용자에게 보낼 때 | SMTP를 지원하는 서비스 하나를 선택해 가입하고 발신 도메인 인증·Supabase 연결. Resend 등은 선택 예시이며 아직 업체를 정하지 않음. [메일 설정](https://supabase.com/docs/guides/auth/auth-smtp) |
| 소셜 로그인 개발자 콘솔 | Google·카카오 등 선택한 로그인을 구현할 때 | 사용할 업체의 계정·개발자 콘솔에서 앱과 로그인 설정 등록. 모든 업체에 미리 가입할 필요는 없음. [소셜 로그인](https://supabase.com/docs/guides/auth/social-login) |
| Apple Developer Program | 향후 iOS 배포 시 | Apple 계정과 개발자 프로그램 가입. 기본 안내 가격 연 99달러, 지역별 결제 금액은 다를 수 있음. [등록 안내](https://developer.apple.com/programs/enroll/) |

Google 로그인 설정과 Google Play 개발자 등록은 목적과 절차가 다르다. Supabase 기본 메일 발송은 팀에 등록된 주소 등으로 제한되어 운영용 사용자 메일은 별도 발송 서비스를 준비한다.

2023-11-13 이후 생성한 개인 Play 개발자 계정은 현재 **최소 12명의 테스터가 14일 연속 참여 상태를 유지하는 비공개 테스트**를 진행한 뒤 프로덕션 접근을 신청해야 한다. 계정만 미리 만들어두는 것으로 테스트 기간이 충족되지는 않는다. 출시 일정에 테스터 확보와 실제 테스트 기간을 포함한다. [공식 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko)

### 계정 외에 미리 정할 것

- 계속 관리할 이메일 주소와 각 서비스에 사용할 계정 소유자.
- 서비스명·도메인 후보와 기존 도메인 보유 여부.
- 도메인·사용량·스토어 등록비를 결제할 수단. 지원 수단은 각 가입 화면에서 확인한다.
- 스토어의 실제 운영 주체에 맞는 개인·조직 계정 유형과 해당 신원 확인 자료. 조직 계정은 추가 자료가 필요할 수 있다.
- 출시 때 제공할 로그인 방식과 문의용 연락처.

가입·본인 인증·결제 정보 입력을 마치면 버킷·도메인·프로젝트 설정과 앱 연결을 이어갈 수 있다. 구체적인 계정·도메인·요금제·로그인 방식은 아직 확정하지 않았으며 다음 실제 작업에서 확인한다.
