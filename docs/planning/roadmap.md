## 독립 서버의 다음 실행 순서

**방향 정리 완료 → 4-1 로컬 표본·공급 형식 검증 → 4-2 실제 서버 구축·배포 → 4-3 앱 연결 전환 → 4-4 전국 운영** 순서입니다.

2026-09-30 후속 결정으로 실제 서버 배포를 보류했습니다. 서버와 독립적인 4-3 영구 캐시와 5단계 로컬 코스 저장을 먼저 구현·검증했고, 이후 사용자 요청으로 **4-1 휴대폰 표본 검증을 완료했습니다. 이후 2026-10-01 4-2 개발용 실제 배포를 완료했고 4-3 앱 연결·휴대폰 검증도 완료해 다음은 4-4 전국 공급·갱신 운영**입니다. 서버 가입 전 가능한 작업으로 GPX 내보내기도 완료했으며 후속 휴대폰 GPX 확인도 완료했습니다. 다음 앱 작업은 코스 시뮬레이션입니다. 서버 준비가 모든 앱 기능의 선행 조건은 아닙니다. 새 공급 연결·기존 API 제거는 실제 배포 후 검증했습니다.

1. **4-1 로컬 검증:** 새 OSM 원본으로 서울·부산·지역 경계 자료를 가공하고 연결성과 모바일 처리 비용을 확인합니다. 형식 초안을 먼저 만들고 측정 결과로 확정합니다. 로컬 파일·테스트용 로컬 제공만으로 시작하며 두 테스트 프로젝트의 서버에 의존하지 않습니다.
2. **4-2 실제 서버 구축·배포:** 표본의 크기·개수·요청량을 기준으로 저장소·전송·배포 구성을 구체화합니다. 개발용 `r2.dev`로 먼저 검증했고 운영 단계에서 사용자 도메인·CDN을 연결합니다.
3. **4-3 앱 전환 — 표본 범위 완료:** 새 공급·영구 캐시를 연결하고 기존 API·대체 연결을 제거했습니다. PC에서는 다른 공급자를 거절하고 실제 R2를 대조했으며, 휴대폰 빈 캐시·오프라인 계산과 별도 에뮬레이터 신규 설치도 검증했습니다.
4. **4-4 전국 운영:** 자료 갱신·실패·이전 버전 복구와 사용량을 검증합니다.
5. **5단계 회원·서비스:** 로그인·코스/러닝 기록·동기화·공유·커뮤니티를 구현하고 6단계 무료 출시 검증으로 이어갑니다.

표본 검증은 파일 크기·다운로드 단위·휴대폰 메모리를 알아야 서버 규모와 전송 방식을 결정할 수 있기 때문에 먼저 진행합니다. 회원·커뮤니티 서버의 데이터 설계는 별도로 검토할 수 있으며 도로 표본 검증의 선행 조건이 아닙니다. 자세한 산출물과 단계 진입 조건은 [서버 계획](server-strategy.md)을 따릅니다.

기존 Sites 서버 복구·배포는 이 순서에서 제외합니다. 유료화·결제·사용권·생성 횟수 차감 구현도 현재 실행 순서와 완료 조건에 포함하지 않습니다. 아래 9월 27일 계획과 검증은 당시 실행 이력이며 변경된 서버 방향은 이 절과 [서버 전략](server-strategy.md)을 우선합니다.

## 변경된 실행 순서와 남은 범위 — 2026-09-27

고정 표본 계산 이후 예정했던 **주변 보행 도로 불러오기**와 **도로 데이터 저장·재사용** 중 일부를 지도 중심 계산 작업에 앞당겨 포함했습니다. 실제 실행 순서는 **v0.2 이식·성능 개선 → 현재 위치/지도 중심 선택 → 주변 도로 API 조회·메모리 캐시 → 조회 시간 표시 → 에뮬레이터 독립 실행·설치 파일 생성**입니다.

현재 위치는 최초 지도 중심으로 사용하고, 이후 지도를 움직이면 **사용자가 선택한 지도 중심**이 도로 조회와 계산 기준이 됩니다. 배경 지도 타일과 계산용 도로 데이터는 별개입니다. 현재 데이터 공급자는 기존 웹의 도로 API이며, 원래 계획의 정적 지역 파일·영구 캐시는 아직 완료하지 않았습니다.

후속 데이터 작업은 이미 구현한 조회를 다시 만드는 대신 **영구 도로 저장·오프라인 재사용과 지역 경계/복원 검증**을 중심으로 진행합니다. 휴대폰 설치·기본 실행은 후속 요청으로 완료했으며 실제 GPS 기준 조회·계산은 별도 확인이 필요합니다. 최종 서비스 기획·디자인과 러닝·코스 저장 기능은 기존 5단계 범위를 유지합니다. 이는 후속 계획이며 아직 추가 구현하지 않았습니다.

이번 실행 증거는 [지도 중심 검증](../quality/route-center-verification.md), 계획 원문과 범위 변경은 [실행 기록](../history/executed-plans/2026-09-27-1835-map-center-routes.md), 설치 파일 안내는 [테스트 APK](../development/android-test-apk.md)에 있습니다.

### 후속 범위

## 3단계 알고리즘 이식 순서

1. 모바일 루트 기준 `../running-art/exports/running-art-algorithm/`의 v0.2 엔진·명세·테스트·합성 그래프를 확보하고 `../running-art/versions/v0.2/` 보관본과 출처를 대조합니다.
2. 동일한 고정 입력과 `version: '0.2'`로 원본 결과를 확보합니다. 점수, 경로 연결·복귀, 총거리, 반복 도로, 크기 범위와 v0.1 기준 후보 보존을 회귀 기준으로 삼습니다.
3. 계산을 `src/modules/route-engine/`에 TypeScript로 이식하고 네트워크·지도·저장·UI와 분리합니다. v0.2에 포함된 도형과 점수 함수를 보존합니다.
4. 원본과 모바일 모듈을 비교한 뒤 Android에서 계산 시간·메모리·UI 응답성·진행률·취소를 검증합니다. 실행 방식은 측정 결과에 맞춰 정합니다.

위 순서로 이식·에뮬레이터 검증을 완료했으며 실제 결과는 [현재 상태](../handoff/status.md)에 기록했습니다.

## 작업 방식

1. 해당 단계의 결정·현황·완료 조건을 확인하고 범위와 검증을 계획합니다.
2. 이미 허용된 범위의 일반 구현은 불필요한 재승인 없이 진행합니다.
3. 실제 구현 직전에 실행 기록을 만듭니다. 계획만 논의하고 끝나면 만들지 않습니다.
4. 기능 단위로 구현하고 필요한 검증을 수행합니다.
5. 실제 결과·실패·미검증을 기록하고 현재 상태를 갱신합니다.

## 해당 단계에서 정할 항목

- 배포: 정식 앱 ID·서명·스토어 계정·릴리스 조건·iOS 일정.
