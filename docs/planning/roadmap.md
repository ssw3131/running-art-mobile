## 변경된 실행 순서와 남은 범위 — 2026-09-27

고정 표본 계산 이후 예정했던 **주변 보행 도로 불러오기**와 **도로 데이터 저장·재사용** 중 일부를 지도 중심 계산 작업에 앞당겨 포함했습니다. 실제 실행 순서는 **v0.2 이식·성능 개선 → 현재 위치/지도 중심 선택 → 주변 도로 API 조회·메모리 캐시 → 조회 시간 표시 → 에뮬레이터 독립 실행·설치 파일 생성**입니다.

| --- | --- | --- |

현재 위치는 최초 지도 중심으로 사용하고, 이후 지도를 움직이면 **사용자가 선택한 지도 중심**이 도로 조회와 계산 기준이 됩니다. 배경 지도 타일과 계산용 도로 데이터는 별개입니다. 현재 데이터 공급자는 기존 웹의 도로 API이며, 원래 계획의 정적 지역 파일·영구 캐시는 아직 완료하지 않았습니다.

후속 데이터 작업은 이미 구현한 조회를 다시 만드는 대신 **영구 도로 저장·오프라인 재사용과 지역 경계/복원 검증**을 중심으로 진행합니다. 사용자가 휴대폰을 연결해 검증을 요청하면 설치용 APK의 실제 GPS·조회·계산을 확인합니다. 최종 서비스 기획·디자인과 러닝·코스 저장 기능은 기존 5단계 범위를 유지합니다. 이는 후속 계획이며 이번 커밋에서 추가 구현하지 않습니다.

이번 실행 증거는 [지도 중심 검증](../quality/route-center-verification.md), 계획 원문과 범위 변경은 [실행 기록](../history/executed-plans/2026-09-27-1835-map-center-routes.md), 설치 파일 안내는 [테스트 APK](../development/android-test-apk.md)에 있습니다.

## 실행한 개발 목표 — v0.2 모바일 코스 계산 검증

후속으로 [성능 최적화·웹 비교](../development/route-engine-performance.md)를 반영했습니다. 검색 범위와 전체 결과를 유지한 상태에서 PC Node 중앙값은 9.82초에서 4.21초로 감소했습니다. 수정 후 폰 반복·입력/취소·메모리와 에뮬레이터 검증을 완료했습니다. 폰은 개발 모드 중앙값 58.44초, 개발 APK + 배포용 JavaScript 44.27초, 독립 실행 릴리스 APK 24.83초로 수십 초 대기가 남습니다. 장시간·열 조건과 남는 병목을 확인해 별도 실행 스레드·네이티브 계산 필요성을 판단합니다.

설정일: 2026-09-27. 상태: **이번 실행 범위 완료 — 구현·자동 검사·Android 에뮬레이터 검증**.

2026-09-27 후속 결정: 사용자가 실행을 요청했고, 실제 휴대폰 검증은 나중에 진행하기로 했습니다. 이번 실행 범위는 구현·자동 검사·Android 에뮬레이터 검증입니다. 아래 원래 완료 조건 중 실제 휴대폰 항목은 후속 미완료로 유지합니다.

**Codex v0.2 알고리즘을 모바일 내부 TypeScript 모듈로 이식하고, 고정 도로 데이터·도형·목표 거리로 원본과 일치하는 코스를 계산해 Android 앱 지도에서 확인한다.**

현재 지도·전경 위치·SQLite 저장 기반의 에뮬레이터 검증을 바탕으로, 다음 핵심 기능인 경로 계산을 검증하는 목표입니다. 사용자 표현의 v2.0은 저장소의 v0.2입니다.

### 작업 범위와 순서

1. **원본 비교 기준 확보:** 독립 소스 묶음과 v0.2 보관본의 출처를 대조하고, 고정 그래프·시작점·도형·목표 거리·탐색 옵션과 원본 결과를 보존합니다. 합성 그래프와 출처가 확인된 고정 OSM 표본을 구분합니다.
2. **계산 모듈 이식:** `src/modules/route-engine/`에 계산 코드를 이식합니다. 도형·점수·탐색 조건과 OSM 노드 ID·연결성을 보존하고 지도·네트워크·저장·화면과 분리합니다.
3. **앱 테스트 화면 연결:** 고정 데이터에서 도형·목표 거리를 선택하고 계산을 실행합니다. 추천 코스·거리·점수를 지도와 목록에 표시하며, 진행률·취소·오류·유효 후보 없음 상태를 확인할 수 있게 합니다. 화면은 핵심 기능 검증용입니다.
4. **회귀·Android 검증:** 원본 결과와 비교하고 Android에서 계산 시간·메모리·화면 반응·취소를 측정합니다. 실행 방식은 측정 결과에 맞춰 결정합니다.

### 후속 범위

주변 OSM API 조회·메모리 캐시는 후속 지도 중심 작업에서 구현했습니다. 4단계에는 지역 파일 영구 저장·오프라인 재사용·버전과 복원 검증이 남습니다. 실제 코스 저장·GPS 러닝 추적·러닝 기록·시뮬레이션·GPX는 5단계에서 진행합니다. 최종 서비스 기획·디자인은 이후 전달받아 반영합니다. CI/CD는 기존 실행 보류 상태를 유지합니다. 원래 알고리즘 구현은 [당시 실행 기록](../history/executed-plans/2026-09-27-1446-algorithm-port.md)에 보존합니다.

## 3단계 알고리즘 이식 순서

1. 모바일 루트 기준 `../running-art/exports/running-art-algorithm/`의 v0.2 엔진·명세·테스트·합성 그래프를 확보하고 `../running-art/versions/v0.2/` 보관본과 출처를 대조합니다.
2. 동일한 고정 입력과 `version: '0.2'`로 원본 결과를 확보합니다. 점수, 경로 연결·복귀, 총거리, 반복 도로, 크기 범위와 v0.1 기준 후보 보존을 회귀 기준으로 삼습니다.
3. 계산을 `src/modules/route-engine/`에 TypeScript로 이식하고 네트워크·지도·저장·UI와 분리합니다. v0.2에 포함된 도형과 점수 함수를 보존합니다.
4. 원본과 모바일 모듈을 비교한 뒤 Android에서 계산 시간·메모리·UI 응답성·진행률·취소를 검증합니다. 실행 방식은 측정 결과에 맞춰 정합니다.

위 순서로 이식·에뮬레이터 검증을 완료했으며 실제 결과는 [현재 상태](../handoff/status.md)에 기록했습니다.

## 작업 방식

1. 해당 단계의 결정·현황·완료 조건을 확인하고 범위와 검증을 계획합니다.
2. 이미 허용된 범위의 일반 구현은 불필요한 재승인 없이 진행합니다.
3. 실제 구현 직전에 실행 기록을 만듭니다. 계획만 논의하고 끝나면 만들지 않습니다.
4. 기능 단위로 구현하고 필요한 검증을 수행합니다.
5. 실제 결과·실패·미검증을 기록하고 현재 상태를 갱신합니다.

## 해당 단계에서 정할 항목
