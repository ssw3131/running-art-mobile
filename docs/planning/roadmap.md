# 단계별 개발 계획

현황은 [인수인계](../handoff/status.md), 실제 실행한 계획은 [실행 이력](../history/executed-plans/README.md)을 기준으로 봅니다.

현재 개발 목적은 **핵심 기능 테스트**입니다. 서비스 기획·디자인은 이후 사용자에게 전달받아 반영하며, 아래 단계는 기술 기능과 검증 순서입니다.

2026-09-27 사용자 결정: 알고리즘은 **Codex v0.2(사용자 표현 v2.0)** 소스를 기준으로 진행합니다. 루트 v0.3은 테스트 버전으로 이식 대상에서 제외합니다. 소스와 보존할 계산 기준은 [프로토타입 이식 기준](../architecture/prototype-migration.md)을 따릅니다.

CI/CD는 기능 개발 전 구축할 방향으로 계획했지만 사용자가 나중에 실행하기로 했습니다. 문서 정리나 새 세션 시작을 재개 지시로 해석하지 않습니다. 사용자가 선택한 다음 작업에 맞춰 진행합니다.

## 3단계 알고리즘 이식 순서

1. 모바일 루트 기준 `../running-art/exports/running-art-algorithm/`의 v0.2 엔진·명세·테스트·합성 그래프를 확보하고 `../running-art/versions/v0.2/` 보관본과 출처를 대조합니다.
2. 동일한 고정 입력과 `version: '0.2'`로 원본 결과를 확보합니다. 점수, 경로 연결·복귀, 총거리, 반복 도로, 크기 범위와 v0.1 기준 후보 보존을 회귀 기준으로 삼습니다.
3. 계산을 `src/modules/route-engine/`에 TypeScript로 이식하고 네트워크·지도·저장·UI와 분리합니다. v0.2에 포함된 도형과 점수 함수를 보존합니다.
4. 원본과 모바일 모듈을 비교한 뒤 Android에서 계산 시간·메모리·UI 응답성·진행률·취소를 검증합니다. 실행 방식은 측정 결과에 맞춰 정합니다.

이번 변경은 이식 계획 정정입니다. 실제 이식은 아직 시작하지 않았습니다.

## 작업 방식

1. 해당 단계의 결정·현황·완료 조건을 확인하고 범위와 검증을 계획합니다.
2. 이미 허용된 범위의 일반 구현은 불필요한 재승인 없이 진행합니다.
3. 실제 구현 직전에 실행 기록을 만듭니다. 계획만 논의하고 끝나면 만들지 않습니다.
4. 기능 단위로 구현하고 필요한 검증을 수행합니다.
5. 실제 결과·실패·미검증을 기록하고 현재 상태를 갱신합니다.

## 해당 단계에서 정할 항목

- 지도·데이터: MapTiler 키, 정적 호스트, 지역 분할·파일 스키마·캐시 크기.
- 알고리즘: 실기기 성능에 따른 연산 방식과 시간·메모리 기준.
- 러닝: GPS 누락·백그라운드·복원 정책과 저장 스키마.
- 배포: 정식 앱 ID·서명·스토어 계정·릴리스 조건·iOS 일정.

지금 임시 값으로 확정하거나 완료된 기능처럼 설명하지 않습니다. 로그인·과금·서비스 운영은 현재 개발 기반 범위 밖입니다.
