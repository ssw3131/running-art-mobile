## S0 — 서비스 구조를 먼저 연결

**작업**
- 기존 앱/자료를 유지하며 Expo Router의 서비스 레이아웃·5탭·상단 안내·상세 스택·팝업 책임을 정한다.

- 서비스 화면 미완성 탭은 해당 기존 기능의 실제 화면으로 연결하는 과도기 경계를 명시한다. 빈 시안만으로 탭 완료를 선언하지 않는다.
- 기존 딥링크/인증 callback, 활성 러닝 복원 배너·세션 유지와 탭 이동을 대조한다. 루트 복원 배너 문제는 기존 알려진 항목으로 별도 재현·처리한다.

**완료 조건**
- 5탭·상세→뒤로·시스템 뒤로·안내 메뉴가 일관되게 이동한다.
- 탭 전환으로 인증/러닝 서비스가 중복 구독·시작되지 않는다. 진행 중 러닝과 생성 입력이 유실되지 않는다.
- 기존 코스·러닝·소셜 callback·공유 경로·진단 진입을 확인한다. 단계 변경이 없는 저장 데이터는 내용 보존을 대조한다.
- Noto 기본·명시 Roboto, 작은 폭/큰 글씨·키보드·상태바/하단 제스처 영역을 점검한다.

**10-12 완료:** 서비스 5탭·실제 기존 기능/입력/GPS 유지·공통 UI·상세/콜백/공유/진단·작은 폭/큰 글씨/키보드를 검증했다. [구현 경계](../development/service-navigation.md)·[검증과 한계](../quality/service-s0-verification.md). **다음 첫 실행 범위는 S1**이며 필요한 동의/가입/홈 계약을 먼저 구체화한다. 상품·배지·장소 검색을 함께 추가하지 않는다.

- D-08 확정에 따라 실제 거리·추천 순위·경사만 표시한다. 유사도·예상 시간·난이도는 제외한다. 데이터 없는 혼잡도·AI 설명은 생성하지 않는다.
- 생성 작업 ID/상태를 정리해 S7 차감 연결 지점을 마련한다. 이번 단계의 표시와 실제 과금 시행을 구분한다.

**완료 조건**
- 동일 입력의 기존 엔진 정합성을 유지하며 서버 지연/한도/실패→기기, 취소/재계산, 0/소수 후보를 처리한다.
- 후보·상세·저장·러닝 준비가 같은 중심·도형·방향·경로를 사용한다.
- 입력 변경·지도 이동·결과 표시의 관계, 이미지 권한/대용량/윤곽 없음/취소, 직접 그리기 복원을 확인한다.
- 화면의 실제 거리·추천 순위·경사는 계산/저장 결과와 일치하며 근거 없는 유사도%·ETA·난이도를 표시하지 않는다. 길이 확대는 반경 2km/성능/보행 가능 결과까지 검증한다.

## S3 — 보관함과 데이터 관계

**작업**
- 저장 코스/러닝 기록 탭, 월별 목록·빈 상태·상세·이름/삭제·GPX·재도전 연결.
- 코스 사본과 러닝 세션 관계를 유지한다. 여러 종료 기록을 합치는 다일 도전은 D-06으로 제외한다.
- D-09 구현 계약은 명시적 저장 후 준비, 코스/기록 삭제 분리, 사본 재도전과 모든 종료 기록 표시다. 구매/저장 한도는 S7 후속이다.
- 고도 조회/그래프를 상세에 통합하고 오프라인 미조회와 기존 조회 가능 상태를 구분한다.

**완료 조건**
- 저장/재열기·재도전·코스 이름 변경/삭제 후 과거 러닝 사본 보존, 목록/상세/통계의 즉시 일치를 검증한다.
- 코스 삭제와 러닝 기록 삭제가 분리되고, 새 시도가 이전 기록을 덮지 않는다.
- 계정별 격리·오프라인 수정/재시도·서버 복원과 형식 이행을 확인한다. GPX의 좌표/이름·방향을 대조한다.
- 저장 용량 정책 적용 전 기존 자료를 잘라내거나 삭제하지 않는다.

## S4 — 실제 러닝과 도전

**작업**
- 지도/집중 정상·이탈·설정 화면을 기존 실제 GPS/네이티브 서비스에 연결한다.
- 준비·접근·진행·일시정지·복귀·중도 종료·완주 확인·계속 달리기의 상태와 화면을 정리한다.
- D-06 확정: 한 번의 러닝에서 한 바퀴 완주, 종료 후 새 도전이다. 기존 일시정지/프로세스 체크포인트 복원은 유지한다.
- D-10 구현 계약은 임시 터치 잠금과 세션에 저장하는 지도/집중·음성·백그라운드 옵션이다. OS 위치 권한과 구분한다.

**완료 조건**
- 실제 GPS/권한 거부·OFF·불량, 정방향/역방향·코스 밖 합류/이탈/복귀, 종료와 완주 판정 분기를 검증한다.
- 탭/설정/홈·강제 종료/복원·오프라인·화면 잠금에서도 기록의 중복/유실이 없다.
- 접근 거리와 완주 진행률, 실제 거리/활동 시간·페이스가 동일 기록에서 나온다.
- 에뮬레이터 주입과 실기기 야외·장시간/배터리 결과를 따로 보고한다. 후자가 남으면 “실서비스 러닝 전체 검증 완료”로 쓰지 않는다.

## S5 — 성취와 공유

**작업**
- 완주 화면·배지 수집·완주 횟수/누적/연속일을 D-11에 맞춰 구현한다. 10-14 사용자 결정으로 칼로리·체중 입력은 제외한다.
- 성취 ID/중복 방지·동기화·기존 기록 소급·삭제 후 처리 계약을 먼저 정한다.
- 9:16·4:5 이미지 카드 렌더링, 미리보기·저장·OS 공유를 연결한다. 1:1은 선택안이다.
- 기존 실제 러닝 링크/세 경로 토글·공유 중단을 유지하며 이미지와 링크의 공개 범위를 구분한다.

**완료 조건**
- 정상 종료·중도 종료·완주 계속·동기화 재시도에서 배지/완주 횟수가 잘못 증가하지 않는다.
- 홈/마이페이지/기록/카드의 수치가 일치하고, 자정/월 경계·계정 변경·삭제 후 집계가 정의대로 동작한다.
- 카드의 한글/영문·길어진 이름/시간·작은 수치·해상도를 확인하고 실제 파일 저장/공유 취소/실패·수신자 링크 접근·공유 중단을 검증한다.
- AI 이미지 호출을 암묵적으로 추가하지 않는다.

## S6 — 계정과 운영 화면

**작업**
- 기존 프로필·사진·연결 계정·로그아웃·탈퇴·설정·동기화 안내를 Figma 화면으로 옮긴다.
- 앱/지도 테마·음성·권한 안내, 통계/배지와 계정별 갱신을 통합한다.
- 소개/사용법/FAQ·공지 목록/상세·문의 폼을 구현한다. 실제 문의 저장/전달 채널·콘텐츠 공급/갱신 책임을 D-15로 정한다.
- 동의/약관 초안을 모바일 실제 수집·서버·상품 구조와 일치시키고 운영자·시행일 등 빈 항목을 확정한다. 문안 확정과 법적 검토는 별도 산출물이다.

**완료 조건**
- 프로필 저장 실패/사진 없음·변경/삭제·계정 전환, 테마 재시작·GPS 권한 설정 복귀를 확인한다.
- 탈퇴 확인/중단 재개·서버 삭제 결과·기기 비로그인 자료 보관·다른 계정 자동 업로드 방지를 검증한다.
- 문의가 실제 접수되고 실패/재전송/중복·선택 연락처를 처리한다. 공지 링크·목록 복귀·오프라인 콘텐츠 동작과 최신 문안을 확인한다.
- 예시 출시일·약관 placeholder·허위 공지/구매 이력을 제품에 노출하지 않는다.

## S7 — 변경 가능한 비즈니스 모델 적용

현재 상품 수치는 [10-11 사용자 표](../product/business-model.md)를 따른다. **가입 시 5회/한도 3개, 기본 1,900원/+10회/5개, 플러스 4,900원/+30회/15개, 확장 6,900원/+50회/30개.** B-01~B-07의 재구매·차감·환불 등 동작만 구체화한다.

**작업**
- S7a: 상품 카탈로그/정책 버전, 계정 권리, 생성 작업 원장, 거래/환불 원장 계약과 기존 사용자 이행안을 만든다.
- S7b: 생성 예약/확정/복구·저장 한도와 UI 현황을 연결한다. 공개 계산/기기 fallback/오프라인에도 일관된 처리 규칙을 정한다.
- S7c: Google Play 상품·결제→서버 검증→권리 지급·구매 완료/내역·재설치/다른 기기 복원·환불 처리를 구현한다.
- 상품 숫자는 카탈로그에서 읽고 공통 버튼/카드·생성 엔진에 하드코딩하지 않는다. 스토어 상품 정보와 표시 가격을 대조한다.
- 기존 구매자의 거래 당시 혜택/정책 버전을 보존하고 상품 변경이 과거 권리를 임의로 바꾸지 않게 한다.

**완료 조건**
- 결제 취소/보류/오류/응답 유실/중복 통지·앱 종료·동시 기기·복원·환불을 검증한다.
- 생성 0후보/취소/실패/서버→기기/재시도의 차감이 정한 기준과 일치하고 중복 차감/지급이 없다.
- 상품 수치를 한 곳에서 바꿔도 구매/홈 현황/보관함/마이페이지/완료·이력이 일관된다. 이전 거래 이력은 변하지 않는다.
- 기존 초과 자료의 열람·내보내기/신규 저장 정책과 삭제하지 않는 이행을 확인한다. 서버 운영 한도와 회원 상품 한도를 각각 검증한다.
- 상품/스토어/법적 요구사항은 구현 시점에 최신 공식 자료로 확인한다. 이 계획을 결제 검증 완료나 유료 판매 개시로 해석하지 않는다.

## S8 — 출시 범위 통합 검증

**작업:** 첫 출시 범위를 확정하고, 선택한 서비스 흐름 전체의 실제 자료·계정·동기화·공유·상품 상태를 연결 검증한다. 실기기 야외/장시간 잠금·배터리·저사양 성능·접근성·오프라인·스토리지 부족·복구, 네이버 공개 검수·스토어 아이콘/대표 이미지·약관/문의·권한 설명·운영 관측/복구를 확인한다.

**완료 조건:** 첫 가입부터 생성→저장→러닝→완주/중도 종료→재방문/공유·계정 전환/복원까지 출시 범위의 실제 성공/실패 경로가 검증된다. 알려진 한계와 후속 항목을 남기고 동일 앱의 업데이트·자료 보존을 확인한다. 배포·스토어 공개는 별도 실행으로 기록하며 CI/CD 보류를 자동 해제하지 않는다.

## 폴더·책임 배치

아래 중 새 디렉터리는 필요해지는 단계에서 만든다. 미구현 폴더를 지금 대량 생성하지 않는다.

| 위치 | 책임 |
| --- | --- |
| `src/app/` | Router 경로·레이아웃·탭/상세 진입·파라미터 검증. 업무 규칙을 쌓지 않음 |
| `src/features/home`, `onboarding`, `course-generation` (제안) | 해당 화면 합성·폼/선택 상태·상태별 표현, 기존 route-lab 기능 추출 |
| 기존 `features/account`, `courses`, `running`, `terrain` | 기존 업무 모듈을 호출하며 서비스 표현으로 점진 이관 |
| `features/records`, `achievements`, `sharing`, `support`, `billing` (제안) | 해당 기능의 합성 UI·입력/처리 상태. 재사용한다는 이유만으로 공통 폴더에 넣지 않음 |
| `src/components/ui`, `navigation` | 제어형 표현·접근성·상하단 바. DB/GPS/인증/결제 조회 금지 |
| `src/theme`, `assets/ui` | 색상·글꼴·간격·모서리·명시 폰트/원본 아이콘 |
| 기존 `src/modules/*` | 계산·도로·GPS·저장·계정·동기화·공유 계약 재사용 |
| 신규 `modules/onboarding`, `challenges`, `achievements`, `billing`, `support` (제안) | 정책/검증/저장·원격 계약. 확정한 단위에서만 추가 |
| 기존 `supabase/`, `server/`, `scripts/` 관련 영역 | 실제 저장소 구조를 따라 서버 권한·API·운영 도구 추가. 앱 화면에서 서버 비밀 사용 금지 |

의존은 app→features→공통 표현/theme, features→modules다. modules는 Router/화면에 의존하지 않는다. 카드·모달이라도 코스 저장/구매/권한 판단이 들어가면 기능 폴더에서 합성한다. 현재 프로필·러닝 파일을 한 번에 이동하지 않고 단위별 이관으로 회귀 범위를 줄인다.

## 자료 이행과 매 단위 종료 기준

1. **시작:** 현재 변경분·최신 상태를 확인하고 관련 Figma 노드와 D/B 항목만 대조한다. 실제 구현 시작 시 실행 계획 기록 스킬로 해당 단위 계획을 보존한다.
2. **계약:** 필요한 데이터/상태 전이를 먼저 정의한다. 새 도전·동의·성취·상품은 계정 소유권·삭제·오프라인·동기화/복원을 함께 다룬다. 새 DB/동기화 버전은 실제 필요 시 기존 v1/v2/v3 코스·현재 SQLite를 읽는 이행으로 추가한다.
3. **실행:** 재사용 모듈에 실제 데이터를 연결하고 로딩/빈/실패/취소/재시도/재진입을 구현한다. 승인된 정책만 동작으로 적용한다.
4. **검증:** 변경된 업무 규칙의 자동 검사·타입/린트와 해당 Android 화면 흐름, 관련 저장/동기화 회귀를 확인한다. 전체 빌드/실기기·서버 검증은 변경 영향에 맞게 선택한다.
5. **기록:** 화면 ID·완료 범위·검증·미검증·다음 단위, 정책 변경을 제품/상태/실행 기록에 반영한다. 기술 모듈 완료·서비스 화면 완료·실기기 검증·출시 준비를 각각 구분한다.

공통 UI를 다시 만드는 작업, 기존 계정/서버 기반 재개발, 과거 웹 프로젝트 복구, 미확정 AI·커뮤니티·CI/CD는 이번 계획의 자동 후속이 아니다.
