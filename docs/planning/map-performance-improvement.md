# 저장 코스 안내 지도 성능 개선 계획

**2026-10-05 사용자 검증 완료:** 건물 숨김 APK를 설치한 SM-S942N에서 사용자가 직접 검증을 마치고 성능 개선을 확인했다. 건물 표시 제거와 사용자 체감 개선 확인은 완료했으며 아래의 정량 FPS·다기기 비교 등 전체 측정 기준을 모두 통과한 것은 아니다. 추가 성능 변경은 이번 요청에 포함하지 않는다.

**2026-10-05 후속:** 사용자가 건물 면·윤곽·입체 표시 숨김만 먼저 실행하도록 요청했다. 현재 Streets v2의 두 건물 레이어를 확인해 모바일에 적용했고 타입/린트·관련 검사·APK 및 SM-S942N 자료 유지 설치를 완료했다. 이 제한된 실행은 아래 2단계의 건물 표시 실험에 해당한다. 이후 사용자 검증 결과는 위 후속을 따르며 전체 정량 측정 기준의 통과를 뜻하지 않는다. [구현/설치와 한계](../quality/map-buildings-20261005.md).

작성일: 2026-10-04. 상태: **사용자 결정으로 보류·실행 전**. 사용자 요청은 개선 계획 수립이며 이 문서는 앱 수정·APK 설치·성능 개선 완료를 뜻하지 않는다. 실제 구현을 시작할 때 프로젝트의 실행 계획 기록 규칙을 적용한다.

**2026-10-04 14:35 KST 사용자 후속:** 일정 수준 이상 확대해 지도가 상세해질 때, 실제 러닝 화면 수준의 확대율에서 느려진다고 추가 관찰했다. MapTiler 자체 문제 가능성을 제기했지만 원인은 미확정이다. 사용자가 “일단 기록만 해두고 나중에 개선”하기로 결정했으므로 추가 진단·앱 수정·기기 시험은 보류한다. 아래 계획은 후속 재개용으로 보존하며 자동으로 실행하지 않는다. 정확한 확대율 임계값과 지도 공급/스타일·MapLibre 렌더러·기기 영향의 구분은 재개 시 확인한다.

## 목표와 근거

**배경 지도와 코스 안내를 유지하면서 저장 코스 지도의 이동·확대·축소를 부드럽게 만든다.** 저장 좌표·거리·안내 판정·개인 자료를 보존한다. 현재 SM-S942N에서 안정적인 60fps 이상을 우선 목표로 하며, 가능한 120fps 동작을 불필요하게 제한하지 않는다.

[휴대폰 진단](../quality/map-performance-20261004.md)에서 저장 코스는 상세 화면 없이 직접 진입해도 지연됐고, 배경 OFF에서는 같은 경로가 약 8.34ms 프레임 간격으로 표시됐다. 배경 ON 복귀 때 지연이 재현됐다. 배경 표시 조건을 우선 조사할 근거이며 특정 레이어·Vulkan·네트워크 중 하나를 원인으로 확정한 것은 아니다.

기존 비교에는 지역·확대율 차이, 지도 재생성 때 zoom 16.5→16 변화, SurfaceFlinger 표본 누락·늦은 보고가 있었다. 두 손가락 축소 자동화는 실패했다. 이 한계를 먼저 보완하고 측정 가능한 변경을 선택한다.

## 1. 동일 조건의 측정 기준 만들기

현재 설치 APK와 소스 기준을 고정하고 원본 APK·서명·자료 보존 기준을 확보한다. 진단 조작은 내부 검증 범위로 두고 기존 단일 앱을 사용한다. 현재 계정 개발 변경과 섞이지 않도록 변경 파일을 제한한다.

- 같은 저장 코스의 같은 중심점에서 zoom 15, 16, 16.5, 17을 비교한다. 카메라 방향·기울기·지도 영역 크기·추적 상태를 같게 한다. 배경 전환 때 중심점과 확대율이 바뀌지 않게 한다.
- 일반 지도 컴포넌트와 안내 지도 컴포넌트에 같은 카메라 조건을 제공한다. 안내 지도는 배경만 표시, 배경+코스, 코스만 표시를 비교해 **배경 단독 병목과 배경·경로 조합의 병목**을 구분한다.
- 최초 진입/타일 로딩 구간과 로딩 완료 후 반복 조작을 나누어 측정한다. 앱 재시작과 캐시 초기화를 구분하며 사용자 자료·캐시를 임의 삭제하지 않는다.
- 지도 영역 안에서 같은 거리·시간의 좌우 이동과 두 손가락 확대/축소를 실행한다. 기존 UiAutomator의 런타임 오류를 해결하거나 동작이 검증된 다른 입력 수단을 사용한다. 실제 확대율 변화 확인 전에는 성공 처리하지 않는다.
- 측정 구간의 시작·끝, 실제 지도 Surface, 표시 프레임을 대응시킨다. 프레임 조회 누락은 다른 측정 수단으로 보완하고 0fps로 환산하지 않는다. 화면 녹화/프레임 추적의 부하도 구분한다. 제스처 중 정지 구간을 제외해 좋은 수치만 만드는 방식은 사용하지 않는다.
- 동일 조건을 최소 3회 반복하고 앱 재시작 뒤도 재현한다. CPU·메모리·열 상태와 지도 요청/로딩 여부는 비교 해석에 필요한 범위로 함께 기록한다.

산출물: 조건별 기준표와 재현 절차. 이 단계에서 다른 지역/다른 확대율의 결과를 동일 성능 비교로 사용하지 않는다.

## 2. 배경 지도 요소를 하나씩 분리

실제 스타일의 레이어 구성을 확인한 다음 **존재하는 요소만** 실험한다. 3D 건물이 병목이라는 가정을 구현 사실로 취급하지 않는다.

| 순서 | 실험 | 판단 |
| --- | --- | --- |
| 1 | 3D 건물/입체 표현이 있으면 해당 요소만 제외 | 유의하게 개선되면 러닝 안내용 2D 표현 후보로 삼는다. |
| 2 | POI·상점 등 부가 라벨/아이콘을 그룹별로 줄임 | 도로명·진행 방향·출발점 등 길 찾기에 필요한 정보가 유지되는지 확인한다. |
| 3 | 도로·지형·필수 지명 위주의 간소한 2D 배경과 비교 | 전체 스타일 복잡성의 영향을 확인한다. 외형 변경은 전후 화면으로 검토한다. |
| 4 | 충분히 로딩한 같은 타일을 반복 표시 | 네트워크·타일 준비 지연과 지속적인 렌더링 지연을 구분한다. |

각 실험은 하나의 조건만 바꾸고 기준본과 비교한다. 로고·출처 표시를 유지한다. 스타일을 얻는 과정에서 기존 API 키 직접 조회 요청이 자동 승인 검토에서 차단된 이력이 있으므로, 동일한 외부 요청을 다시 실행하려면 먼저 필요한 승인을 확보한다. 차단된 요청을 다른 도구로 우회하지 않는다. 승인 조건이 해결되기 전에는 확인하지 못한 레이어 구조를 전제로 구현하지 않는다.

산출물: 병목 요소와 효과가 입증된 최소 수정 후보. 배경을 영구히 끄는 방식은 목표 달성으로 보지 않는다.

## 3. 효과가 있는 수정부터 적용

가장 작은 변경으로 목표를 만족하는 후보를 채택한다. 레이어 조정으로 해결되면 그 변경에 집중하고, 차이가 없으면 실험 변경을 되돌려 원인 범위를 좁힌다.

배경 단독은 빠르고 코스/안내와 함께 표시할 때만 느리다면 지도 속성·레이어 갱신·카메라 추적 간섭을 우선 조사한다. 정지 중 불필요한 갱신, 재생 중 경로 전체의 재전송, 사용자의 지도 조작과 자동 추적 충돌은 실제 발생 여부를 측정해 수정한다. 원본 코스 좌표 축소는 현재 근거상 우선 수정안이 아니다.

배경 요소를 줄여도 문제가 남으면 Android 지도 표면 방식과 Vulkan/OpenGL을 각각 분리 비교한다. 이는 후순위다. [기존 검증](../quality/map-location-verification.md)에 OpenGL의 한글·영문 지명 누락 이력이 있으므로 속도만으로 전환하지 않는다. 영구 네이티브 설정 변경은 Expo 설정/plugin에 반영하며 생성된 `android/`만 직접 수정하지 않는다.

`GuidanceMap`은 모의 안내 외 실제 GPS 안내에서도 사용하므로 적용 범위와 회귀 영향을 확인한다. 모든 지도의 공통 설정을 바꾸려면 일반 지도·저장 상세·러닝 기록 지도까지 검증 범위를 넓힌다.

## 4. 동일 휴대폰에서 전후 검증

같은 ID·서명의 release APK로 기존 앱을 업데이트하며 이전 검증 APK를 복구 후보로 보존한다. 재설치 초기화나 별도 서비스 앱 생성은 하지 않는다. 기존 사용자의 자료는 검증용 내용 해시/개수 등 적절한 방법으로 전후 대조하고 좌표·인증 정보를 공유 문서에 노출하지 않는다.

- 같은 지역·같은 확대율·같은 조작에서 기준본과 수정본을 번갈아 최소 3쌍 비교한다. 지도 로딩 완료 후의 주 측정은 회당 20초 이상으로 한다.
- 시작 전·모의 재생 중·일시정지 후의 이동·확대/축소, 위치 추적 해제·재중앙 정렬, 배경/집중 모드 전환을 확인한다.
- 기존 문제 코스 외 다른 도심 지역과 단순 시험 지역을 확인한다. 원래 부드러운 지도에서 새로운 지연이 생기지 않아야 한다.
- 실제 GPS 안내의 경로/위치/복귀선 표시와 화면 전환을 회귀 확인한다. 모의 검증 결과를 야외 GPS·배터리 검증 완료로 확대 해석하지 않는다.
- 지도 표시와 관련한 기존 자동 검사, 타입·린트, Android release 빌드를 수행한다. 네이티브 렌더러를 바꾸면 에뮬레이터와 휴대폰에서 한글·영문 지명·선·마커·앱 복귀도 확인한다. 시각 성능은 자동 로직 검사만으로 통과 처리하지 않는다.

## 완료 기준

아래 수치는 측정 전 정한 목표이며 현재 달성한 결과가 아니다.

1. 배경 지도 ON, 검증 대상 확대율에서 이동·확대·축소가 지속적으로 부드럽고 실제 조작 구간의 표시 속도가 60fps 이상을 유지한다. 평균뿐 아니라 프레임 간격 P95 33.3ms 이하를 함께 확인한다. 표시 타이밍의 작은 측정 오차는 원본과 함께 설명한다.
2. 타일 로딩 완료 후 동일 제스처에서 100ms 이상의 반복적인 지도 멈춤이 재현되지 않는다. 조회 누락이나 측정 도구 실패는 통과 근거로 사용하지 않는다.
3. 세 쌍의 전후 비교 모두 개선 방향이 일치하고, 사용자가 실제 손가락 조작으로도 개선을 확인한다. 기대만큼 개선되지 않으면 부분 완료로 보고한다.
4. 도로·필수 지명·코스 선·현재 위치·안내 정보·출처가 유지되고 기존 코스/러닝/계정 자료가 보존된다.
5. 진단 도우미를 제거하고 불필요한 서비스가 남지 않은 상태에서 APK 기준, 수치, 변경점, 미검증을 인수인계한다.

최종 산출물은 검증된 최소 코드 변경, 동일 ID/서명의 APK, 전후 성능·화면 비교 보고서다. 일정은 1단계 측정으로 병목을 분리한 뒤 추정한다.
