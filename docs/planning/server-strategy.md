## RunPen 서비스 전환 기준 — 2026-10-03

서비스명은 **RunPen**, 기술 프로젝트명은 Running Art다. [제품 기획](../product/overview.md)의 Figma UI를 우선하며 prototype은 보조, 보관함은 과거 시안이다. 현재 앱을 실서비스로 이어가고 개발용·배포용 앱을 따로 만들지 않는다. **서버 환경 분리 여부는 후속 결정**이며 단일 앱을 단일 서버 환경 확정으로 해석하지 않는다. 기존 Supabase·R2 자원의 이름이나 `.dev` 주소만으로 새 자원을 만들거나 운영 전환 완료로 표시하지 않는다.

소셜 로그인은 카카오·네이버·Google을 목표로 하고 이메일 로그인·비밀번호 찾기는 현재 범위에서 제외한다. Google은 휴대폰 검증 완료, 개인 코스·러닝 소유권·RLS·비공개 Storage·동기화는 별도 진행 중이다. 구현 파일이 생겼다는 사실과 실제 마이그레이션 적용·권한 검증·기기 복원 완료를 구분한다. 위 날짜별 회원 상태는 해당 검증 시점의 기록이다.

현재 서비스 목표는 개인 코스·러닝·배지/통계·프로필·탈퇴·외부 공유·서비스 안내다. 문의/공지의 관리 방법, 탈퇴 시 자료 처리, 공유 시 위치 노출, 약관 운영은 후속 설계이며 공개 API·스키마를 이번 문서에서 확정하지 않는다. 커뮤니티 피드·댓글·좋아요는 후속 확장이다. Figma의 공유 이미지를 만들기 위해 공개 게시물 서버를 선행 조건으로 요구하지 않는다.

과금은 [사용자 검토안](../product/overview.md#과금-정책--검토-중-미확정)이며 결제·횟수 차감·저장 제한을 선구현하지 않는다. 출시 필수 범위와 과금 도입 시점은 미확정이다. 이번 변경은 문서만 수정하며 클라우드 설정·DB·키·배포는 변경하지 않는다.

### 로컬 검증이 먼저인 이유

지역 분할별 파일 크기·파일 수, 도로 경계 연결, 휴대폰의 다운로드·압축 해제 시간·메모리와 엔진 입력 적합성을 확인해야 저장·전송·캐시 구성을 정할 수 있다. 검증 전에 배포 형식과 서버 규모를 고정하면 데이터를 다시 가공하거나 앱·배포를 함께 고쳐야 할 수 있다.

### 첫 단계의 산출물과 종료 조건

1. 날짜·해시·출처가 고정된 새 OSM 원본과 독립 가공 스크립트. 모바일 저장소만으로 재현하며 두 테스트 프로젝트의 서버·가공 파일을 필수 입력으로 삼지 않는다.
2. 서울·부산·지역 경계의 표본 파일과 공급 형식 초안. 노드·way ID·연결·필수 속성, 좌표 순서, 범위, 버전·크기·해시를 정의한다.
3. 분할 전후 연결성과 현재 엔진 입력·결과의 비교 증거. 경계를 가로지르는 도로, 누락·중복·손상·버전 불일치를 검증한다.
4. 파일 크기·개수, 로컬 제공 환경의 전송 시간, 휴대폰의 해제·입력 처리 시간·메모리 측정. 로컬 전송 결과를 운영 CDN의 다운로드 성능으로 보고하지 않는다. 기기 측정을 못하면 해당 조건은 미검증으로 남긴다.
5. 측정 결과에 따른 지역 분할·압축·매니페스트·엔진 어댑터의 공급 형식과 근거. 이 산출물을 바탕으로 4-2 저장소·전송·배포 구성을 결정한다.

4-1은 로컬 파일과 필요 시 테스트용 로컬 제공으로 검증할 수 있다. 운영 클라우드 구축·앱의 운영 주소 변경은 4-2와 4-3에서 진행한다. 회원·커뮤니티 서버 설계는 별도로 검토할 수 있으며 4-1의 선행 조건이 아니다.

## 확정된 요구사항과 설계 범위

- `../running-art/`와 `../running-art2-google-/`는 각각 Codex·Gemini 테스트 프로젝트다. 기존 서버·DB·배포 주소·자격 증명을 모바일 운영에 공유하지 않는다. 참고 소스와 회귀 표본의 출처는 보존한다.
- Android 우선, 전국 사용자 위치 주변의 코스를 지원한다. v0.2 코스 계산과 GPS 기록·우선 저장은 휴대폰에서 수행한다.
- 서비스 화면은 RunPen Figma UI 기준이다. 로그인·기기 간 동기화·개인 기록·외부 공유를 목표로 하고 커뮤니티는 후속 확장으로 유지한다. 세부 미정 정책은 제품 기획에서 관리한다.
- 작은 비용으로 시작하고 실제 지도 요청·저장·전송·DB 사용량에 따라 확장한다. 사용자에게 무료로 제공하는 것과 인프라 무료 요금제는 별개다.
- 결제·구독·회원 등급별 기능·코스 생성 횟수 제한은 후속 계획이다. 지금 상품 테이블, 사용권 발급, 횟수 차감 API, 결제 SDK, 온라인 생성 승인 절차를 추가하지 않는다.
- 기존 Sites 서버 복구·배포는 모바일의 다음 작업에서 제외한다. 이번 문서 정리는 CI/CD 재개나 클라우드 자원 생성·과금 동의를 의미하지 않는다.

| 설치 APK | 전국 공급·GPS·기존 성능 변경을 포함한 10월 3일 Google 로그인 APK, 해시·기존 자료 보존 확인 | 전국 다른 지역·저사양·장시간 야외 검증 등 남은 범위는 현재 상태 기준 |

현재 소스와 휴대폰 APK는 R2 개발용 전국 채널을 사용한다. 기존 API·대체 연결은 제거했으며 새 공급의 전체 해시·헤더·조건부 포인터와 공개/오프라인 입력을 대조했다. 후속 휴대폰에서는 강남 계산·기존 코스 재생을 확인했고 다른 지역·장시간 검증 등은 남아 있다. 전환 전 서버 수정·실패 증거는 과거 기록으로 보존한다. [전국 검증](../quality/national-roads-verification.md)·[휴대폰 후속](../quality/phone-performance-20261002.md)·[기존 휴대폰 캐시 검증](../quality/road-cache-verification.md).

## 권장 서버 구성

아래 서비스 조합은 저비용 시작을 위한 설계 기준안이다. 2026-10-01 사용자 Cloudflare·Supabase 계정과 `running-art` R2 버킷(APAC·Standard)을 확인했고, 이후 `running-art-mobile-dev` Supabase 프로젝트(서울·Free)와 Google 로그인 연결을 확인했다. 사용자 도메인·운영 CDN은 후속이며 서버 환경 분리·출시 요금제는 아직 확정하지 않았다.

| 역할 | 권장 구성 | 이유 |
| --- | --- | --- |
| 로그인과 회원 정보 | 독립 Supabase Auth·Postgres | 인증과 사용자 관계 데이터를 관리형 서비스에 모음 |
| 코스·러닝·커뮤니티 정보 | 같은 Supabase DB | 소유자·공개 상태·게시글·댓글 등의 관계와 접근 정책 관리 |
| 개인 GPS 파일·사진 | Supabase Storage | 개인 파일과 공유 파일을 분리하고 사용자별 접근 정책 적용 |
| 검증이 필요한 서버 작업 | Supabase 서버 함수 또는 DB 함수 | 발행·탈퇴·관리 작업을 서버 권한으로 수행 |
| 공용 도로 파일 | 독립 Cloudflare R2·자체 도메인·CDN | 공통 파일을 배포하고 사용자 기기에서 재사용 |
| OSM 가공 | 재현 가능한 별도 실행 작업 | 사용자 요청과 분리해 자료 생성·검증. 초기 수동 실행 후 자동화 별도 결정 |
| 배경 지도 | MapTiler | 기존 네이티브 지도 유지, 계산용 도로 파일과 분리 |

초기에는 회원·커뮤니티 API를 위해 별도 상시 VM이나 Cloudflare Workers를 추가하지 않는 구성을 권한다. Supabase가 제공하는 API와 서버 함수로 처리할 수 없는 요구가 확인되면 확장한다. 도로 자료 가공은 일반 API 요청 안에서 실행하지 않는다.

서버 설정·DB 마이그레이션·가공 스크립트는 모바일 저장소에서 함께 관리한다. `scripts/road-data/`의 가공·검증·배포 도구와 `infra/road-data/`의 설정 예시, 개발용 R2 전국 배포는 구현·검증했다. Supabase Auth 앱 연결은 구현했고 `supabase/` 마이그레이션과 회원별 자료 테이블·RLS·동기화는 별도 진행 중이다. 실제 적용·검증 완료는 해당 실행 결과로 확인한다. 원본 데이터·생성 파일·실제 키는 소스 저장소와 분리한다.

## 도로 파일 공급과 앱 연결

목표 흐름은 **한국 OSM 원본 → 보행 도로 추출·지역 분할 → 검증 → 버전별 파일 배포 → 앱 다운로드·영구 저장 → 휴대폰 계산**이다. Geofabrik은 한국 PBF와 갱신 자료를 제공한다. 공개 Overpass를 정식 앱의 필수 실시간 공급자로 유지하지 않는다. [한국 자료](https://download.geofabrik.de/asia/south-korea.html), [갱신 방식](https://download.geofabrik.de/technical.html), [Overpass 운영 안내](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)

1. 날짜·해시가 고정된 원본으로 서울·부산·지역 경계 표본부터 생성한다. 지역 크기와 압축 형식은 파일 크기·해제 시간·휴대폰 메모리를 측정한 뒤 정한다.
2. OSM 노드·way ID, 연결 관계와 보행 속성을 보존한다. 경계를 넘는 도로와 도로 구간만 영역을 가로지르는 경우도 누락하지 않는다. 이웃 파일은 같은 릴리스의 OSM ID로 합치며 좌표 근접만으로 연결하지 않는다.
3. 매니페스트에는 자료 릴리스, 형식 버전, 데이터 기준 시각, 파일 범위·주소·크기·해시를 둔다. 정확한 스키마는 표본 검증 후 고정한다.
4. 앱은 계산 영역을 덮는 파일을 선택하고 검증 완료 후 원자적으로 저장한다. 다운로드 취소·중단·손상·저장 공간 부족을 구분하고, 사용 중인 파일은 용량 정리에서 보호한다.
5. 한 번의 계산에는 같은 자료 릴리스만 사용한다. 업데이트 실패 시 마지막 정상 자료를 유지하고, 필요한 범위가 없는 오프라인 상태는 명확히 안내한다.
6. 공급 어댑터가 현 엔진 입력으로 변환한다. 동일 원본·동일 범위를 분할 전후 비교해 ID·연결·계산 결과를 검증한다. 최신 OSM 결과가 오래된 서울 표본과 동일하다고 가정하지 않는다.
7. 지역 표본 검증 후 전국 자료로 확장한다. 초기 갱신 주기는 주 1회를 제안하되 원본 최신성·가공 비용 측정 후 정한다. 새 릴리스 업로드·검증을 마친 뒤 참조 매니페스트를 바꾸고 이전 릴리스로 복구할 수 있게 한다.

독립 공급이 준비되면 기존 기본 API와 환경 변수 설정을 새 계약에 맞춰 변경한다. 운영 공급 설정이 빠졌을 때 기존 사이트로 자동 연결하지 않는다. 빈 응답이나 고정 표본을 주변 도로 조회 성공으로 대신하지 않는다.

도로 파일의 오프라인 재사용은 배경 지도의 오프라인 표시와 별개다. 조회 지연 개선과 v0.2 계산 시간 개선도 별도로 측정한다. 배포 자료에는 OSM 출처·ODbL 안내를 포함한다. [OSM 라이선스](https://www.openstreetmap.org/copyright)

## 회원 데이터와 공개 범위

구체적인 테이블·API 계약은 구현 단계에서 정하되 아래 책임과 데이터 경계는 유지한다.

| 데이터 | 기본 접근 | 저장 방향 |
| --- | --- | --- |
| 회원·프로필 | 계정 정보는 본인, 공개 프로필은 선택한 항목만 | Auth와 프로필 정보 분리 |
| 개인 코스·러닝 | 본인 | 요약·소유 관계는 DB, 좌표 파일은 비공개 저장소 |
| 공개 코스·게시물 | 사용자가 명시적으로 공개한 범위 | 개인 원본과 별도 공개 자료 및 발행 상태 |
| 댓글·좋아요·저장 | 게시물 공개 범위와 작성자 권한에 따름 | DB에서 중복·소유 관계 검증 |
| 신고·차단·관리 기록 | 신고자에게 필요한 범위와 관리자 | 서버에서 관리 권한 확인 |

위치는 기본적으로 개인 기록에 속한다. 공개 전에 경로·출발/도착 위치를 확인할 수 있도록 설계하며 공개용 파일에 개인 원본을 그대로 노출하지 않는다. 게시물 공개 취소와 개인 기록 삭제는 다른 동작으로 다룬다.

DB와 Storage 접근은 서버 정책으로 검사한다. 앱의 화면 숨김만으로 권한을 통제하지 않고, 서버 관리 키를 앱에 넣지 않는다. 공개 도로 저장소에는 개인 GPS나 사진을 넣지 않는다. [DB 접근 정책](https://supabase.com/docs/guides/database/postgres/row-level-security), [파일 접근 정책](https://supabase.com/docs/guides/storage/security/access-control)

동기화는 **휴대폰 저장 → 전송 대기 → 서버 확인 → 다른 기기 복원**을 기준으로 한다. 안정적인 사용자·자료 ID, 재전송 중복 방지, 변경 버전, 삭제 전달, 충돌 처리를 설계한다. GPS는 휴대폰에 먼저 기록하고 묶음으로 전송하며 통신 실패가 기록 손실로 이어지지 않게 한다. 회원 탈퇴·자료 삭제·복구 범위도 실제 데이터 모델과 함께 검증한다.

커뮤니티는 후속 확장으로 유지한다. 코스 피드·공개/비공개·댓글·좋아요·저장과 신고·차단·관리 기능은 그때 화면·정책을 확정한다. 현재 UI의 완주 이미지 외부 공유와 커뮤니티 게시물 발행을 같은 범위로 합치지 않는다.

## 비용과 운영

개발은 로컬 환경과 서비스 무료 구간을 활용하되 무료 운영을 보장하지 않는다. 실제 사용자 자료를 보관하는 출시 단계에서는 백업·복구·비활성 정지 조건을 보고 요금제를 정한다. 2026-10-03 기준 서버의 개발·운영 환경 분리 여부는 후속 결정이며 기존의 무조건 분리 전제는 적용하지 않는다. 환경을 어떻게 구성하든 공개 클라이언트 키와 서버 관리 권한은 분리하고 비밀 값은 앱·공개 문서에 넣지 않는다. 유료 운영 프로젝트를 불필요하게 여러 개 만들지 않는다.

2026-09-30 공식 안내 확인값은 Supabase Pro 월 $25부터, MapTiler Flex 월 $30, R2 Standard 월 저장 10GB·읽기 1천만 회 등의 무료 구간이다. Supabase 운영 프로젝트 1개와 MapTiler Flex의 기본료 합계 $55는 전체 견적이나 상한이 아니다. 초과 사용량·도로 가공 실행·파일 백업·도메인·메일·세금은 별도다. [Supabase 요금](https://supabase.com/pricing), [MapTiler 요금](https://www.maptiler.com/cloud/pricing/), [R2 요금](https://developers.cloudflare.com/r2/pricing/)

현재 MapLibre 연동은 지도 요청 수 기준으로 비용을 측정해야 한다. 실기기에서 탐색·러닝당 지도 요청량을 확인하고 경고 기준을 정한다. 지출 상한에 도달하면 지도 API가 중단될 수 있으므로 비용 제한과 서비스 가용성의 영향을 함께 정한다. [사용량 산정](https://docs.maptiler.com/guides/account/sessions-vs-requests/), [비용 제한](https://docs.maptiler.com/guides/account/controlling-expenses/)

피드는 페이지 단위로 읽고 사진은 압축·미리보기를 활용한다. 좌표 파일과 목록용 요약을 분리하고 같은 도로 파일의 반복 다운로드를 줄인다. 서버 오류·응답시간·파일 전송량·DB 사용량을 관측하되 원본 GPS를 진단 로그에 남기지 않는다.

DB와 파일은 각각 백업·복구를 확인한다. Supabase DB 백업만으로 Storage 파일까지 복구되는 것으로 보지 않는다. 메일 인증을 선택하면 실제 사용자에게 발송할 SMTP를 별도로 준비한다. [백업 범위](https://supabase.com/docs/guides/platform/backups), [메일 설정](https://supabase.com/docs/guides/auth/auth-smtp)

첫 구현은 **4-1 로컬 도로 표본·공급 형식 검증**으로 진행했고, 사용자 휴대폰 측정 보류 후 4-2 배포 준비를 마쳤다. 이후 서버 보류 결정에 따라 4-3 중 영구 캐시와 5단계 로컬 코스 저장을 먼저 구현했다. 후속 사용자 요청으로 SM-S942N 측정·형식 결정을 마쳐 4-1을 완료했고 2026-10-01 개발용 R2 실제 배포를 마쳤다. 후속 일반 계산 연결·휴대폰 영구 캐시 검증도 완료했고 후속 4-4에서 전국 채널로 확장했다. 실제 휴대폰은 전국 도로·러닝·성능 변경을 포함한 2026-10-03 Google 로그인 APK로 업데이트했다. 회원·커뮤니티 전체나 유료화는 후속 범위다. 실제 전국 이전 버전 복구는 4-4에서 완료했고 운영 단계에서는 사용자 도메인·CDN을 검증한다.

독립화 완료 시 모바일만 내려받아 빌드·테스트할 수 있어야 한다. 형제 프로젝트 서버를 끄고 기존 도메인을 차단한 상태에서 빈 캐시·신규 설치 기준으로 검증하며, 런타임뿐 아니라 가공·배포 스크립트도 형제 폴더에 의존하지 않아야 한다. 알고리즘 참조 원본과 출처 기록은 이 조건과 구분한다.

## 유료화 후속 계획

기존 초기 무료 제공 방침은 결정 이력으로 보존한다. 2026-10-03 사용자가 무료 최초 생성 5회·매일 충전·코스 저장 3개, 월 2,900원 무제한 생성/저장, 도형 제한 없음, 추가 생성 이용권 검토안을 제공했다. **모두 미확정**이며 연간 요금·매일 충전량·누적·갱신 시점·실패/취소 차감·구독 종료 후 초과 저장 처리·도입 여부와 시점은 정하지 않았다. 원본과 상세는 [제품 기획](../product/overview.md#과금-정책--검토-중-미확정)을 기준으로 한다.

현재는 회원·자료 ID와 서버 책임을 명확히 하는 데 그친다. 별도 상품·구독·사용권·차감 시스템을 선구현하거나 유료화 때문에 코스 계산을 서버로 이전하지 않는다. 후속 설계에서는 서버의 결제 검증, 여러 기기의 이용량, 오프라인 동작과 로컬 계산의 변조 방지 한계를 함께 검토한다. 이 항목은 독립 서버 기반의 완료 조건에 포함하지 않는다.
