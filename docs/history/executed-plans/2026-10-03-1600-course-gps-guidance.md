## 목표와 범위

**위치·거리·도형 설정 → 후보 비교 → 코스 저장 → 실제 GPS 러닝 → 기록 확인**을 하나의 흐름으로 연결한다.

- 기존 화면을 연결·정리하고 현재 계산·저장·GPS 기록·모의 안내·동기화 기능을 재사용한다.
- 출발점 부근에서 정방향으로 시작한다. 중간 합류·역방향 출발은 후속으로 둔다.
- 폰 없이 구현·자동 검사·에뮬레이터 검증·설치용 APK 준비까지 진행한다. 휴대폰 설치와 야외 검증은 별도 후속으로 구분한다.
- 전체 5개 탭 전환, 장소 검색·직접 그리기·이미지 입력, 배지·칼로리·공유·과금은 이번 범위에서 제외한다.

## 1단계 — 코스 생성부터 러닝 시작까지

- 기존 계산 화면을 조건 설정 → 후보 비교 → 선택·저장 순서로 정리한다. 개발용 측정·검증 정보는 접힌 별도 영역으로 이동한다.
- 위치는 현재 위치 또는 지도 중심 선택, 거리는 기존 3·5·7km, 도형은 기존 9종을 유지한다. v0.2 엔진과 전국 도로 공급·캐시를 사용한다.
- 후보 선택 시 지도 경로와 도형 원형을 함께 표시한다. 실제 거리와 기존 계산 점수를 제공하며, 종합 점수를 유사도 백분율로 바꾸지 않는다.
- 지도에서 선택한 계산 중심과 **실제 코스 출발점**을 구분해 표시한다.
- 후보를 먼저 저장한 뒤 저장된 코스 ID로 러닝 준비 화면에 진입한다. 중복 저장은 기존 처리 방식을 유지한다.
- 저장 코스 상세에서도 같은 러닝 준비 화면으로 연결한다. 가상 테스트 코스는 실제 GPS 러닝 시작을 허용하지 않는다.
- 계산 취소·조건 변경·후보 없음·저장 실패를 처리하고, 진행 중인 러닝이 있으면 기존 기록의 재개·종료로 안내한다.

## 2단계 — 실제 GPS 안내와 기록

- 기존 GPS 수신을 기록 저장과 안내 엔진에 함께 전달한다. 안내는 정지 상태의 수신도 받아 완주·복귀의 지속 시간을 판단하고, 기록 거리는 기존 흔들림 필터로 계산한다.
- 출발 준비에서는 위치 권한·GPS 상태를 확인한다. 초기 기준은 **정확도 30m 이내, 수신 후 5초 이내, 코스 시작점과 25m 이내**로 정한다. 조건 충족 후 사용자가 시작하며, 대기 시간은 러닝 시간에 포함하지 않는다.
- 지도·집중 모드, 진행률·남은 거리, 방향·이탈·지나온 길 복귀, 한국어 음성·진동을 실제 위치에 연결한다.
- 실제 GPS는 기존 위치 백그라운드 서비스를 사용한다. 음성·진동 실행부를 모의 서비스와 분리하고 화면이 없어도 안내하도록 연결한다. 모의 주행과 실제 러닝은 동시에 실행하지 않는다.
- 이탈·복귀·완주 수치는 기존 모의 기준을 초기값으로 사용한다. 위치 불량·수신 공백에서는 판정을 보류하고, 끊긴 이동을 직선 거리로 더하지 않는다.
- 일시정지·재개 시 활동 시간과 위치 수신 시각을 구분한다. 앱 강제 종료 후에는 마지막 저장 상태를 복원하고 사용자가 재개한다. 재개 위치가 벗어나 있으면 진행률을 건너뛰지 않고 복귀를 안내한다.
- **완주 감지 → 기록 일시정지 → 종료·저장 또는 계속 달리기**로 처리한다. 계속 달리기를 선택하면 완주 감지를 해제하고, 같은 위치에서 즉시 다시 멈추지 않도록 다음 정상 이동 후 재평가한다.
- 중도 종료와 코스 완주를 기록에서 구분한다. 거리·시간·페이스는 실제 GPS 기록 기준으로 표시한다.

## 자료 구조와 호환성

- 러닝 시작 인터페이스에 선택적 코스 ID를 추가해 기존 자유 러닝을 유지한다.
- SQLite v5 마이그레이션으로 러닝에 코스 ID·시작 당시 이름/경로 사본·완주 결과·안내 복원 상태를 추가한다. GPS 기록과 안내 상태는 함께 저장하고, 저장 실패 시 추적을 중단해 마지막 정상 자료를 보존한다.
- 안내 엔진에 상태 저장·복원 기능을 추가한다. 진행 위치·이탈 복귀 지점·안내 중복 방지·완주 확인 상태를 복원한다.
- 코스를 나중에 변경하거나 삭제해도 과거 러닝의 코스 정보와 궤적은 유지한다.
- 코스 연결 러닝은 버전이 명시된 동기화 파일에 좌표·코스 사본·완주 결과를 담는다. 기존 좌표 배열 형식도 계속 읽고 복원한다. 기존 비공개 Storage·소유권·RLS를 유지하며, 진행 중 러닝은 기기에 보존하고 종료한 기록만 동기화한다.
- 기존 앱 ID·서명·사용자 자료를 유지한다. 현재 작업 폴더의 미커밋 안내 구현도 보존한다.

구현 시작·종료 시 프로젝트의 실행 계획 기록 절차를 따르고, 현재 상태·사용법·검증 결과를 갱신한다. 지금은 계획만 정리하며 파일·앱·서버는 변경하지 않는다.

## 실행 결과

- 기존 코스 계산 화면을 코스 만들기·조건/후보/저장 순서로 정리하고 기본 실제 도로·개발 진단 접기·계산 중심/실제 출발점 구분을 적용했다. 저장 직후와 상세에서 같은 저장 코스 ID로 러닝 준비에 진입한다.
- `CourseRunPreparation`·`LiveGuidancePanel`을 기존 러닝 화면에 연결했다. 최신 위치·정확도·출발 거리 확인, 지도/집중·방향/복귀·음성/화면 꺼짐 설정, 완주 확인/계속 달리기와 코스별 결과를 제공한다.
- 기존 위치 콜백을 기록과 안내에 함께 전달한다. 정지 좌표는 안내에 사용하고 거리는 기존 흔들림/공백 필터로 계산한다. 체크포인트와 GPS를 한 트랜잭션에 저장한 후 효과를 실행하며 중단 재개에서 경로를 건너뛰지 않는다.
- SQLite v5에 러닝별 코스 사본·이름·진행/완주 결과·안내 복원/설정을 추가했다. 코스 연결 종료 기록의 동기화 파일 v2와 기존 좌표 배열을 모두 읽고, 원래 코스 삭제 후에도 과거 러닝의 이름/경로를 보존한다. 서버 테이블·RLS·비공개 버킷은 변경하지 않았다.
- Android `GuidanceFeedback.kt`로 실제 GPS 세션의 오프라인 한국어 TTS·진동을 연결했다. 실제 GPS에는 기존 Expo Location foreground service를 사용하며 모의 서비스와 동시에 실행하지 않는다.
- 실행 중 발견한 준비 화면 권한 재요청 반복과 오프라인 네트워크 위치 동의창을 수정했다. 이미 허용된 권한을 먼저 읽고 중복 위치 요청을 억제하며 시스템 네트워크 위치 동의창 없이 GPS를 확인한다.
- 기존 변경과 모의 안내 기능을 유지했다. 이번 작업에서 휴대폰 설치·조작·야외 테스트 또는 클라우드 변경/배포를 하지 않았다. 기존 모의 서비스의 휴대폰 `heartbeat_timeout` 문제를 해결한 것으로 표시하지 않는다.
