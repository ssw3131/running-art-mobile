# RunPen 러닝 안내 1차 시험 개발 목표

## 1. 이번에 달성할 목표

**저장한 코스를 모의 위치로 따라가며, 방향 안내 → 이탈 감지 → 지나온 길로 복귀 → 완주 확인까지 체험할 수 있도록 만든다. 화면을 꺼도 모의 주행과 한국어 음성·진동 안내가 이어져야 한다.**

사용자 선택에 따라 다음 범위로 확정한다.

- 현재 앱 안에 시험 기능을 추가한다. 실제 GPS 연결은 다음 단계다.
- 첨부 이미지의 지도·정상 집중·이탈 집중·설정·완주 결과 화면을 구현한다.
- 자동 시나리오와 수동 상황 조작 버튼을 함께 제공한다.
- 자동 검사·Android 에뮬레이터 검증·독립 실행 APK 준비까지 완료한다. 휴대폰 설치는 후속이다.
- 배지 지급·칼로리·공유 이미지·실제 러닝 기록 저장은 후속으로 둔다.

## 2. 화면과 사용자 흐름

진입은 **저장 코스 상세 → ‘러닝 안내 시험’ → 시나리오 선택 → 시작**으로 한다. 저장 코스가 없어도 사용할 수 있도록 앱에 시험 코스를 제공한다.

모든 화면과 잠금 화면 알림에 **‘모의 주행’**을 표시한다.

| 화면 | 구현 목표 |
|---|---|
| 지도 모드 | 선택 코스·가상 현재 위치·이동 궤적·다음 방향을 표시한다. 이동 거리·남은 거리·모의 러닝 시간·평균 페이스를 보여준다. 지도 이동 후 현재 위치로 돌아오는 버튼을 제공한다. |
| 집중 모드·정상 | 첨부 이미지의 초록 배경과 큰 방향 화살표를 따른다. ‘약 50m 앞에서 좌회전’처럼 방향과 거리를 크게 표시한다. |
| 집중 모드·이탈 | 주황 배경·이탈 문구·복귀 방향·되돌아갈 거리를 표시한다. 복귀가 확인되면 정상 화면으로 돌아간다. |
| 러닝 설정 | 지도/집중 모드, 음성 켜기/끄기, ‘화면 꺼져도 안내’를 제공한다. 설정을 여는 동안 모의 주행은 계속하며 별도 일시정지가 가능하다. |
| 완주 결과 | 완주 감지 후 주행을 멈추고 ‘완주 결과 보기’를 제공한다. 결과에는 모의 이동 거리·시간·평균 페이스를 표시하고 다시 시험하기·코스 상세로 돌아가기를 제공한다. |

- 초기 설정은 **지도 모드·음성 켜짐·화면 꺼져도 안내 켜짐**이다. 설정은 이번 시험 세션 안에서 유지한다.
- 중도 종료는 확인 후 종료하며 완주와 구분한다. ‘저장하고 종료’ 대신 **‘시험 종료’**로 표시한다.
- 지도 배경은 기존 MapTiler 연결을 사용한다. 연결이 없거나 실패해도 경로·가상 위치·안내는 계속 표시한다.
- 색상 외에도 문구와 아이콘으로 정상·이탈을 구분한다. 위치 판단이 어려우면 별도의 ‘위치 확인 중’ 상태를 표시한다.

## 3. 안내와 모의 주행의 상세 기준

### 코스 진행·방향 안내

- 저장된 좌표 순서대로 출발점에서 시작한다. 역방향 출발·중간 합류는 이번 범위에서 제외한다.
- 경로 좌표의 방향 변화로 좌회전·우회전·유턴 지점을 만든다. 도로명·교차로 정보가 없으므로 **‘다음 교차로’라는 표현 대신 거리와 방향**을 안내한다.
- 교차·왕복·겹치는 구간에서는 이전 진행 위치와 이동 방향을 함께 사용한다. 가까운 다른 구간으로 진행률이 뛰거나 출발점에서 바로 완주하는 일이 없어야 한다.
- 이동 거리는 모의 위치가 이동한 거리이며, 코스 진행 거리는 원래 코스를 따라 전진한 거리다. 이탈·복귀 이동을 코스 완주 진행률에 더하지 않는다.

### 이탈·복귀·위치 불량

아래 값은 **이번 모의 검증용 초기 기준**으로 사용하고 한곳에서 관리한다.

| 항목 | 초기 동작 기준 |
|---|---|
| 이탈 | 신뢰 가능한 위치가 코스에서 25m 넘게 떨어진 상태로 모의 시간 5초간 유지될 때 확정 |
| 복귀 | 이탈한 구간으로 되돌아와 코스와 12m 이내인 상태가 3초간 유지될 때 정상 전환 |
| 위치 불량 | 정확도 30m 초과 또는 수신 공백 5초 초과이면 방향·이탈·완주 판단을 보류 |
| 완주 | 코스를 순서대로 진행해 마지막 구간에 진입하고, 남은 경로 10m 이하·도착점 15m 이내가 3초간 유지될 때 감지 |

- 이탈 전후의 모의 이동 궤적을 보관하고 **지나온 궤적을 역순으로 따라 이탈 지점까지 복귀**시킨다. 가까운 코스 지점으로 새 길을 계산하지 않는다.
- 복귀 중 남은 거리는 ‘되돌아갈 거리 + 원래 코스 잔여 거리’로 계산한다.
- 위치가 불량하거나 궤적이 끊겨 복귀 경로를 확인할 수 없으면 ‘위치 확인 중’을 표시한다. 끊긴 구간을 직선으로 연결해 복귀 안내를 만들지 않는다.
- 시작점과 도착점이 같은 코스, 중간에 도착점 근처를 통과하는 코스도 전체 진행 순서를 확인한다.

### 음성·진동

- 한국어로 방향·이탈·복귀·완주를 실제 재생한다.
- 회전 안내는 **100m 전·30m 전**에 각 한 번 제공한다. 해당 거리보다 가까운 곳에서 새 안내가 시작되면 현재 필요한 안내만 제공한다.
- 이탈 확정 시 음성과 진동을 한 번 발생시킨다. 같은 이탈 상태에서 반복 진동하지 않는다.
- 가속 재생에서도 음성 속도는 정상으로 유지한다. 지난 안내를 쌓지 않고 현재 유효한 안내를 우선하며, 일시정지·종료 시 발화를 취소한다.
- 한국어 음성이 없거나 재생에 실패하면 화면에 이유를 표시하고 문자 안내를 유지한다. 음성 검증은 별도 미완료로 기록한다.

### 모의 상황 조작

- 기준 페이스는 기존 시뮬레이션과 같은 **6분/km**, 배속은 **1·5·10·30배**다.
- 배속은 모의 시간을 가속한다. 화면의 러닝 시간·페이스와 이탈 판정도 모의 시간을 기준으로 계산한다.
- 자동 시나리오는 정상 완주, 좌·우회전/유턴, 이탈 후 복귀, 위치 흔들림, 신호 끊김, 교차·겹침 코스를 제공한다.
- 시험 패널에 재생·일시정지·처음부터·배속·이탈 시작·지나온 길로 복귀·위치 불량·정상 수신 버튼을 둔다.
- 수동 조작은 위치 흐름을 바꾼다. ‘이탈’ 버튼으로 안내 상태를 직접 강제 변경하지 않고, 안내 로직이 입력 위치로 판단하도록 한다.
- 안내 발생 시점·문구·판정 상태를 시험 패널에서 확인할 수 있게 한다.

## 4. 구현 구조와 화면 꺼짐 처리

- 기존 코스 저장 형식과 경로 보간 기능을 재사용하고, **모의 위치 공급기 → 안내 엔진 → 화면·음성·진동**으로 분리한다.
- 안내 엔진의 입력은 코스와 위치·시각·정확도다. 출력은 진행 거리·남은 거리·다음 방향·이탈/복귀 상태·완주 상태·안내 이벤트다. 모의 공급기만 아는 정답 구간 번호를 엔진에 전달하지 않는다.
- 화면과 백그라운드 실행부가 **동일한 세션 하나**를 사용한다. 화면 복귀나 모드 전환으로 시간이 중복 누적되거나 음성이 다시 발생하지 않게 한다.
- Android 로컬 Expo 모듈에 실행 서비스·한국어 TTS·진동을 연결하고, 안내 계산은 공통 TypeScript 엔진을 Headless JS에서 실행한다. 생성된 `android/` 폴더 직접 수정에 의존하지 않는다. [React Native 백그라운드 실행 구조](https://reactnative.dev/docs/headless-js-android)
- 실제 위치 권한을 요구하지 않는 사용자 시작형 모의 시험이므로 Android 14 이상에서는 용도를 명시한 `specialUse` foreground service를 사용한다. 이는 내부 시험 APK의 구성으로 한정하며 스토어 출시 구성은 후속 검토한다. [Android 서비스 유형 기준](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)
- 실행 중 상시 알림에 모의 주행 상태·일시정지·종료를 제공한다. ‘화면 꺼져도 안내’를 끄면 앱이 백그라운드로 갈 때 일시정지하고 자동 재개하지 않는다.
- 종료·오류·강제 종료 시 음성·진동·서비스를 정리한다. 프로세스가 종료된 시험은 자동으로 다시 시작하지 않는다. 앱 프로세스 종료 후 진행 복원은 후속이다.
- 시험 세션은 메모리에서 관리하며 사용자 SQLite·Supabase에 기록하지 않는다. 실제 GPS 러닝과 모의 안내는 동시에 실행하지 않는다.

## 5. 구현 순서와 완료 판정

| 순서 | 작업 | 통과 조건 |
|---|---|---|
| 1 | 백그라운드 실행 기반 | 에뮬레이터에서 화면을 끈 상태로 모의 위치·한국어 음성이 계속 발생하고 알림으로 종료 가능 |
| 2 | 안내 엔진·시나리오 | 정상·이탈·복귀·신호 불량·교차·완주를 고정 입력과 기대 결과로 자동 검증 |
| 3 | 첨부 5개 화면 연결 | 같은 세션으로 모드 전환·설정·일시정지·완주 결과까지 이어지고 수치가 일치 |
| 4 | 통합·회귀 검증 | 기존 코스 저장·단순 시뮬레이션·GPS 기록·로그인·동기화 검사 통과 |
| 5 | APK·검증 자료 준비 | 기존 앱 ID·서명으로 독립 실행 APK, SHA-256, 사용법·검증 결과 제공 |

필수 검증에는 다음을 포함한다.

- 정상·이탈/복귀·위치 불량 시나리오를 동일 조건으로 반복했을 때 판정과 안내 순서가 일치한다.
- 20,000점 코스, 중복 좌표, 자기 교차, 같은 도로 왕복, 출발/도착점 중첩에서 진행이 잘못 건너뛰지 않는다.
- 네트워크와 위치 기능을 꺼도 모의 주행·기본 경로·설치된 한국어 음성으로 안내할 수 있다.
- **API 36 에뮬레이터에서 실제 경과 시간 30분간 화면 꺼짐 시험**을 수행하고, 잠금 중 회전·이탈·복귀 안내와 화면 복귀 후 상태 일치를 확인한다.
- 일시정지·종료 뒤 추가 이동·발화·진동이 발생하지 않고 실행 서비스와 자원이 정리된다.
- 진동은 에뮬레이터의 요청·시스템 처리 여부까지 검증한다. 실제 진동 감각·야외 GPS 정확도·휴대폰 배터리는 후속 검증으로 구분한다.
- 시험 전후 기존 코스·러닝·메모 내용이 보존되고 시험 데이터가 동기화되지 않는다.

구현을 시작할 때 확정 계획을 실행 기록으로 보존하고, 종료 시 현재 상태·사용법·검증 문서를 갱신한다. 이번 완료 상태는 **‘러닝 안내 모의 시험 완료’**로 기록한다.
