## 실행 전 계획

2. 완전한 요청 범위의 파일 검증·병합을 마친 뒤 트랜잭션으로 저장하고 현재 버전을 바꾼다. 누락·손상·업데이트 실패·취소에는 기존 정상 자료를 유지한다.
3. 저장 자료 우선 조회·명시적 갱신·네트워크 없는 조회를 분리한다. 버전 혼합 방지, 만료 표시, 손상 파일 재수신, 용량 제한·사용 중 자료 보호를 구현한다.
4. 기존 SQLite 네이티브 기반에 연결하고 별도 검증 화면에서 지역별 저장·오프라인 재조회·저장 상태를 확인할 수 있게 한다. 실제 클라우드 대신 PC 로컬 표본 공급을 사용한다.
5. 실제 SQLite의 재열기·프로세스 종료/미완료 트랜잭션·실패·취소·경합·용량 정리 및 실제 3개 지역 표본을 검사한다. 타입·린트·Android 번들을 확인하고 문서·상태·실행 이력을 갱신한다.

서버 계정·도메인·배포·휴대폰 연결 테스트는 보류한다. 기존 도로 API 제거·운영 공급 연결과 실기기 검증은 후속이며 이번 결과를 4-3 전체 전환 완료로 보고하지 않는다. 앞선 미커밋 배포 준비 변경은 보존한다.
