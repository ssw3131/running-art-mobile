## 실행 전 계획

1. 별도 SQLite 도로 캐시에 매니페스트 해시·공급자·격자별 gzip 원본을 저장한다. 기존 테스트 메모 DB와 운영 도로 API는 유지한다.
2. 완전한 요청 범위의 파일 검증·병합을 마친 뒤 트랜잭션으로 저장하고 현재 버전을 바꾼다. 누락·손상·업데이트 실패·취소에는 기존 정상 자료를 유지한다.
3. 저장 자료 우선 조회·명시적 갱신·네트워크 없는 조회를 분리한다. 버전 혼합 방지, 만료 표시, 손상 파일 재수신, 용량 제한·사용 중 자료 보호를 구현한다.
4. 기존 SQLite 네이티브 기반에 연결하고 별도 검증 화면에서 지역별 저장·오프라인 재조회·저장 상태를 확인할 수 있게 한다. 실제 클라우드 대신 PC 로컬 표본 공급을 사용한다.
5. 실제 SQLite의 재열기·프로세스 종료/미완료 트랜잭션·실패·취소·경합·용량 정리 및 실제 3개 지역 표본을 검사한다. 타입·린트·Android 번들을 확인하고 문서·상태·실행 이력을 갱신한다.

서버 계정·도메인·배포·휴대폰 연결 테스트는 보류한다. 기존 도로 API 제거·운영 공급 연결과 실기기 검증은 후속이며 이번 결과를 4-3 전체 전환 완료로 보고하지 않는다. 앞선 미커밋 배포 준비 변경은 보존한다.

2. 저장 자료 우선·명시적 갱신·오프라인 모드, 7일 확인 만료·64 MiB 저장 자료 한도·LRU·손상 복구를 구현했다. 캐시 적중으로 확인 시각을 연장하지 않고 갱신 실패 대체 사용은 오래된 상태를 알린다.
3. `cache-database.ts`에서 기존 Expo SQLite를 별도 DB에 연결했다. 기존 테스트 메모 DB·스키마는 유지하고 공유 SQL 값 타입에 BLOB 지원만 추가했다.
4. `road-cache-lab.tsx`와 `features/road-cache-lab/source.ts`에 세 공개 표본 지역의 로컬 다운로드·재읽기·오프라인·취소·비우기·용량 화면을 추가하고 홈에 연결했다. 운영 공급과 기존 일반 계산은 변경하지 않았다.
5. `tests/road-cache.test.mjs`, 실제 SQLite adapter와 `scripts/road-data/cache-rehearse.mjs`를 추가했다. [사용법](../../development/road-cache.md)·[검증 기록](../../quality/road-cache-verification.md)·[결과 JSON](../../quality/road-cache-report.json)과 최신 상태·로드맵을 갱신했다.

## 한계와 후속

커밋 직전 취소 검사까지는 롤백하지만 커밋된 저장은 늦은 취소로 되돌릴 수 없다. 이후 취소는 결과 표시를 막는다. 64 MiB는 BLOB·목록 바이트 한도이며 실제 DB/WAL·객체 메모리 상한이 아니다. 기본값은 기기 측정 후 조정한다. 앱 내 하나의 캐시 연결을 전제로 하며 운영 CDN 전송·포인터 검증·일반 계산 연결은 후속이다.
