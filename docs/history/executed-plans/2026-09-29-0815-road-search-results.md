## 실행 전 계획

1. 현재 앱의 위치 선택·도로 공급자·계산 흐름을 확인하고 공개 위치에서 새 지역 탐색 실패를 재현한다. 잘못된 지역의 고정 표본으로 대체하지 않는다.
2. 확인된 원인에 맞춰 모바일 도로 조회를 수정하고 기존 OSM 식별자·연결성·범위 검사·취소·캐시 제한을 유지한다. 원본 프로토타입과 v0.2 계산 기준은 변경하지 않는다.
3. 지도 이동·현재 위치 선택 후에도 완료된 경로·후보·원래 계산 기준을 유지한다. 다음 계산 시작 시 결과를 초기화하고 새 중심으로 조회한다. 진행 중 작업 취소와 늦은 응답 차단을 유지한다.
4. 관련 회귀 검사·타입·린트·Android 빌드를 실행하고 에뮬레이터에서 새 지역 조회/계산, 지도 이동 후 결과 유지, 재탐색과 취소를 검증한다. 연결된 휴대폰 유무와 검증 범위를 구분한다.
5. 변경한 사용법·현재 상태·검증 근거·실행 기록을 갱신하고 업데이트용 APK를 준비한다. 외부 공개 배포와 CI/CD 구축은 포함하지 않는다.

## 실행 결과

모바일 도로 로더에 공급자별 25초·전체 90초 제한과 기본 공급자 실패 시 동일 지역 Overpass 대체 조회를 추가했다. 전체 geometry·OSM ID·범위 검사·캐시 상한·취소를 유지하고, 사용자 지정 공급자는 자동 전환을 제외했다. `ROAD_DATA_ATTEMPT` 로그에 위치정보 없이 공급자·시간·응답 코드·성공 여부만 남긴다.

`route-lab.tsx`에서 다음 탐색 조건 변경과 완료 결과 초기화를 분리했다. 지도 이동·현재 위치·도형/거리 변경은 기존 결과를 유지하고, 계산 시작·데이터 종류 전환은 초기화한다. `fixtures.ts`의 서울 OSM 이름을 주변 OSM으로 변경했다. v0.2 엔진과 원본 프로토타입은 변경하지 않았다.

관련 자동 검사, README·사용법·구조·현재 상태·검증 문서를 갱신했다. 업데이트용 APK·체크섬·한글 설치 안내를 `build/install/`에 준비했다. 외부 공개 배포는 하지 않았다.

## 검증

시작 시 Git 작업 트리는 깨끗했고 연결된 Android 기기는 없었다. 공개 위치의 기본 API 조회에서 강남 95초 시간 초과를 재현하고 부산 조회·계산 성공을 확인했다. 수정 후 PC와 Android에서 강남 도로 조회·계산이 성공했다.

- 전체 Node 검사 75개 통과. 최종 진단 로그 보완 후 관련 17개·타입·린트 재검증 통과.
- Android 릴리스 빌드 성공, 기본 JS 번들/서명/지원 아키텍처 검증. 기존 Pixel 7 에뮬레이터에 업데이트 설치 후 Metro 없이 실행했다.
- 강남 모의 위치 3km: 후보 5개. 완료 경로를 남긴 채 지도 중심을 변경했고 기존 결과 기준은 유지됐다. 재탐색 시작 시 초기화·진행 중 지도 이동 취소·새 중심에서 캐시 재탐색(후보 5개)을 확인했다.
- 기본 공급자만 차단하는 테스트 프록시로 부산 조회를 실행했다. 실제 Overpass 응답으로 후보 5개를 계산했으며 종료 후 프록시 설정·프로세스를 원복했다.
- 실제 검증 APK와 전달 파일의 SHA-256 일치: `54a05258c17e91c32004d6c437cf1ea66f4791793da0177cfa3e8ce587448805`.

구체적인 수치·캡처·실패 이력·검증 범위는 [검증 기록](../../quality/road-search-results-verification.md)에 남겼다. 실제 휴대폰은 연결되지 않아 이번 APK 설치·GPS 검증은 하지 않았다.
