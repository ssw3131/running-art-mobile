# 도로 조회 재시도를 서버로 단일화

## 목표와 범위

앱은 도로 API를 한 번 호출하고, **공급자 전환과 자동 재시도는 기존 서버에서만 관리**한다.

Overpass 공급자 두 곳, 조회 지역·도로 필터·전체 geometry, 서울 저장 자료와 기존 캐시는 유지한다. 영구 도로 저장과 계산 알고리즘 변경은 이번 범위에서 제외한다.

## 변경 내용

- **앱:** Overpass 직접 호출과 공급자 반복문을 제거한다. 데이터 검증·메모리 캐시·사용자 취소는 유지하며, 실패 후 재계산 버튼을 누르는 수동 재요청은 허용한다.
- **서버:** `overpass-api.de → overpass.private.coffee` 순서로 공급자당 최대 한 번씩 순차 요청한다. 배포 서버와 로컬 서버에서 같은 재시도 모듈을 사용한다.
- **전환 조건:** 네트워크 오류·시간 초과·5xx·잘못된 JSON·불완전한 도로 응답이면 다음 공급자로 전환한다. 요청 제한 응답인 429/406, 그 외 4xx, 취소 시에는 추가 요청 없이 종료한다.
- **시간 제한:** Overpass 쿼리 제한 20초, 공급자당 본문 수신 포함 25초, 서버 전체 55초, 앱 전체 65초로 맞춘다. 시간 초과 시 실제 네트워크 요청도 중단한다.
- **취소와 캐시:** 수신한 취소 신호를 외부 요청까지 전달하고 이후 공급자 호출을 막는다. 실패·부분 응답은 캐시하지 않는다. 로컬 서버의 공유 요청은 대기 중인 모든 호출이 취소됐을 때 중단한다.
- **API 계약:** 기존 주소·요청 매개변수·성공 응답·`X-Road-Area`를 유지한다. 앱에는 API 호출 시간, 서버에는 공급자별 시간·결과를 기록한다.

## 검증

- 앱의 캐시 미적중 조회가 API 요청 **1회**로 끝나고 Overpass 직접 호출이 없는지 확인한다.
- 첫 공급자 성공, 실패 후 두 번째 성공, 양쪽 실패, 429/406 종료를 검증한다.
- 응답 본문 정지·불완전 JSON·시간 초과·취소 후 늦은 응답이 추가 호출이나 캐시 저장으로 이어지지 않는지 검증한다.
- 서울 저장 자료·캐시 재사용·지역 이동·완료 코스 유지에 대한 회귀 검사와 모바일 타입·린트, 서버 테스트·배포 빌드 검사를 수행한다.

## 적용 순서와 현재 제약

서버 수정·검증·배포를 먼저 완료한 뒤 앱 변경을 적용한다. 실행 기록과 인수인계 문서를 갱신하며 기존 미커밋 문서 수정은 보존한다.

현재 배포 도구가 기존 사이트에 대해 `Sites project not found`를 반환했고, 안내된 Sites 호스팅 스킬 파일도 찾지 못했다. 코드 수정과 로컬 검증은 준비할 수 있지만, 운영 반영에는 기존 사이트 접근과 배포 환경 복구가 필요하다.
