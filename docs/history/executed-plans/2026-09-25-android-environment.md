### Android Studio Gradle 동기화 복구 계획

#### 목표와 확인된 문제

Android Studio를 시작 메뉴에서 열고, **Gradle 동기화 → `app` 선택 → ▶ Run → 가상 휴대폰에서 앱 실행**까지 가능하게 정리합니다.

현재 확인된 문제는 다음과 같습니다.

- 프로젝트에 Node.js가 있지만 Windows의 영구 Path에 등록되지 않았습니다.
- Studio가 가리키는 SDK에는 API 37.0이 설치돼 있고, 기존 빌드에 사용한 API 36은 프로젝트 SDK에 있습니다.
- 생성된 Gradle 설정이 JDK 25를 요구합니다. 기존 프로젝트 기준은 JDK 17이며, 진단 실행에서도 Java 탐색·다운로드 오류가 발생했습니다.

#### 수정 순서

1. **선택한 사용자 Path 등록**
   - 기존 프로젝트의 `.tools/node`를 현재 Windows 계정의 Path에 추가합니다.
   - 기존 항목을 보존하고 중복 등록을 방지합니다. 변경 전 값을 복구용으로 보관합니다.
   - Android Studio를 완전히 종료한 뒤 시작 메뉴에서 다시 열어 새 경로를 적용합니다.

2. **Gradle 실행 환경 통일**
   - JDK 25를 요구하는 `gradle-daemon-jvm.properties`를 백업하고 제거합니다. 이 설정은 `JAVA_HOME`보다 우선하므로 별도 처리가 필요합니다. [Gradle 공식 설명](https://docs.gradle.org/current/userguide/gradle_daemon.html#sec:daemon_jvm_criteria)
   - Studio의 Gradle JDK를 프로젝트 `.tools/java`의 **JDK 17**로 지정합니다.
   - Gradle 캐시는 프로젝트 `.cache/gradle`을 사용합니다.
   - Gradle **9.3.1**, AGP **8.12.0**을 유지합니다. Android Studio 자체는 번들 JBR로 실행합니다.

3. **SDK와 에뮬레이터 연결 정리**
   - 프로젝트 SDK 경로를 `.tools/android-sdk`로 통일하고 기존 API 36·NDK·빌드 도구를 사용합니다.
   - 현재 Pixel 7 가상 기기와 데이터를 보존합니다. SDK 변경으로 이미지 탐색이 끊기지 않도록 기존 시스템 이미지의 실제 위치를 참조하게 합니다.
   - Gradle 동기화를 실행합니다. 성공 후에도 실행 구성이 없다면 Android App 구성에 `app` 모듈을 지정합니다.
