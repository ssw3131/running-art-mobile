## 실행 전 계획

1. A7 실기기에서 확인한 제목 입력칸 가림과 현재 문의 작성/수정 화면을 대조한다. 기존 문의 데이터·전송/권한 계약은 유지한다.
2. 키보드 표시·입력 포커스·화면 크기 변경 후 실제 입력칸/스크롤 영역/키보드 경계를 측정하고 필요한 만큼 스크롤한다. 긴 본문은 사용 가능한 높이 안에서 입력·스크롤하도록 한다. 키보드를 닫으면 임시 여백을 제거한다.
3. 기존 문의/공지 UI와 타입·린트, Android29/36에서 작성·수정의 제목/본문·긴 입력·다크/큰 글씨·뒤로 가기를 검증한다. 접근성 노드 존재만으로 통과하지 않고 키보드 경계와 입력칸 전체 경계를 대조하고 원본 화면을 검토한다.
4. 변경 검토 기록·결과·인수인계를 갱신하고 draft 빠른 검사→ready 전체 CI→main 필수 검사·작업 브랜치 정리를 완료한다.
5. 기존 앱 ID/서명으로 독립 실행 APK를 만들어 업로드하고 해시/메타데이터를 확인한다. 실제 삼성 키보드/휴대폰은 연결 여부와 실제 실행 범위를 분리해 기록한다.

## 결과·검증·남은 작업

착수 때 기존 SupportPage는 Android에서 키보드 회피 behavior와 포커스 위치 보정이 없고, 문의 검사도 입력 노드의 실제 키보드 가림을 확인하지 않았다.


작성·수정의 네이티브 입력 ref를 공통 문의 스크롤에 연결해 포커스/키보드/레이아웃 변경 시 가림을 보정했다. 구형 Android의 이벤트 누락에서도 줄어든 뷰포트를 사용하며 긴 본문은180dp 또는 가용 높이 안에서 내부 스크롤한다. 키보드 종료 시 임시 여백을 제거한다. 기존 문의 API·권한·입력 계약은 유지했다.
