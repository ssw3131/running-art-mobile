## 전략과 실행 계획

기준은 같은 서울 OSM·하트·5km의 개발용 앱 관측인 휴대폰 59.95초 / 에뮬레이터 301.05초다. 후보 평가 상한 200/140/80, 도형·점수·거리·OSM 연결성·동점 처리·추천 결과를 유지하면서 실제 반복 연산과 불필요한 할당을 줄인다. 탐색 수를 줄여 속도만 높이거나 기준 결과를 계산 대신 반환하지 않는다.

1. 현재 작업 트리와 기존 기기 로그를 기준으로 변경 전 엔진을 별도 보존한다. 재현 가능한 Node 벤치마크·CPU 프로파일로 병목과 단계별 시간을 확인한다. Node와 Hermes의 속도를 같은 것으로 해석하지 않는다.
2. 병목에 따라 공간 검색의 불필요한 거리 연산, A* 상태 할당·중복 경로 계산, 점수 계산 중복을 우선 검토한다. 재사용은 한 검색 범위로 한정하고 캐시는 상한을 둔다. 취소·동시 작업·그래프 변경에서 결과가 섞이지 않도록 한다.
3. 필요하면 실행 양보 비용을 개선하되 계산 중 입력·취소와 최대 연속 연산을 함께 확인한다. 별도 스레드·네이티브 도입은 앞선 측정으로 필요성이 확인될 때 판단한다.
4. 서울 하트 5km의 원본 전체 기준 결과를 앱·회귀 사례에 추가한다. 기존 사례와 새 사례에서 경로·점수·거리·순위·통계 일치, 작은 그래프의 경계·동점·일방통행·취소·연속 실행을 검증한다.
5. 타입·린트·관련 회귀·Android 번들을 확인한다. 연결된 휴대폰에서 같은 입력을 반복 계산해 시간·원본 전체 비교·UI 입력·취소·메모리를 확인하고 에뮬레이터에서도 같은 입력을 확인한다. 개발용 결과와 릴리스/다른 폰의 성능은 구분한다.
6. 구현 설명·벤치마크 사용법·전략·측정 결과·제한과 실행 기록·현재 상태·로드맵을 갱신한다.

## 완료 기준

- 측정으로 우선순위를 정한 최적화가 실제 앱에 반영돼 있고 동일 입력의 지연이 실질적으로 감소한다.
- 원본 결과·탐색 범위·경로 제약을 보존하고 새 재사용 경계의 회귀 및 기존 기능 검사가 통과한다.
- 휴대폰의 전체 결과 비교·반복 측정·입력/취소와 Android 번들 검증 증거가 있다. 검증할 수 없는 범위는 완료로 표시하지 않는다.
- 측정 조건·전략·결과·후속 한계를 문서에서 재현할 수 있다.

## 실행 결과·검증

계획에 따른 첫 최적화와 검증을 완료했다. 원본 결과를 유지한 PC 계산·에뮬레이터 지연 감소를 확인했고, 폰 개발 모드의 효과가 작다는 한계도 기록했다. 같은 APK의 배포용 JavaScript 모드를 추가해 폰 중앙값 44.27초를 확인했다. 수십 초 대기와 정식 릴리스 성능은 후속 과제다.

### 2026-09-27T17:00:32+09:00 — 웹 비교 추가

사용자가 `https://running-art-seoul-mobile.alo-ha.chatgpt.site/`와 형제 `running-art/`로 비교를 요청했다. 원래 계획은 유지하고 웹 배포 원본·입력·Worker 실행 방식 비교를 추가한다. 기본 페이지는 v0.3이며 `/v0.2/` 보존 화면에서 광화문·하트·5km·반경 2km로 맞췄다. 배포 v0.2 엔진의 정규화 SHA-256은 보존 참조와 같은 `43a5a0f6bff98b6697d98ee10be85865a9328225b87345e613f8707864ab2fbf`다. 웹 UI에서 6,280개 배치·386개 경로·107개 유효 후보와 같은 상위 5개 거리/점수를 확인했다.

웹 API 응답은 11,266개 요소, 앱 고정 표본은 ID로 정렬한 4,810개 요소다. 그래프 생성 후 양쪽 21,627노드·23,132도로이나 순서가 다르므로 입력이 바이트 단위로 같다고 가정하지 않는다. 전체 차이 문자열을 만드는 진단이 PC 메모리 오류를 일으켜 중단했으며, 이후 비교는 항목별·요약 출력으로 제한한다. 이 시점 USB 휴대폰 연결이 사라지고 에뮬레이터가 offline이어서 기기 검증은 복구 후 진행한다. 웹 자동화의 완료 대기가 실패했으므로 현재 웹 실행 시간은 확정값으로 보고하지 않는다.

### 2026-09-27T17:51:34+09:00 — 구현·검증 종료

- `src/modules/route-engine/engine.ts`: 검색마다 숫자 공간 인덱스를 준비하고 A* 비용·이전 노드·휴리스틱·세대 배열을 재사용한다. 방향·정확한 길이 예산을 포함한 경로 캐시를 8,192경로·262,144노드 ID 이내로 유지한다. 최근접 축 경계 필터와 동점 순서를 보존하는 힙 이동을 적용했다. 탐색 상한 200/140/80·점수·거리 수식과 8ms 실행 예산·32방문 체크포인트는 유지했다.
- `runner.ts`·화면 로그: 원본 결과와 분리된 `routing` 진단을 기록한다. 캐시는 검색끼리 공유하지 않으며 취소·동시 실행 경계를 검증했다.
- `scripts/benchmark-route-engine.mjs`: 같은 입력의 그래프·탐색·전체 시간을 반복 측정하고 매번 원본 전체 결과를 비교하는 명령을 추가했다. CPU 프로파일을 켠 수치는 성능 개선율에서 제외했다.
- `scripts/prepare-route-reference.mjs`·`tests/fixtures/route-engine/`·`assets/route-lab/`: 서울 하트 5km 기준을 추가해 총 6개 전체 결과를 보존하고 앱에서 실시간 전체 비교가 가능하게 했다. 원본 `tests/reference/v02` 파일은 수정하지 않았다.
- `tests/route-engine-optimization.test.mjs`와 기존 회귀: 방향·실패·동점·예산 경계, 최근접 경계·필터, 동시 검색·취소 후 재시작을 확인했다. 화면 기준 사례의 명시적 ID도 연결했다.
- `package.json`: 같은 개발 APK로 배포용 JS를 비교하는 `start:performance` 명령을 추가했다. 네이티브 릴리스 빌드와 구분한다.

같은 PC Node에서 프로파일 없이 각 3회 측정한 전체 계산 중앙값은 보존 원본 **8.50초**, 수정 전 모바일 **9.82초**, 최종 모바일 **4.21초**였다(수정 전 대비 약 **57.1% 감소**). 모든 전체 결과 SHA-256은 `955a70a2ead477338056d0f48b3453f28cfec1f74cf8c77f5d88d5193c9fcc22`로 같았다. 배포 웹 API 입력을 원본으로 계산한 결과도 앱 기준과 오차 0으로 일치했다. 브라우저의 정확한 계산 시간은 자동화 연결 문제로 미확정이며 Node 시간을 대신 제시하지 않는다.

폰 SM-S942N·Android 16, 에뮬레이터 Pixel 7·Android 16.1에서 같은 서울 하트 5km를 실행했다. 최종 코드의 개발 모드 폰은 **53.27 / 61.15 / 58.44초**, 중앙값 **58.44초**로 수정 전 단일 관측 59.95초 대비 뚜렷한 개선이라고 해석하기 어렵다. 에뮬레이터는 **301.05초 → 199.75초**, 약 33.6% 감소였다. Hermes 프로파일은 A*·최근접 노드·힙 개선 우선순위에 사용했으며 프로파일 켠 폰 76.95초는 비교에서 제외했다.

동일 APK에서 `dev=false`, `minify=true`를 확인한 뒤 폰 **39.42 / 44.27 / 48.87초**, 중앙값 **44.27초**를 얻었다. 최종 코드의 개발 모드 중앙값 대비 약 **24.2% 감소**다. 에뮬레이터는 **82.15 / 106.40초**였다. 코드와 모드 변경 효과를 하나의 알고리즘 개선율로 합치지 않는다. 두 모드의 폰, 배포 모드 에뮬레이터에서 실제 버튼 입력·취소·재시작과 원본 전체 비교를 확인했다. 메모리는 앱 전체 순간 PSS/RSS로 기록했으며 엔진 전용·최대치·누수 검증과 구분했다.

검증 명령은 `npm test`(**58개 통과**), `npm run check`(타입·린트 통과), `npm run export:android`(Android HBC 번들 통과), 벤치마크 원본/전후 각 3회다. 원본 9개 파일 해시가 유지됐다. 네이티브 코드 변경이 없어 기존 APK를 사용했다. 문서 40개·상대 링크 162개에서 오류가 없었고 `git diff --check`와 종료 시 타입 재검사도 통과했다. 개별 수치·증거 파일은 [검증 기록](../../quality/route-engine-verification.md), 재현과 전략은 [성능 개선](../../development/route-engine-performance.md)에 남겼다.

기기 복구는 기존 앱 데이터 삭제 없이 수행했다. 반복된 USB 단절은 사용자 재연결과 reverse 복구, 멈춘 Pixel 7은 확인한 에뮬레이터 프로세스만 재시작했다. 중복 Metro는 프로젝트·명령·PID를 확인해 종료했다. 개발 서버의 IPv6 전용 localhost 문제는 호스트 바인딩과 USB URL을 분리해 해결했다. 종료 시 **Metro 8081 하나, 성능 비교 모드, 두 기기 결과 화면**을 유지한다. 평소 개발로 복귀하려면 서버를 종료하고 `npm run start`를 사용한다.
