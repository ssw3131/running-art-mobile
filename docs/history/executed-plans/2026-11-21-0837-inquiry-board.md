## 실행 전 계획

### 1. 확정 방향

- **본인과 운영팀만** 볼 수 있는 비공개 문의 게시판으로 전환한다.
- 이메일 입력·수집·메일 발송을 제외한다.
- 운영팀은 **Supabase 관리 화면에서 답변을 직접 입력**한다. 별도 관리자 화면은 만들지 않는다.
- 문의는 답변 전에만 수정·삭제할 수 있다. 답변 후 추가 질문은 새 문의로 받는다.
- `미확인`은 **답변이 없는 상태**, `답변 완료`는 **답변이 등록된 상태**를 뜻한다. 운영자의 열람 여부는 추적하지 않는다.

### 2. 화면과 이동

**첫 진입**
- 화면 제목은 `문의 및 의견 보내기`.
- 본인 문의를 정상 조회한 뒤, 게시글이 있으면 목록을, 없으면 작성 화면을 바로 표시한다.
- 조회 중에는 로딩, 실패하면 오류와 재시도를 표시한다. 조회 실패를 빈 목록으로 처리하지 않는다.

**목록**
- 공지사항의 카드 형태·날짜·제목·이동 아이콘을 재사용한다.
- 카드에 `미확인` 또는 `답변 완료` 태그를 표시한다.
- 기존 문의 이미지를 상단에 사용한다.
- 최신 등록순으로 20개씩 조회하고 `더 보기`로 이어서 표시한다.
- 하단에 고정한 `문의 및 의견 보내기` 버튼으로 작성 화면을 연다.

**작성·수정**
- 기존 문의 이미지와 문의 유형·제목·내용 입력을 사용한다. 이메일 필드는 제거한다.
- 기존 유형과 제목 100자·내용 5,000자 제한을 유지한다.
- 등록 성공 시 해당 상세로 이동한다. 뒤로 가면 갱신된 목록이 나온다.
- 수정 중 답변이 등록되면 저장을 막고 최신 답변을 안내한다.
- 삭제는 확인 후 처리하며, 마지막 문의를 삭제하면 작성 화면으로 돌아간다.

**상세**
- 공지사항 상세의 레이아웃을 재사용한다.
- 문의 유형·상태·등록일·제목·내용을 표시한다.
- 답변이 있으면 본문 아래에 구분선을 두고 **`RunPen 운영팀 답변`**, 답변 내용·작성일을 표시한다.
- 답변이 없으면 `운영팀의 답변을 기다리고 있어요.`를 표시한다.
- 답변 전에는 수정·삭제 버튼을, 하단에는 목록 복귀 버튼을 제공한다.

### 3. 서버와 운영팀 답변

- 현재 서버에 누락된 문의 테이블·접수 함수를 마련하고, 답변 본문·답변 시각·수정 버전을 추가한다.
- 상태는 답변 유무로 자동 결정한다. 관리자가 상태와 날짜를 따로 입력하지 않아도 되도록 한다.
- 문의당 운영팀 답변은 하나로 시작한다. Supabase에서 답변 본문을 저장하면 즉시 공개되고, 이후 답변 수정도 가능하다. 등록된 답변을 빈 값으로 지워 미답변 상태로 되돌리는 것은 막는다.
- 앱에는 본인 문의 목록·상세 조회와 등록·수정·삭제 인터페이스를 제공한다. 사용자 입력 모델에서 이메일을 제거한다.
- DB 권한으로 본인 문의만 조회하도록 제한한다. 사용자에게 답변 필드 변경이나 직접 테이블 쓰기 권한을 주지 않는다.
- 수정·삭제와 관리자 답변이 동시에 발생해도, **답변이 먼저 저장되면 원문 변경을 거부**하도록 서버에서 처리한다.
- 요청번호 기반 중복 방지와 시간당 신규 5건 제한을 유지한다. 별도 접수 원장에 요청번호·원본 지문·접수 시각을 보존해, 삭제 후 재전송으로 문의가 되살아나거나 등록 제한이 우회되지 않도록 한다.
- 문의·답변·접수 원장은 탈퇴 시 함께 삭제한다. 이번 변경에서 별도 자동 보관기간은 추가하지 않는다.

### 4. 실패 처리와 기존 앱 호환

- 목록·상세·전송 요청에 10초 제한을 두고, 연결 실패·로그인 만료·접수 제한·수정 충돌을 구분해 안내한다.
- 접수 결과가 불확실하면 같은 요청번호로 확인한다. 서버 접수를 확인하기 전 성공으로 표시하지 않는다.
- 기존 암호화 저장소의 미전송 문의는 유형·제목·내용·요청번호를 보존하고 이메일만 제거해 복구한다.
- 구버전 앱의 접수 함수 형식은 유지하되 이메일 인자는 저장·사용하지 않는다. 새 앱은 이메일을 전송하지 않는다.
- 공지사항에서는 **화면 구성만 재사용**한다. 공개 공지용 공통 캐시에 개인 문의를 저장하지 않는다.
- 계정 전환 시 문의 화면 데이터를 비우고 이전 계정의 늦은 응답을 무시한다.
- 답변은 화면 재진입·새로고침 때 갱신한다. 푸시 알림·실시간 채팅·첨부파일은 이번 범위에서 제외한다.

### 5. 검증과 적용 순서

1. **DB 준비:** 기존 약관 테이블이 부분 적용된 상태를 대조하고, 문의 전용 변경만 새 마이그레이션으로 준비한다. 과거 지원 SQL 전체를 재실행하지 않는다.
2. **기능 검증:** 빈 목록→작성→등록→상세→목록, 수정·삭제, 관리자 답변 등록·수정, 태그 전환을 확인한다.
3. **권한·실패 검증:** 타인 문의 접근·답변 조작 차단, 중복 클릭, 응답 유실·재시작, 삭제 후 재전송, 답변과 수정의 동시 처리, 계정 전환을 검사한다.
4. **화면 검증:** Android 29·36에서 긴 본문·키보드·큰 글씨·다크 모드·뒤로 가기와 하단 버튼을 확인한다. 기존 공지 화면도 회귀 검사한다.
5. **운영 적용:** 검증한 DB 변경을 먼저 반영하고 새 앱을 적용한다. 실제 휴대폰 문의 등록→Supabase 답변 입력→앱 답변 확인까지 확인한다.

운영 문서에는 Supabase에서 답변할 필드와 절차를 남기고, 앱 안내·개인정보 관련 설명에서 문의 이메일 수집 표현을 수정한다.
