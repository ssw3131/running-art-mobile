## 실행 전 계획

1. 최신 main에서 기능 브랜치를 만들고 D-01/05/12 중 가입에 필요한 계약을 구체화한다. 게스트 가입 안내·동의 구성·기존 계정 처리의 선택지를 사용자에게 제시하고 답을 반영한다. 기존 비로그인 계산과 자료 소유권은 유지한다.
2. Figma 가입/로그인·프로필/동의 원본을 조회하고 공통 UI·기존 3종 소셜/프로필/사진 기능을 재사용한다. 로딩·취소·오류·중단 후 재진입을 처리한다.
3. 서버가 관리하는 정책 버전·가입 완료·동의 이력과 본인 접근/탈퇴/응답 유실·중복 방지를 새 마이그레이션으로 구현한다. 기존 계정 메타데이터를 가입 권한 근거로 쓰지 않는다. 확정되지 않은 약관을 실제 배포 문안으로 만들거나 보너스 지급 성공을 표시하지 않는다.
4. 로컬 정책/상태/UI 검사와 적절한 Android 검증 후 변경을 검토하고 PR 필수 검사를 수행한다. 기존 DB 배포 이력은 실제 배포 전에 대조한다. 운영 DB·사용자 휴대폰 배포는 구체적 결과가 준비된 뒤 다룬다.
5. 제품 결정·개발/검증 문서·현재 상태와 이력을 갱신한다. 홈 3상태·결제·자동 배포·형제 프로젝트는 이번 범위에 넣지 않는다.

## 남은 작업과 종료

Figma의 빈 운영자/연락처/시행일과 현재 서비스에 맞는 본문 확정, 운영 DB 구조/수동 배포 이력 대조 후 실제 기존 계정 이관·정책 게시, 새 화면에서 세 소셜/사진/동의 완료까지 실기기 통합이 남아 있다. 사용자 폰 설치·홈 3상태·상품/보너스는 수행하지 않았다. 이번 구현·격리 검증과 운영 기능 활성화를 구분해 부분 완료로 기록한다.
