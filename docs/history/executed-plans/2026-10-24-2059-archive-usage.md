- 생성은 서버에서 횟수를 예약하고, 후보가 1개 이상 생성되어 결과 수령이 확정될 때 후보 묶음당 1회 차감한다. 확정 전 취소·실패·0후보는 예약을 해제한다. 확정과 취소가 경합하면 서버의 먼저 완료된 상태를 따르며, 응답 유실은 같은 작업 ID로 복구한다.

앞 절에는 실행 시 수정 사항을 요약했다. 아래는 같은 사용자 요청의 원문을 실행 중 보완해 보존한 것이며 별도 승인이나 새 계획이 아니다.

### 1. 목표와 완료 범위

가입·홈·코스 20km 변경을 통합하고, Figma에 맞춘 기록 보관함과 생성·저장 횟수 제한을 구현한다. 이번 수정에서는 **저장 코스 / 완주 기록** 구분과 홈→목록→상세→이전 화면 이동을 확정한다.

이미 작성한 통합 코드와 사용량 초안은 이어서 보완한다. 완료 범위는 **통합 소스·격리 검증·release APK 준비**까지이며, PR/CI·병합·운영 반영·휴대폰 설치는 후속이다.

### 2. 보관함·홈·뒤로가기

#### 저장 코스 탭

- 왼쪽 탭 이름은 **저장 코스**다. 저장한 코스를 모두 표시한다.
- 해당 코스의 **가장 최근 도전**이 진행 중·일시정지·앱 중단·중도 종료라면 **미완주** 태그를 표시한다.
- 한 번도 달리지 않은 코스에는 미완주 태그를 표시하지 않는다. 최근 도전이 완주라면 미완주 태그를 제거한다.
- 이전에 완주했더라도 새로운 도전이 미완주라면 태그를 표시한다. 이전 완주 기록은 오른쪽 탭에 그대로 남는다.
- 코스와 러닝의 연결은 코스 ID와 저장된 코스 사본으로 판별한다. 같은 도형이라는 이유로 연결하지 않는다.
- 사용 현황 카드는 ‘저장 공간’ 대신 **저장 횟수**로 표시한다.

#### 완주 기록 탭

- 오른쪽 탭 이름은 Figma대로 **완주 기록**이다.
- 러닝 종료가 확정되고 코스 완주 판정이 있는 기록만 표시한다. 도착 확인 대기·진행 중·중도 종료·자유 러닝은 제외한다.
- 같은 코스를 여러 번 완주하면 각각의 완주 기록을 표시한다.
- 월별 묶음·날짜 타임라인·도형 아이콘·카드 디자인을 적용한다. 완주 조건으로 먼저 조회한 후 페이지를 나눠 중간에 빈 페이지가 생기지 않게 한다.
- 제외되는 기존 기록을 삭제하거나 통계에서 임의로 제거하지 않는다.

#### 홈과 이동

- 홈의 **최근 달린 코스 / 최근 저장 코스 ‘더보기’는 모두 저장 코스 탭**을 연다. 추천 도형의 ‘전체보기’는 기존 도형 선택 이동을 유지한다.
- 홈의 개별 코스 카드와 저장 코스 목록의 카드를 누르면 **코스 상세**를 연다.
- 홈의 러닝 카드에 연결된 원본 코스가 삭제됐다면 당시 코스 사본으로 상세를 연다. 열람만으로 재저장하거나 횟수를 차감하지 않는다.
- 코스가 없는 자유 러닝 카드는 기존 러닝 상세를 유지한다. 완주 기록 탭의 개별 기록은 완주 기록 상세를 연다.
- 헤더 이전 버튼은 **직전에 보던 화면**으로 돌아간다. 홈→상세는 홈으로, 저장 목록→상세는 해당 목록으로, 추천 목록→상세는 추천 목록으로 복귀한다.
- 홈 ‘더보기’로 보관함에 들어온 경우에도 이전 버튼으로 홈에 돌아갈 수 있게 한다. 목록 탭·스크롤·추천 조건을 보존하고 Android 뒤로가기에도 같은 규칙을 적용한다.
- 직접 실행·딥링크처럼 이전 화면이 없는 경우에만 관련 목록으로 이동한다. 일반 뒤로가기에서 화면 이력을 일괄 제거하지 않는다.

### 3. 공통 코스 상세와 러닝 동작

- 추천과 저장 코스는 제목을 **코스 상세**로 통일하고 같은 본문을 사용한다. 지도·코스명·거리·예상 시간·위치·난이도·참고 사항은 동일하며 저장 여부와 러닝 상태에 따라 하단 동작을 바꾼다.
- 저장 전에는 이름 수정·저장·조건 재설정/재생성을 제공한다. GPX와 러닝은 명시적으로 저장한 뒤 사용할 수 있다.
- 저장 후에는 러닝 시작·GPX 내보내기·삭제를 제공한다. 저장 완료 즉시 같은 화면에서 상태를 전환한다.
- **미완주 저장 코스의 주 버튼은 ‘이 코스 러닝 이어하기’**로 표시한다.
  - 같은 코스가 진행 중이면 현재 러닝 화면으로 이동한다.
  - 일시정지·앱 중단 상태이면 기존 세션과 진행 상태를 복원하고 사용자가 명시적으로 재개한다.
  - 이미 중도 종료했다면 **‘이전 러닝은 종료되어 새 도전으로 시작합니다’**를 안내한 뒤 새 러닝 준비로 이동한다. 과거 거리·시간·완주 진행을 합산하거나 종료 기록을 다시 열지 않는다.
  - 다른 코스의 활성 러닝이 있으면 먼저 해당 러닝을 재개하거나 종료하도록 안내한다.
- 한 번도 시작하지 않았거나 최근 도전이 완주인 저장 코스의 버튼은 **‘이 코스 러닝 시작하기’**로 표시한다.
- 완주 기록 상세는 배지 최초 획득 여부에 따라 배지/트로피, 실제 거리·시간·지도·재도전·공유를 제공한다.
- 이름 수정은 편집 아이콘, 경사·추가 설명은 펼침 영역으로 정리한다. 모의 주행은 개발 경로로 옮긴다.
- 원본 Figma 자산과 기존 공통 컴포넌트를 재사용한다. 실제 주소가 없으면 좌표와 정확한 위치 설명을 사용하고, 예상 시간·난이도는 20km 작업의 계산 규칙을 유지한다.

### 4. 횟수 제한·DB·재가입

- 생성은 **성공한 계산 5회**, 저장은 **누적 15회**다. 자동 충전은 없으며 삭제해도 저장 사용량이 줄지 않는다.
- 홈 상단과 보관함은 **사용 횟수/총량**을 표시한다. 기존 자료·과거 사용은 제외하고 도입 이후부터 집계한다.
- 새 생성·저장은 온라인 가입 완료 회원만 가능하다. 기존 자료 열람·내보내기·저장 코스 러닝은 오프라인에서도 유지한다.
- Supabase에 정책 설정·사용자별 사용량·생성/저장 작업 원장을 둔다. 관리 화면에서 총량을 변경하면 기존 회원에게도 적용하되 사용량은 보존한다. 한도 하향 시 자료를 삭제하지 않고 추가 사용만 제한한다.
- 조회 인터페이스는 정책 버전·사용량·총량·사용 가능 상태를 반환한다. 로그인·앱 복귀·작업 완료 때 갱신하고 실행 직전 서버가 재검사한다.
- Cloud Run 계산 API에 회원 인증·작업 ID를 적용한다. v1/v2 계산 형식을 지원하며 인증 없는 계산과 서비스의 기기 계산 fallback을 차단한다.
- 생성은 예약 후 후보가 하나 이상 나오고 결과 수령이 확정될 때 1회 차감한다. 확정 전 취소·실패·0후보는 미차감이며, 응답 유실·재시도·취소 경합은 같은 작업 ID로 정리한다.
- 저장은 예약→로컬 준비→서버 확정→목록 노출 순서로 처리하고 중단 상태를 보존해 복구한다. 실패·중복 요청·이미 저장된 동일 코스·이름 변경·동기화 복원에는 추가 차감하지 않는다.
- 삭제한 코스를 사본에서 다시 저장하면 1회를 사용한다. 기존 저장 코스의 이어하기·새 도전은 생성·저장 횟수를 차감하지 않는다. 실제 러닝 기록 저장도 제한 대상이 아니다.
- 동기화 OFF여도 사용량은 서버에서 확인한다. 복수 기기에서 중복 차감·한도 초과가 발생하지 않도록 원자적으로 처리한다.
- 같은 소셜 계정으로 탈퇴 후 재가입해도 사용량을 유지한다. 서버에서 확인한 제공자·고유 식별자의 HMAC 값과 사용량만 무료 혜택 정책 운영 기간 동안 별도로 보관한다.
- 기존 프로필·코스·GPS 삭제 절차는 유지한다. 탈퇴 전에 진행 중 사용 작업을 정리하고, 탈퇴 안내와 개인정보 처리방침 변경 초안을 준비하되 게시하지 않는다.
- 연결된 소셜 로그인은 사용량을 공유하고, 연결되지 않은 계정을 이메일로 추정해 합치지 않는다.
- 소진 시 **‘추가 이용권 구매는 준비 중입니다’**를 안내한다. 결제·가격표·가짜 충전은 구현하지 않는다.
