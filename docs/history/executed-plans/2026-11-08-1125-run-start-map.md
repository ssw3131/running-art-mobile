# 러닝 시작 준비와 A7 지도 호환성 수정

- 기록 생성·실행 시작: 2026-11-08T11:25:30+09:00 (Asia/Seoul)
- 상태: 진행 중
- 기록 유형: 실행 시작 시 계획 작성
- 요청: 사용자가 러닝 시작 지연/실패·버튼 변화와 A7 MapLibre 오류를 함께 수정하도록 요청했다.

## 실행 전 계획

1. 기존 `codex/bottom-tab-spacing`의 사용자 화면 조절 변경을 보존한다. 준비 화면의 최신 위치·합류 경로를 시작 단계에 전달하고 권한 확인 후에도 유효성을 재확인한다. 정확도/나이 제한은 유지한다.
2. 추가 위치 확인은 시작에 적합한 위치가 올 때까지 기다리되 취소/시간 제한을 적용한다. 시작 준비 단계를 표시하고 버튼 위치를 안정화한다. 경로 재계산은 필요할 때만 수행한다.
3. MapLibre의 `samplerAnisotropy` 오류를 숨기지 않는다. 휴대폰 development/preview APK는 공식 OpenGL 렌더러로 구성하고, 기존 에뮬레이터 Vulkan 검증은 유지한다. 실제 APK의 렌더러를 메타데이터에 기록한다.
4. 회귀 검사·타입/린트·PR 검사와 휴대폰 APK 빌드/자료 유지 교체·실제 지도 표시를 확인한다. 사용자의 러닝 기록을 임의 시작/종료/초기화하지 않는다. 실제 야외 GPS 검증과 코드/실내 검증을 구분한다.
5. 실패와 미검증을 기록하고 main 반영·필수 검사 및 로컬 정리까지 이어간다. 네이티브 APK 빌드/설치가 막히면 구체적인 원인과 완료 범위를 남긴다.

## 최초 관찰

- A7 개발 APK215677929에서 Vulkan 지도를 만들 때 `Feature not available: samplerAnisotropy` 반복. `source must have tiles` 경고도 관찰했으나 정확한 소스는 미확정.
- 준비 위치와 시작 위치가 분리되어 있고 준비한 합류 경로가 시작으로 전달되지 않는다. 위치 수신 함수는 30초 이내 첫 좌표를 반환하지만 실제 시작은 5초/30m를 요구한다.
- 해당 오류가 러닝 시작 실패의 직접 원인이라는 증거는 아직 없다.

## 구현·로컬 검사

- 준비 화면의 최신 위치·경로를 getter로 전달해 권한 확인 후 재검증한다. 시작 버튼은 GPS readiness에 따라 토글하지 않고 준비 중/코스 로딩 때만 비활성화한다. 합류 준비 버튼도 위치를 유지한다.
- 추가 위치 조회는 5초/30m 조건을 만족할 때까지 기다리며 15초 제한과 취소 신호를 사용한다. 준비된 유효 경로는 재사용하고 위치가 바뀌면 다시 계산한다. 저장 직전 기존 검증은 유지한다.
- handset APK_KIND에만 공식 OpenGL variant를 적용하고 기본/에뮬레이터는 Vulkan을 유지한다. 산출물 metadata에 mapRenderer를 기록하고 생성 Gradle 속성도 확인한다.
- 관련 Node 회귀78개와 준비 UI2개·타입·린트 통과. 첫 Node 검사77/78은 기존 시험의 벽시계 불일치를 명시적으로 고쳤다. 초기 타입의 선택 인자 경고와 React ref 렌더 중 쓰기는 수정했다. Jest 첫 실행은 시스템 임시 캐시 rename EPERM으로 테스트0개 실행 실패했고 프로젝트 내부 캐시로 재실행해 통과했다. 실패 로그는 `.cache/run-map-*`에 보존한다.
- 앞선 홈/메뉴 시각 조절은 로컬에서 유지하며 이번 기능 수정 커밋과 APK 소스에 섞지 않는다. development APK는 이 PC Metro로 해당 로컬 UI 변경도 표시할 수 있다.
