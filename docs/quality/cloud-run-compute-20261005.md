# 실제 Cloud Run·휴대폰 계산 비교 — 2026-10-05

상태: **승인된 서울 1·2 CPU 총 66요청 시험과 정리 완료. 서버 계산 이전의 실익 확인, 제품 앱 연결은 별도 작업.** [원자료/집계](cloud-run-compute-20261005.json)·[내부 PC 비교](server-compute-20261005.md)·[실행 도구](../development/server-compute-benchmark.md).

## 판단

강남 자유 순환 5km의 반복 전체 응답 중앙값은 Cloud Run 1 CPU **6.40초**, 2 CPU **5.32초**였다. SM-A750N의 도로 준비 포함 **87.03초**와 비교하면 온라인 서버 계산을 검토할 실익이 크다. 단, 클라우드의 HTTP 클라이언트는 PC이며 실제 앱/휴대폰 네트워크를 연결한 사용성 시험은 아니다. 폰과 서버의 입력 캐시 단계도 다르므로 순수 CPU 성능비로 표시하지 않는다.

비용을 우선하는 초기 후보는 **Cloud Run 1 CPU/1GiB·인스턴스당 동시 계산 1개**다. 단일 요청 10초 이내라는 잠정 목표를 통과했다. 2 CPU는 이 표본에서 단일 요청이 약 17% 짧았지만, 할당 자원 단가가 두 배이고 4개 동시 요청의 실패도 완전히 없애지 못했다. 단일 경로 탐색 자체를 병렬화한 실험이 아니며 이 차이를 CPU 수만의 효과로 단정하지 않는다.

운영에는 인스턴스 자동 확장 상한과 요청 대기·재시도·취소 정책이 필요하다. **이번 시험의 최대 인스턴스 1 설정을 그대로 제품에 적용하지 않는다.** 1 CPU 복수 인스턴스와 2 CPU의 운영 비용/동시 처리 비교는 후속이다. Supabase는 로그인·개인 자료, R2는 도로 공급을 유지하는 방향을 제안한다. 오프라인 로컬 계산 유지 및 앱 연결은 아직 구현하지 않았다.

- 1 CPU 시험 23:43:14~23:45:42 KST, 2 CPU 23:47:58~23:50:04 KST. 각 표본 첫 관측 1회+반복 3회, 강남 동시 1/2/4개 각 3묶음으로 각 33요청.
- 도로 입력만 재사용하며 후보 결과는 캐시하지 않는다. 매 요청마다 검증·그래프·탐색을 실행한다.

‘묶음 종료’는 성공/실패 응답이 모두 돌아온 시간이다. 1 CPU의 4개 조건이 더 짧은 것은 요청 절반을 거절했기 때문이며 더 빠른 정상 처리로 해석하지 않는다. 2 CPU에서 4건 모두 성공한 두 묶음은 16.37/16.74초였고 나머지 묶음은 1건 실패했다.

총 **59건 HTTP 200·전체 결과 해시 일치, 7건 HTTP 429**. 1 CPU 27성공/6실패, 2 CPU 32성공/1실패이며 실패는 모두 4개 동시 요청 조건이다. 서버 로그 66건과 클라이언트 기록의 리비전별 상태 개수가 일치한다. 429 로그는 처리 가능한 인스턴스가 없다는 플랫폼 메시지다. 엔진 결과 불일치·500·타임아웃은 관측하지 않았다. 실패를 재요청해 성공값으로 덮지 않았다.

## 검증·정리

- 클라이언트 66건·서버 요청 로그 66건, 성공 59건의 전체 결과 해시, 세 표본·반복·동시성 행렬, 두 구성/동일 이미지, IAM 비공개, 런타임/기동 로그를 자동 대조했다. `node scripts/server-compute/analyze-hosted.mjs`로 집계를 재현한다.
- 검토 묶음 해시·제품 엔진 불변·로컬 57요청·기존 13응답 smoke를 `verify.mjs`로 다시 대조했다. 제품 코드 변경이 없어 전체 앱 테스트/APK를 반복하지 않았다. 새 분석 도구의 구문/린트도 통과했다.
- 시험 서비스 삭제, 정확한 이미지 digest/태그 삭제, 정확한 소스 zip 세대 삭제 후 서울 서비스 0개·시험 이미지 0개·활성 소스 파일 0개를 확인했다.
- 빈 Artifact Registry 저장소·소스 버킷, 빌드 이력/로그, 활성화한 API는 남아 있다. 소스 버킷 기본 soft delete는 7일이므로 삭제한 작은 zip의 보존 비용이 미량 남을 수 있다. 운영 서버가 계속 실행 중인 상태는 아니다.
- 제품 앱·APK·폰 자료·Supabase/R2 설정·배포 변경 없음. SDK 인증은 Git 제외 작업 전용 설정에만 유지하며 일회용 인증 코드를 공유 문서에 저장하지 않았다.

실제 앱 연결, 휴대폰 인터넷 왕복/불안정 통신, 장시간 부하·자동 확장·콜드 스타트, 임의 사용자 입력·인증/취소·오프라인 전환은 이 고정 표본 비교 다음 단계다.
