## 2026-10-01 일반 계산의 R2 공급 연결

일반 계산·캐시 검증 화면을 같은 영구 캐시와 R2 개발용 공급에 연결했다. 기존 도로 API 기본값·환경 변수 사용·대체 공급 호출을 제거했다. 세 표본 위치 선택과 저장 자료 우선·명시적 갱신·오프라인 모드를 제공한다. 표본 위치를 직접 선택하면 지도 서비스가 응답하지 않아도 도로 계산이 가능하다.

`channel.ts`에서 HTTPS 현재 포인터·불변 경로·버전·매니페스트 해시를 검사한다. Expo 스트리밍 전송으로 MIME·Content-Length·실제 크기를 확인하고 리디렉션·압축 전송 변환을 거절한다. 저장 목록으로 누락 파일을 받을 때도 원본 매니페스트 SHA-256을 사용한다. 전체 조회 제한은 65초이며 취소·실패는 부분 저장과 늦은 결과를 막는다.

- `npm test`: **133개 통과**. 새 공급 10개 검사에서 빈 캐시·재열기·손상·불법 경로·해시·스트림 초과/누락·응답 정지·중간 취소·갱신 실패·명시적 재시도를 확인했다. 기존 API 테스트는 새 계약 검사로 교체했고 위치/세션·알고리즘 원본·저장 코스·GPX 회귀는 유지했다.
- `dev.ps1 check`: 타입·린트 통과.
- `node scripts/road-data/channel-rehearse.mjs`: 실제 공개 R2만 허용하고 다른 모든 공급자 주소를 거절했다. 포인터 1·목록 1·타일 23, 총 **25회** 요청으로 1,205,306바이트를 저장했다. 세 지역 모두 분할 전 원본의 전체 입력·그래프와 일치했다.
- DB를 닫고 별도 프로세스에서 모든 네트워크 호출을 금지했다. 세 지역 전체 입력·그래프가 다시 일치했고 **HTTP 0회**였다.

## 2026-09-30 최초 구현 당시 결과

당시 서버 준비와 휴대폰 연결을 사용자 요청으로 보류하고 저장 모듈·로컬 검증 화면만 먼저 구현했다. 아래는 그 당시 검증 범위이며 최신 공급 연결은 위 후속 기록을 따른다.

## 실제 SQLite 검사

Node 24.21.0의 `node:sqlite`를 사용한다. SQL 호출을 가짜 객체로 성공 처리하지 않고 실제 BLOB·트랜잭션·파일 DB를 실행한다. 13개 신규 검사를 포함한 전체 **109개 테스트가 통과**했다.

- 전체 입력 캐시 적중·오프라인 네트워크 호출 0회, 다른 공급자 격리·부분 영역 거부.
- gzip·매니페스트 손상 검출과 검증된 재수신으로 복구, 다른 버전 파일 혼합 거부.
- 다운로드 중·대기열 취소와 SQL 쓰기 도중 취소의 롤백.
- SQL trigger로 쓰기 실패를 주입해 이전 포인터·파일·메타데이터 보존 확인. 실제 기기의 디스크를 채운 시험은 아니다.
- 7일 기본 만료 정책의 시계 주입 검사, 적중으로 확인 시각이 늘어나지 않음, 갱신 실패 시 검증된 과거 자료 표시.
- 동일 버전 다른 격자 LRU 정리·현재 영역 보호·용량 초과 시 실패, 조회 중 비우기·동시 요청 순서.
- 실제 파일 DB를 닫은 뒤 별도 프로세스가 트랜잭션 안에서 파일을 손상시키고 포인터를 삭제한 채 종료. 다시 열면 미완료 변경이 롤백되고 이전 입력을 복원함.
- 높은 DB 스키마를 삭제하지 않고 거부, 로컬 다운로드 헤더 제한·본문 응답 중 시간 초과·취소.

취소 보장은 트랜잭션의 마지막 취소 검사 이전까지다. 이미 커밋된 저장은 늦은 취소로 되돌리지 않으며 화면에 늦은 결과를 내보내지 않는다. 캐시 한도는 저장 BLOB·목록 바이트 기준이고 SQLite 파일/WAL 또는 객체 메모리 한도가 아니다.

## 실제 서울·부산·경계 표본

`npm run roads:cache-rehearse`는 실제 가공한 0.02도 표본을 로컬 HTTP로 받아 **앱과 같은 fflate·SHA-256 codec**으로 검증한다. 첫 프로세스에서 매니페스트 1회·타일 23회, 총 24회 요청으로 DB를 채운다. 파일·목록 합계는 **1,205,306바이트**, 기본 한도는 67,108,864바이트다.

HTTP 서버와 DB 연결을 닫은 뒤 새 Node 프로세스를 실행했다. 세 지역을 저장 DB에서만 읽었으며 다운로드 함수 호출은 **0회**였다. 분할 전 reference와 전체 입력·그래프를 깊은 비교로 대조했다.

| 지역 | 파일 수 | 도로 way | 노드 | 간선 | 재시작 후 새 다운로드 | 전체 입력·그래프 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 서울 강남 | 9 | 3,454 | 13,614 | 15,363 | 0 | 일치 |
| 부산 시청 | 6 | 2,008 | 9,181 | 9,972 | 0 | 일치 |
| 구로·광명 경계 | 8 | 2,929 | 11,189 | 12,384 | 0 | 일치 |

입력·매니페스트 해시는 [결과 JSON](road-cache-report.json)에 보존했다. DB는 `build/road-cache/rehearsal-*/cache.db`, 원본 보고서는 `build/road-cache/rehearsal-report.json`에 있으며 Git에서 제외한다. 코스 엔진은 수정하지 않았고 기존 원본 결과 회귀도 전체 109개 검사에 포함됐다.

## 앱 코드와 번들

- `dev.ps1 check`: TypeScript·ESLint 통과. 새 화면에 맞춰 설치된 Expo CLI의 typed-route 생성기를 실행했다.
- `npm run export:android`: 1,395개 모듈, Android JavaScript/Hermes 번들 생성 통과. `entry-298dd5542123d7c84dd43f26733934cd.hbc`, 약 4.7MB.

이번에는 새 APK를 만들거나 기기에 설치하지 않았다. Expo 네이티브 SQLite bridge의 BLOB·실기기 프로세스 종료 복원·화면 동작·취소 지연·실제 저장 공간 부족·메모리·배터리는 미검증이다. Android export 성공을 기기 실행 성공으로 보고하지 않는다. PC 로컬 HTTP 결과는 R2/CDN 성능이나 운영 다운로드 제한 검증이 아니다.

일반 코스 계산의 새 공급 연결·HTTPS 현재 포인터 검증·다운로드 중 크기 제한·기존 API 제거, 전국 자료, 배경 지도 오프라인 표시는 후속이다. 기존에 준비한 R2 배포 도구는 유지하며 서버·휴대폰·CI/CD를 자동 재개하지 않는다.
