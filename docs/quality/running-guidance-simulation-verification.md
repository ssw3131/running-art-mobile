### 재현과 수정

- 기존 설치본 `3d2ac0a5…7b6b4367`에서 저장 코스 5.60km를 시작→4초 진행→일시정지→재개→Home으로 전환했다. 11:02:03.705 Headless JS 시작과 최초 checkpoint를 확인했으나 11:02:28.714 `heartbeat_timeout`으로 서비스가 종료됐다. 전날 실패를 같은 휴대폰에서 재현했다.
- 확인한 고장 지점은 재개 후 백그라운드의 JS 프레임 타이머 갱신 중단이다. React Native 내부의 특정 결함까지 확정한 것은 아니다. 화면 프레임에 의존하는 `setInterval`을 제거하고 Android 서비스의 `nextTick(token)`을 순서대로 기다리도록 바꿨다. main Handler의 250ms 응답·서비스 종료 시 대기 해제·이전 세션 응답 무시·완주 후 7초 정리를 같은 흐름에 넣었으며 하트비트 감시는 유지했다.
- 실제 runtime와 session/engine을 사용하고 JS 프레임 타이머를 금지한 회귀 검사 4개를 추가했다. 재개 후 진행, 이전 작업 응답/토큰 무시, 서비스 손실, 알림 종료, 완주 후 정리를 확인했다. 격리한 설치 기준 코드에서 전체 **243개**, 이 안내 수정의 개발 소스 통합 검증에서 **284개** 검사와 타입·린트를 통과했다. 중간 통합은 278개였다. 이후 별도 계정 개발로 늘어난 전체 검사 수와 이 검증 시점의 결과를 구분한다.
- Android release 빌드 성공(재시도 10분 47초). 최초 빌드는 Kotlin daemon 연결 실패와 대체 컴파일 지연으로 해당 격리 빌드만 중지했다. 기존 의존성을 사용한 `--offline --max-workers=2 -Pkotlin.compiler.execution.strategy=in-process` 재시도에서 성공했다. 의존성 버전은 바꾸지 않았다.
