## 구현과 실제 배포

- 앱은 계산 중심/도형/조건만 `POST /v1/routes`에 전송한다. 서버 성공 시 휴대폰 그래프/탐색을 실행하지 않는다. 비로그인 서버 요청, 실패 시 기기 전환, 오프라인·기기 저장·합성 진단의 로컬 경로를 유지한다.
- 서버는 공개 전국 도로를 다운로드·해시 검증하고 64MiB 메모리 SQLite에 캐시한다. 별도 권한 없는 실행 계정, 임의 외부 URL/도로 입력 금지, 입력·응답·시간·동시 계산 제한을 적용했다.
- 실제 서비스 `runpen-route-compute`, `asia-northeast3`, 프로젝트 `running-art-mobile`. 리비전 `runpen-route-compute-00001-96r`, 트래픽 100%. 1 CPU/1GiB, 동시 1, 최소 0, 서비스와 리비전 최대 2, 요청 기반 CPU·부스트 OFF·70초 제한을 실제 describe에서 확인했다.
- 이미지 digest `sha256:44804338f7dfc4efa322957400d88c5af7b165ec4943caae147639db833175ff`.
- 주소: `https://runpen-route-compute-125644906792.asia-northeast3.run.app`. 공개 호출 가능. Supabase 토큰·키를 서버에 배포하지 않았다.

## 자동 검사와 실제 계산

- 전체 Node 검사 **368/368 통과**, 앱 TypeScript/ESLint 통과. 관련 신규 8개 검사에는 계약 위변조/크기·guest·서버 타임아웃/취소·늦은 응답 무시·장애 전환·HTTP 과부하·실제 CPU 작업자 강제 종료/복구·전국 도로 캐시를 포함한다.
- 공개 R2를 읽는 로컬 서버의 강남 5km·부산 3km·강남 직접 도형과 실제 Cloud Run의 같은 세 입력 모두 이전 고정 도로 입력을 동일 엔진으로 계산한 **전체 결과 SHA-256이 일치**했다. 후보마다 좌표·순서·도로 참조까지 포함한 JSON을 대조한다. 잘못된 입력은 실제 HTTP 400이다.

| 사례 | 로컬 HTTP | Cloud Run HTTP | Cloud Run 도로 / 계산 | 후보 |
| --- | ---: | ---: | ---: | ---: |
| 강남 하트 5km | 9.01초 | 14.21초 | 2.05 / 10.07초 | 5 |
| 부산 하트 3km | 3.92초 | 6.55초 | 1.57 / 4.38초 | 5 |
| 강남 직접 도형 5km | 3.19초 | 7.60초 | 0.24 / 7.01초 | 5 |

이는 기능 확인용 단회 측정이다. 강남·부산 첫 요청은 도로 다운로드를 포함하고 직접 도형은 강남 캐시를 재사용했다. 기존 2026-10-05의 고정 입력 warm 반복 벤치마크, 실제 휴대폰 HTTP 성능, 엄밀한 0→1 cold start 측정과 구분한다. 10초 미만을 보장하지 않는다.

## 동시 요청과 한계

서울 서비스에 동시 4개 강남 요청을 보낸 재검증에서 **3건 200·1건 429**, 성공한 세 결과는 모두 같은 전체 해시였다. 성공 응답은 9.20~17.17초이고 네 요청 종료까지 17.41초였다. 초기 수집기는 Cloud Run 프록시의 `Rate exceeded.` 일반 텍스트를 JSON으로 읽다가 실패했다. 수집기만 보완했으며 앱은 HTTP 상태를 먼저 검사하므로 일반 텍스트 429도 기기 전환 경로다.

앱 시험 전 서버 접근 로그 집계는 계산 11건 중 8건 200·3건 429, 잘못된 입력 1건 400이다. 첫 동시 시험의 응답 본문 전체를 보관하지 못했으므로 그 성공 2건을 해시 대조 완료 건수에 포함하지 않는다. 429를 성공·단순 지연으로 숨기지 않는다. 최대 2개는 공개 출시 부하를 해결한 설정이 아니며 폭주 시 여전히 기기 전환이 발생한다.

최대 인스턴스 제한은 강제 지출 차단이 아니다. 계산 서비스/이미지/빌드 소스는 이번에 실제 앱 연결용으로 유지한다. 이전 벤치마크 서비스 정리 기록과 구분한다. 정확한 이번 청구 비용은 확인하지 않았다.

## APK·Android

기존 앱 ID/서명으로 서버 URL이 포함된 release APK 빌드가 통과했다. 물리 휴대폰은 연결되어 있지 않아 설치하지 않았다.

- 파일: `build/install/running-art-0.1.0-20261010-cloud-run.apk`, 114,289,247바이트, arm64/x86_64.
- SHA-256: `2e626a809b754818bc0c757bcabceb7b9a333da734bb243a81d1a3d4e4387410`.
- 서명 인증서 SHA-256: `fac61745dc0903786fb9ede62a962b399f7348f0bb6f899b8332667591033b9c`.
- Hermes 번들에 실제 Cloud Run URL 포함을 확인했다. 기존 `RunningArt_UI_QA` API 36에 `adb install -r` 성공, 새 계산 선택/설명 UI 표시와 강남 공개 표본 선택을 확인했다. 사용자 코스/러닝을 생성·수정·삭제하지 않는다.

첫 빌드는 Gradle이 `.cache` 아래 Google 인증 디렉터리를 입력으로 스캔하다 차단됐다. Metro 제외와 별개인 Gradle 입력에도 `.cache/.tools/.git/server` 제외를 넣는 Expo 플러그인을 추가했고 prebuild로 반영했다. 이어 PC 네이티브 메모리 부족으로 JVM이 종료돼 이번 QA 에뮬레이터를 종료하고 단일 작업·낮춘 JVM 힙으로 다시 빌드했다. 최종 빌드/화면 결과는 아래에 기록한다.

Expo doctor 재검증은 **20/21 통과**다. 남은 한 항목은 기존 고정 패키지 6개의 최신 권장 패치 차이(`expo`, `expo-constants`, `expo-image-manipulator`, `expo-linking`, `expo-router`, `expo-sqlite`)다. 이번 작업에서 npm 의존성/잠금 파일은 변경하지 않았다. 최초 doctor는 검사 자식 Node 종료로 해당 항목을 확인하지 못했으며 재실행으로 경고 내용을 확인했다. 타입·린트·테스트·release는 통과했고 SDK 패치 업그레이드는 별도 후속이다.

API 36 QA 에뮬레이터에서 동일 강남 5km 하트를 계산했다. 비로그인 공개 HTTP 경로이며 요청에 계정 토큰을 넣지 않는다.

세 결과의 노드/탐색 통계가 같고 후보 점수 5개는 모두 허용 오차 0.000001 이내다. Native Hermes와 서버 Node 사이의 극소수 부동소수점 차이는 구분하며 네이티브 결과의 전체 JSON 해시 동일을 주장하지 않는다. 서버 계산 중 취소 버튼으로 취소 상태를 확인했고, 취소 후 새 계산도 정상 완료됐다. 기기 성능 비교용 반복 시험이 아니라 기능 확인이며 물리 휴대폰 수치로 해석하지 않는다.

네트워크 설정은 시험 전 Wi-Fi/데이터 1/1로 복구·확인했다. 새 QA 도우미와 화면 덤프 임시 파일을 정리하고 이번에 실행한 에뮬레이터를 종료했다. 사용자 코스/러닝 저장·계정 조작은 하지 않았다. 로컬 증거는 `.cache/route-compute-ui/`, 공유 가능한 수치·해시는 [JSON 보고서](cloud-run-routes-20261010.json)에 있다.
