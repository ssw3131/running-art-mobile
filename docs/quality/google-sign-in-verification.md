검증일: 2026-10-03 (Asia/Seoul). **실제 SM-S942N에서 Google 로그인 → 앱 복귀 → 계정 표시 → 앱 재시작 후 유지 → 로그아웃의 다섯 단계 목표를 완료했다.** 초기에는 휴대폰을 후속으로 미뤘으나 사용자가 같은 날 연결을 알려 재개했다. 아래 PC·에뮬레이터 결과와 실제 휴대폰 결과를 구분한다.

## 실제 휴대폰 후속 — 목표 완료

- 기기: SM-S942N·Android 16. 2026-10-03 **10:49:20 KST**에 준비한 APK를 `install -r --no-streaming`으로 업데이트했다. 앱 ID·UID·버전·최초 설치 시각(2026-09-27 16:29:39 KST)·데이터 경로를 유지했다.
- 휴대폰 Google 계정 선택과 이름/프로필 사진/이메일의 기본 범위로 인증했다. Supabase의 실제 코드 교환 뒤 시스템 브라우저에서 앱으로 돌아와 이름·이메일·로그인 성공 안내·로그아웃 버튼을 표시했다.
- 앱을 강제 종료하고 COLD 실행했다. PID가 바뀌었고 내 계정의 이름/이메일이 처음 로그인과 정확히 일치했다. 로컬 증거를 비교해 같은 계정임을 확인했으며 개인 값은 문서에 남기지 않는다.
- **이 기기에서 로그아웃** 뒤 로그아웃 성공 안내와 로그인 버튼을 확인했다. 다시 강제 종료·COLD 실행한 뒤에도 계정 정보가 나타나지 않았다.
- 같은 Google 계정으로 재로그인·앱 복귀도 성공했다. 마지막으로 다시 로그아웃했고 최종 휴대폰은 **내 계정의 로그아웃 상태**다.
- 사용자 DB 네 테이블은 휴대폰 안에서 읽기 전용으로 순회해 개수·SHA-256만 비교했다. 전후 모든 해시가 동일하며 **코스 1개·메모 1개·러닝 2건·GPS 209좌표**를 보존했다. 원문 코스·메모·위치 기록은 PC로 추출하지 않았다.
- 임시 개수/해시 검사 APK `com.runningart.authdigest`와 UI 도우미·덤프 파일을 기기에서 제거했다. 도우미 제거 후 앱의 COLD 실행·로그아웃 화면을 다시 확인했다. 휴대폰 네트워크·보안 설정은 변경하지 않았다.
- 설치된 `base.apk` SHA-256이 아래 배포용 파일과 동일하다. 이번 휴대폰 검증에서는 앱 소스·의존성·APK를 추가 변경하거나 재빌드하지 않았다.

로컬 증거는 Git 제외 `.cache/auth-phone/`의 로그인/복원/로그아웃/재로그인 UI XML·PNG, 전후 PID·설치 정보, 데이터 개수/해시 결과와 설치본 SHA-256에 보관한다. 토큰·인증 코드·원문 사용자 DB는 증거 파일로 추출하지 않았다.

## 구현과 자동 검사

- 홈 → 내 계정 → Google 로그인, 시스템 브라우저, 정확한 `runningart://auth/callback` 수신, 이름/이메일, 세션 저장·복원·갱신·이 기기 로그아웃을 구현했다.
- 공식 Supabase SDK 2.117.2의 PKCE를 사용한다. Expo 네이티브 난수·SHA-256을 연결하고 브라우저를 열기 전 `s256`을 검사한다. 세션·요청 정보는 SecureStore에 분할·참조 교체 방식으로 저장하며 일반 사용자 SQLite는 변경하지 않는다.
- `node --test tests/auth*.test.mjs`: **14/14 통과**. 공개 설정/비밀 키 거부, 정확한 콜백, 취소/재시도, 중복 이벤트, 만료/콜드 스타트, 오류 원문 비노출, 로컬/서버 로그아웃 구분, Unicode 대형 세션, 중단된 쓰기 보존·순차화·삭제를 검사했다.
- 설치된 실제 SDK와 보안 저장 어댑터를 함께 사용하는 계약 검사는 S256 challenge/verifier 일치, 코드 교환, 새 클라이언트에서 세션 복원, refresh token 교체, local scope 로그아웃·저장값 제거를 확인했다. **HTTP 응답은 테스트 fixture이며 실제 Google 계정 성공의 증거가 아니다.**
- `npm test`: **202/202 통과**. 기존 코스·러닝·도로·알고리즘 검사 포함.
- 최종 APK 빌드 종료 후 `npm run check`: **타입·린트 통과**. 앞선 병렬 검사 중 Expo의 Windows 라우트 생성물이 `/runs` 타입을 덮어쓴 오류는 최종 빌드 후 순차 재생성·검사에서 해소됐다.
- `npm run doctor`: **20/21**. 네트워크 허용 재검사에서 Expo 구성·React Native Directory 확인은 통과했다. 기존 고정 버전 Expo 57.0.25·constants 57.0.19·router 57.0.23에 대해 각각 57.0.26·57.0.20·57.0.24 패치 권고가 남는다. 이번 인증 작업에서 기존 패키지 버전은 바꾸지 않았다.
- 실제 개발 프로젝트에 공개 키로 `/auth/v1/settings`를 요청해 **HTTP 200·Google enabled=true**를 확인했다. 키 값은 Git 제외 `.env.local`에만 설정했고 Google Client Secret·Supabase secret/service_role 키는 앱에 연결하지 않았다.
