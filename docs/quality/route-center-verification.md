# 지도 중심·주변 도로 조회 검증

검증일: 2026-09-27 (Asia/Seoul). 사용자 요청 범위는 에뮬레이터 검증과 설치용 APK 생성이다. 실제 휴대폰 설치·GPS 검증은 수행하지 않는다.

## 자동 검사

- `npm test`: 69개 통과(기존 58개 + 지도 중심/도로 11개).
- 마지막 보완 후 `node --test tests/route-center-road.test.mjs`: 11개 재통과. 좌표 순서, 수동 선택 후 늦은 GPS, 권한 거부, 전체 반경 캐시 포함·만료, 요청 좌표와 OSM ID 보존, 손상·부분 응답·범위 부족·429·시간 초과, 취소된 다운로드/계산의 늦은 결과 차단, 요청 시작 좌표 고정, 조회/계산/전체 시간 분리를 확인했다.
- `npm run check`: 타입·린트 통과. 기존 엔진·원본 기준 결과는 변경하지 않았다.
- 기존 공개 API의 광화문 2km 요청은 HTTP 200, 11,266개 요소, `X-Road-Area` 범위를 반환했다. 지도 공급자 키·개인 GPS 좌표를 로그에 기록하지 않았다.

## Android 개발 앱 + 배포용 JavaScript

Pixel 7 x86_64 / Android 16.1 에뮬레이터, Metro 8081의 `--no-dev --minify` 번들로 확인했다. 모든 좌표는 서울 공공장소의 모의 위치이며 실제 휴대폰 위치가 아니다.

- 서울 OSM 진입 후 모의 GPS `37.56650, 126.97800`으로 지도 중심·파란 위치 점이 이동했다.
- 지도 드래그 후 중심이 `37.56650, 126.98911`로 바뀌었다. 완료 화면의 계산 기준도 동일했고 실제 도로를 따르는 후보가 표시됐다.
- 완료 화면에 도로 조회·코스 계산·전체 시간, 캐시 사용, OSM 자료 날짜가 표시됐다. 동적 위치에 고정 원본 일치 메시지를 표시하지 않는다.
- 완료 후 지도 이동 시 이전 코스·시간·후보가 지워졌다. 조회를 시작한 직후 다시 지도를 이동했을 때 취소됐고, 시간이 지난 뒤에도 이전 결과가 나타나지 않았다.
- 새 중심 `37.56650, 127.01344`로 재시작해 새 도로와 그래프를 구성하고 후보 5개를 얻었다. 중심 A의 20,505노드/21,971구간과 달리 중심 B는 21,721노드/23,998구간이었다.

첫 관측은 최종 응답 검증 보완 전, 나머지는 보완 후 코드다. 공개 API·에뮬레이터와 빌드 작업이 있는 PC의 관측이므로 통제된 성능 비교가 아니다. 과거 고정 서울 하트 5km 휴대폰 결과와 직접 비교하지 않는다.

로컬 증거는 Git 제외 경로 `.cache/map-center-qa/`의 `final-location`, `final-panned`, `timing-result`, `moved-after-result`, `moved-during-request`, `after-cancel`, `second-center-metrics.log`에 있다.

## 설치 파일

- 최종 빌드: `:app:assembleRelease --max-workers=2 -PreactNativeArchitectures=arm64-v8a,x86_64`, 6분 8초 성공. 두 ABI를 포함해 휴대폰과 에뮬레이터에 같은 APK를 사용할 수 있다.
- 전달 파일: `build/install/running-art-0.1.0-20260927.apk`, **95,414,459바이트**. 동일 폴더에 설치 안내와 SHA-256 파일을 만들었다.
- 패키지 `com.runningart.mobile.dev`, 버전 `0.1.0`/코드 1, minSdk 24/targetSdk 36. 디버그 플래그 없음, 내장 Hermes 바이트코드 3,940,728바이트, 기존 테스트 앱과 서명 일치.
- SHA-256: `a933cf5c521e693ab89316981dc7a8ecaa935ec1f89c64c6a9690ae603c8358c`.
- 에뮬레이터에 `install -r --no-streaming`으로 업데이트 성공. 기존 앱을 삭제하지 않았다. 실제 설치된 `base.apk`의 SHA-256도 전달 파일과 정확히 같다.
- 에뮬레이터의 기존 Metro 포트 전달 8081·8083을 제거해 빈 목록을 확인했다. 강제 종료 후 새 PID 6484로 실행해 개발 서버 선택 화면 없이 홈·코스 테스트가 열렸다.
- 릴리스 앱에서 모의 현재 위치 `37.56650, 126.97800` → 지도 이동 후 `37.56650, 126.98910`을 확인했다. 하트 3km 실제 다운로드·계산으로 후보 5개를 얻었고 결과 기준 좌표가 선택한 중심과 일치했다.
- 릴리스 1회 관측: **조회 6.651초 / 계산 46.703초 / 전체 53.354초**, 20,503노드·21,965구간. 최대 연속 계산 34.201ms, 타이머 최대 지연 123.619ms. 드래그 좌표가 개발 앱 관측과 미세하게 달라 원본 고정 성능 비교로 사용하지 않는다.
- 완료 화면에서 세 시간·자료 출처·계산 기준을 확인했다. 2순위 후보 선택 상태가 바뀌어도 지도 중심은 유지됐다. 에뮬레이터는 1순위 결과와 시간 표시 화면으로 남겼다.

최종 로컬 증거: `.cache/map-center-qa/apk-verification.json`, `release-universal.log`, `release-home`, `release-location`, `release-panned`, `release-result`, `release-selected`, `release-delivery`, `release-final-metrics.log`. 빌드 파일과 증거는 Git에서 제외한다.
