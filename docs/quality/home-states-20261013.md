## 범위

Figma MAIN-1/2/3의 초기·활성 세션 복귀·실제 종료 기록 홈이다. 기존 앱의 데이터/계정/동기화/러닝 복원과 공통 UI를 재사용한다. 하트/물고기 선택, 최근 기록 상세/보관함, 시작일 기준 기기 달력 월 거리, 현재 계정만의 실제 좌표 미리보기를 연결한다. 홈은 GPS를 시작하거나 중단 기록을 자동 재개하지 않는다.

운영 약관/회원 DB 적용·휴대폰 설치, 다일 도전(S4)·연속일/배지(S5)·상품(S7)은 이번 범위에 포함하지 않는다. 추천 공급이 없는 예시 코스/거리/횟수도 만들지 않는다.

## 발견·수정과 원본 보존

1. 제한 환경의 UI/Python 검사는 Windows 임시 폴더 접근 오류로 실패했다. 프로젝트 임시 폴더를 사용한 권한 있는 재실행은 통과했다.
2. 첫 release 실제 초기 화면에서 주 버튼이 아래로 밀리는 것을 확인해 본문 스크롤 밖에 고정했다. 작은 화면/큰 글씨에서는 내용 스크롤로 모든 항목에 접근한다.
3. 첫 Windows `test-results/home-android-36/`와 첫 CI API 36(아티팩트 `11790828269`)은 홈의 물고기 전달 후 생성 화면의 가로 목록을 세로 스크롤만으로 찾다가 실패했다. Windows `home-android-36-v2`에서는 가로 스와이프가 시스템 뒤로 제스처에 걸렸다. 가로 목록 내부 20~80% 구간을 사용하도록 시험 동작을 수정했고 정리 전 실패 화면을 보존한다.
4. Windows `home-android-diagnostic`의 홈 단독 동작·자료 보존·정리는 통과했지만 화면 검토에서 실제 경로 미리보기가 비어 있음을 발견했다. 따라서 이 실행을 홈 완료 근거로 삼지 않는다. 초기 진단 옵션 추가 때 보고서 mode가 full로 기록된 오류도 있어, 실제 실행 명령 `--home-only`와 한 단계 결과를 기준으로 해석한다. 이후 보고서에는 home-only를 명시한다.
5. 설치된 `expo-image` Android data-URL 로더가 모두 Base64로 디코딩하는 것을 코드로 확인했다. 홈 동적 SVG를 Base64로 수정하고 기존 transitive `base64-js@1.5.1`을 명시 의존성으로 고정했다. 원본 SVG 아이콘은 그대로 유지한다. 렌더링 오류 시 안내를 추가하고 최근 기록 카드를 Figma의 작은 카드 비율로 제한했다.
6. UI 노드 존재만으로 경로 렌더링을 통과시키지 않는다. 새 검사는 실제 PNG의 경로 미리보기 안에서 주황색 선 픽셀을 확인한다. 이전 빈 화면에서 0픽셀로 실패하는 것을 확인했다. 수정 APK 검증은 진행 중이다.
7. 렌더링 수정 후 홈 로직 7개·타입/린트 통과. Gradle/Metro와 동시에 실행한 UI 검사는 첫 초기 상태 검사에서 10초 제한을 넘어 실패(나머지 4개 통과)했으며 제한을 늘리지 않고 빌드 종료 후 독립 재검증한다. `expo-doctor`는 21개 중 20개 통과, 기존 고정 Expo 패치 11개의 최신 권고 버전 차이를 보고했다. 이번 Base64 패키지의 중복/네이티브 호환 오류는 없으며 관련 없는 SDK 일괄 업데이트는 시행하지 않는다.

최초 실패 보고서·스크린샷을 덮어쓰지 않고 별도 실행 디렉터리를 사용한다. 홈 시험은 전용 에뮬레이터에만 합성 기록을 넣고 finally에서 삭제한 뒤 기존 모든 테이블 내용 해시를 대조한다. 연결된 물리 A7은 조작하지 않았다.
