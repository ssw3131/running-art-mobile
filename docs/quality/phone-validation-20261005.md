# 휴대폰 후속 검증 1~4 — 2026-10-05

사용자 요청 “1~4 검증해보자”에 따라 SM-S942N·Android 16의 기존 `20261004-custom-drawing.apk`에서 진행했다. 새 앱 빌드·설치나 서버 스키마·배포 변경은 없다. 임시 검사 도우미는 같은 서명으로 설치했고 인증 저장소를 읽지 않는다. 기존 자료 사본은 휴대폰 내부에만 보관하고 복사마다 fsync·SHA-256을 대조한다.

## 1. 기존 자료·계정

시작 시 코스 **2개**, 완료 러닝 **2건·209좌표**, 메모 **1개**였다. 과거 문서의 코스 1개보다 늘어난 현재 자료 전체를 기준으로 삼았다. Google 로그인 유지, 동기화 켜짐·대기 0건을 확인했다. 기존 GPS와 계정 인증 정보를 PC로 내보내거나 공개하지 않았다.

해시는 코스/러닝의 사용자 내용·소유자·연결 코스 사본과 전체 좌표·메모를 정렬해 계산했다. 정상 동기화로 바뀔 수 있는 원격 버전·dirty·mutation ID는 사용자 내용 비교에서 제외했다. 종료된 러닝의 실행 중 안내 체크포인트·옵션은 서버 복원 계약상 재구성 대상이므로 이 대조에 포함하지 않는다.

## 2. 직접 그리기

- ADB가 실제 휴대폰 터치 이벤트를 주입해 빈 입력 적용 차단, 열린 선 거절, 지우기, 사각형 입력·정리 미리보기·적용을 확인했다.
- 하트로 전환 후 직접 그리기를 다시 열면 기존 도형이 유지됐다. 삼각형 편집을 취소한 뒤 저장된 원형에 사각형 모서리 4개가 남는 것을 확인했다.
- 공개 서울 강남 중심을 명시적으로 선택해 실제 OSM 도로 후보 5개를 계산했다. 선택한 v3 코스는 약 **3.01km·91점**, 원형 11점·도로 경로 131점·도로 참조 130개다.
- `QA phone v3` 이름으로 앱에서 저장하고 중복 저장 방지·앱 완전 종료 후 상세 재열기를 확인했다.
- 갱신 중인 화면의 취소 버튼을 UIAutomator로 직접 눌러 계산 취소와 취소 상태 표시를 확인했다. 사람의 손가락 사용감이나 야외 이동을 시험한 것은 아니다.

## 3. 링크 공유

이번에 만든 공개 좌표 합성 러닝(189좌표·2.25km)만 앱에서 공유했다. Android 시스템 공유 선택창에서 실제 발급 링크를 확인하고 수신자를 선택하지 않은 채 닫았다. 앱에는 기존 링크가 유지됐다.

휴대폰이 발급한 링크를 Codex 브라우저에서 열어 제목·거리·시간, 실제 궤적·계획 코스·원래 도형의 세 경로, 각 표시/숨김·전체 경로 보기를 확인했다. 전체 표시·원래 도형만 표시·전체 숨김 화면을 캡처해 시각 대조했다. 앱의 **공유 중단** 후 웹을 새로 열면 “이 경로를 볼 수 없어요”가 표시됐다. 다른 사람에게 링크를 전송하지 않았다. 브라우저 표시는 PC의 Codex 브라우저에서 검증했으며 휴대폰 브라우저별 호환성 시험으로 확대 해석하지 않는다.

## 4. 실제 서버 동기화·복원

- 기존 공개 도로 fixture의 코스 JSON v2와 휴대폰에서 실제 그린 v3, 각 코스에 연결된 합성 러닝 2건을 사용했다. 러닝은 앱의 저장 모듈로 PC에서 합성한 뒤 검사 도우미로 시험 ID만 기기에 추가했다. 실제 야외 GPS 기록이 아니다.
- Wi-Fi·모바일 데이터를 일시 중지하고 새 자료 3건이 대기하는 것을 확인했다. 앱에서 v3 코스 이름을 오프라인 수정한 뒤 4건 대기·앱 강제 종료/재시작 후 대기 유지를 확인했다.
- 원래 네트워크 상태로 복구하고 앱에서 재시도해 **전송 4건·대기 0건·충돌 0건**을 확인했다. v2 코스/두 러닝은 서버 버전 1, v3 코스 수정은 버전 2가 됐다.
- 동기화 완료 DB도 휴대폰 내부에 사본으로 보관한 뒤 실제 빈 SQLite(코스/러닝/좌표/메모 각각 0건)에서 같은 계정으로 동기화를 켰다.
- **복원 8건**: 코스 4개·러닝 4건·455좌표. 업로드 전→업로드 후→서버에서 새로 내려받은 자료의 내용 해시가 모두 일치했다. 시험 자료만 세면 코스 2개·러닝 2건·246좌표다. 복원된 v2·v3 코스를 휴대폰 상세 화면에서 열었다.
- 메모는 개인 서버 동기화 대상이 아니므로 빈 저장소 복원 때 0건인 것이 정상이다. 이후 원래 기기 사본으로 복귀해 메모와 로컬 설정을 유지한다.

## 증거·재현

`.cache/phone-validation/`에 `baseline.txt`, `offline-inspect.txt`, `synced-inspect.txt`, `empty-inspect.txt`, `restored-inspect.txt`, `verification.json`과 UI 캡처를 보관한다. 계정 UI는 비공개 캐시에만 두고 문서에 계정 이름·이메일·원본 위치를 싣지 않는다. 공유 링크는 시험 후 중단한다.

도구: `scripts/qa/PhoneValidation.java`, `build-phone-validation.ps1`, `phone-validation.py`, `phone-validation-fixture.mjs`, `verify-phone-validation.py`. 명시된 기기만 사용하며 fixture seed는 전용 ID와 시험 이름으로 제한한다. 원본 DB/WAL/SHM을 호스트로 복사하지 않는다. 빈 저장소 검증 전 검증 사본이 있어야 하며 실행 중 동시 UI 명령을 보내면 덤프 파일이 경합할 수 있다.

이 도구들은 이번 기기·화면 크기·증거 파일에 맞춘 단계별 QA 도구이며 무인 전체 시험 명령이 아니다. `drawing-flow`는 새 코스 만들기 화면에서 공개 서울 강남 표본을 먼저 선택한 뒤 실행한다. Java 도우미와 터치 jar를 빌드/배치하고 `free-loop-fixture.mjs`의 공개 fixture, 이번 그리기에서 추출한 `custom.json`을 준비해야 한다. 증거 대조기는 이번 검사 건수와 캐시 파일을 전제로 한다. 12:11 후속 정리에서 계산 취소 동작을 공용 함수로 추출하고 공유 대상의 시험 ID/이름 확인을 추가했으며 이 도구 정리 후 휴대폰 재시험은 하지 않았다.

기본 UI dump는 계산 중 갱신 화면에서 유휴 상태를 기다렸고, 일부 스크롤·지역 ID가 에뮬레이터와 달랐다. 검증 도구의 지역 ID·스크롤 범위와 UIAutomator 버튼 클릭을 조정했다. 앱 코드 결함으로 보고하지 않는다.
