## 실패와 수정 이력

- 첫 UI 검사에서 러닝 설정 footer의 빈 문자열 View 자식이 실제 네이티브 렌더 오류를 발생시켰다. 제거 후 관련 UI 2개를 포함해 26개 통과했다.
- 강아지 홈 선택이 활성화되어 이전 ‘비활성’ 기대값을 새 입력 전달 검증으로 교체했다.
- OpenAPI 생성 시 --write 누락으로 drift 검사가 실패했다. 생성물을 명시적으로 갱신한 뒤 전체 qa:fast에서 통과했다.
- 첫 UI cold import의 제한 시간 실패는 네이티브 선택기 경계를 mock한 기존 생성 화면 테스트에서 재검사하여 통과했다. 실패 로그를 삭제하지 않았다.

- 첫 Android 전체 검사에서 조건 수정 후 스크롤 위치가 아래쪽에 남아 distance-3 탐색이 실패했다. 원본/시험 정리는 통과했다. 새 폼이 네이티브에 렌더된 다음 프레임에 스크롤을 초기화하도록 수정하고 UI 28개를 재검사했다. QA 탐색도 목록 끝에서 방향을 전환하도록 보완했다.

- Android 진단 2·3에서 지도 모드 일시정지는 통과했지만 터치 잠금을 길게 눌러 해제한 다음 일시정지가 동작하지 않았다. 손을 떼기 전에 Modal을 닫던 동작을 pressOut으로 옮겼다. 진단 4에서 잠금 해제 후 일시정지·프로세스 강제 종료/복원·옵션 보존과 종료 기록 화면까지 통과했다. 단순 대기 증가로 실패를 숨기지 않았고, 짧은 터치/긴 터치/해제 후 제어 UI 회귀를 추가했다.
- 집중 모드의 큰 방향 원 아래 안내가 기본 높이에서 잘려, 작은 화면의 숫자/방향 크기와 간격을 줄였다. 진단 4 실제 화면에서 안내·진행률·고정 제어가 함께 보인다. 확대 글씨는 스크롤을 유지한다.
- 실제 Android 사진 선택기→자르기→native PNG 변환→윤곽 미리보기→명시적 적용→생성 확인을 합성 단색 도형으로 통과했다. 원본은 서버에 전송하지 않는다. 시험 사진은 MediaStore와 파일에서 정리한다.

## 10-14 캡처 준비 대기 보완

- CI 38420313036 시도 1 API 36은 빌드 후 앱 검사 전 `adb root` 연결 종료로 중단됐다. 시도 2는 기존 8단계와 S234의 이미지/지도/잠금/복원/종료/재도전을 진행했으나 마지막 월별 목록 캡처에서 `No fresh UI hierarchy`로 실패했다. 최초 실패와 재실행 로그/artifact를 보존했다. API 29 5단계·원본 보존·정리는 통과했고 캡처 전송 경고 1건이 있다.
- Windows의 이전 같은 유형 실패에 이어 반복되어 캡처 도우미를 보완했다. 기존 UIAutomator의 dumpWindowHierarchy는 활성 루트가 null이면 파일 없이 반환한다([AOSP 소스](https://android.googlesource.com/platform/frameworks/uiautomator/+/5fe6e7f321f02b08224fad72374ed041f459b411/core/com/android/uiautomator/core/UiDevice.java)). 매번 새 연결을 만드는 호스트 재시도만으로 준비 시간을 주는 대신, 한 연결에서 최대 5초·250ms 간격으로 새 XML을 기다린다. 빈/과거 XML 제거, 매 호출 UUID 영수증, JUnit 성공과 실제 XML/PNG 읽기 조건은 유지한다. 준비 대기 횟수도 별도 로그/보고서에 남긴다.
- 계층 덤프 실패 시에도 독립 screencap·window/activity·logcat을 정리 전에 수집한다. 앞선 CI에는 계층 실패 뒤 화면 증거가 없어 앱 상태를 단정할 수 없었다. 시간 증가만으로 제품 성공으로 분류하지 않으며 같은 전체 시나리오와 필수 CI를 다시 통과해야 한다. 제품 소스/APK·기능/화면 판정 기준 변경은 없다.

- 보완 후 Python 7개(새 영수증 요구·준비 대기 기록 포함)와 Java/dex 빌드를 통과했다. 동일 제품 APK의 Windows S234 2회 및 새 PR 전체 CI를 실행한다.

- `s234-readiness-recheck`는 재기동한 전용 에뮬레이터의 부팅 완료 전 설치를 시작해 실패했다. 부팅 완료/패키지 관리자 준비를 확인한 뒤 별도 `s234-readiness-recheck-2`로 진행했다. 그 실행의 준비·S234 기능과 원본 보존은 통과했고, 실제 한 캡처가 같은 연결의 네 번째 루트 확인에서 새 XML을 생성했다. 다만 뒤의 화면 기준용 앱 데이터 초기화 후 고정 3초 안에 DB가 준비되지 않아 `no such table: saved_courses`로 전체 실패했다. 새 독립 PNG에는 글꼴 준비 화면, 후속 캡처에는 정상 홈이 남았고 정리는 통과했다. 둘 다 전체 통과로 세지 않는다.
- 초기/화면 기준용 앱 초기화 후에는 파일이 존재하고 필요한 9개 실제 앱 테이블이 모두 생길 때까지 최대 30초 확인한다. 파일/테이블을 도우미가 만들지 않으며 준비되지 않으면 계속 실패한다. 파일 미생성→부분 스키마→완료, 일부 테이블만 존재, 오프라인 오류를 Python 검사에 추가했다. 제품 소스는 변경하지 않았다.
