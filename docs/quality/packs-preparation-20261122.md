처음 웹 검증 번들은 Expo의 Metro 전용 이미지 해석 경로와 개발 환경/플랫폼 설정이 없어 렌더되지 않았다. 검증 어댑터의 웹 자산 해석 및 Expo 웹 환경을 명시한 뒤 10조건이 통과했다. 이 수정은 제품 의존성·환경 설정을 바꾸지 않았다. 임시 도구는 Git 제외 `.cache/packs-preview`에만 설치했다. Python WindowsApps 별칭 실행 실패 후 기존 GCP SDK의 번들 Python으로 검사 파일 문법을 확인했다.

후속 브라우저의 첫 로컬 서버는 sandbox에서 접속되지 않았다. 해당 프로세스를 종료하고 승인된 외부 실행으로 127.0.0.1에만 서버를 연 뒤 화면을 확인했다. 검사 후 서버·검사 탭을 닫고 임시 뷰포트 설정을 원복했다. 통합 Android 검사 준비는 카운터와 사용 기록 전체를 읽어 전후 비교하되 결과 파일에는 해시만 남기며, 실행하지 않은 완료 경로 검증을 성공 필드로 쓰지 않는다.

## 최초 필수 검사 실패와 보완

필수[44982931973](https://github.com/ssw3131/running-art-mobile/actions/runs/44982931973)의 Android29는 게스트/명시적 동의 단계 후 재시작에서 실패했다. 원본 로그에16MB growth limit의 OutOfMemoryError와 앱 종료가 있고 런처 화면을 캡처했다. 단순 타임아웃으로 분류하지 않는다. 자료 정리는 성공했다. 실행 로그의 `hw.heapSize=256M`은 [고정 runner 원본](https://github.com/ReactiveCircus/android-emulator-runner/blob/a421e43855164a8197daf9d8d40fe71c6996bb0d/src/emulator-manager.ts)의 잘못된 키와 일치한다. [upstream PR480](https://github.com/ReactiveCircus/android-emulator-runner/pull/480) 및 로컬 SDK hardware-properties.ini의 정수 `vm.heapSize` 정의를 대조했다.

API29 전용 일회용 CI AVD에 `vm.heapSize=256`을 기록하고 실제 heap 속성을 출력하도록 보완했다. 수동 compatibility는29 smoke만 진단하며 전체 PR의29/36 요구를 유지한다. API36 프로필·화면 오차·제품 APK은 변경하지 않는다. 보정 효과와 최종 필수 검사 결과는 실행 후 기록한다.

같은 최초 전체의 Android36은 기존15단계를 통과하고 추가 `Packs-preparation`에서 `Control not reached: pack-purchase`로 실패했다. 아티팩트14740101184의 원본 PNG/XML에 구매 버튼이 정상 표시·비활성임을 확인했다. 공통 `seek_visible`의 기본 enabled 조건 때문에 발생한 검사 계약 오류이며, 두 구매 비활성 확인에만 기존 `allow_disabled=True`를 전달한다. 나머지 컨트롤의 활성 조건·스크롤 경계·구매 비활성 단언·자료/사용량 보존을 유지한다.
