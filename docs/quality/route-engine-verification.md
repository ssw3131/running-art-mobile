## 검증 중 환경 복구

- 이 프로젝트의 기존 Metro 두 개가 Router 타입 파일을 동시에 작성해 `.expo/types/router.d.ts`가 손상됐습니다. 해당 프로젝트의 실행 명령·PID를 확인한 후 두 서버를 종료하고, 설치된 Expo의 생성기로 타입을 재생성한 뒤 Metro 8083 하나로 검증했습니다. 다른 Node 프로세스는 종료하지 않았습니다.
- 최초 APK 설치 중 패키지 서비스 연결이 끊긴 뒤 에뮬레이터 프로세스가 종료됨을 확인했습니다. 기존 Pixel 7을 데이터 삭제 없이 cold boot하고 파일 전송 방식의 APK 업데이트 설치를 완료했습니다.
- PowerShell 5의 기본 인코딩으로 UI XML의 한글을 읽을 때 파싱 오류가 있어 진단 스크립트에서 UTF-8을 명시했습니다. 앱 코드의 한글 문제는 아니었습니다.

## 증거와 후속 검증

Git 제외 경로 `.cache/route-lab-qa/`에 화면 PNG·접근성 XML·메모리 덤프·`metrics.json`을 보관합니다. 실행 로그의 `ROUTE_LAB_METRICS`에는 고정 표본명·입력·시간·양보 횟수·원본 비교·점수가 있습니다. 주요 화면은 `13-scheduler-result`, `14-grid-candidates`, `15-candidate-selected`, `16-cancelled`, `17-reentered`, `18-background-cancelled`, `20-no-candidates`, `24-seoul-result`, `25-seoul-candidates`, `29-location-regression`, `31-storage-regression`입니다.

실제 Android 휴대폰은 최초 실행에서는 사용자 답변 “실제 휴대폰 검증은 나중에 할게요”에 따라 보류했고, 이후 사용자가 연결·계산한 후속 결과를 아래에 기록했습니다. iOS·릴리스 앱·야외 통행·배터리·러닝 추적·다운로드 캐시·실제 코스 저장은 이번에 검증하지 않았습니다. 이번 기기 결과를 그 범위의 완료로 표시하지 않습니다.

## 후속 문구 정정 — 2026-09-27

진행 단계의 v0.1·v0.2 표기를 ‘기본 경로 탐색 → 크기·위치 추가 탐색 → 우수 후보 미세 조정’으로 바꿨습니다. 추가 탐색 준비 안내를 포함한 문구 4개 변경이며 수식·횟수·단계 순서는 유지했습니다. 타입·린트와 기존 원본 해시·합성 하트 v0.2 전체 결과 비교 2개를 재확인했습니다. 위 기기 시간·화면 증거는 문구 정정 전 측정입니다.

실제 폰으로 옮길 때의 개선 폭은 미측정입니다. 에뮬레이터는 호스트와 가속 설정의 영향을 받고, 같은 개발용 앱을 폰에 설치해도 개발 모드는 유지됩니다. [Android 가속 안내](https://developer.android.com/studio/run/emulator-acceleration)와 [React Native 성능 안내](https://reactnative.dev/docs/performance)에 따라 후속 비교에서 기기 조건과 개발용·릴리스 빌드를 구분합니다. 서울 표본의 연산 구간 합계는 121.15초, 전체는 277.44초이므로 현재 지연을 가상화 비용만으로 설명하지 않습니다.
