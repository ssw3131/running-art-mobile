# A7 합류 경로 반복 성능

사용자 요청의 공개 강남 입력을 Android 10/arm64 release Hermes에서 측정했다. 이전/현재 각4조건×20회, 총160표본이며 현재 구현80표본은 모두 성공했다. SM-A102N 결과나 야외 GPS/배터리 검증은 아니다. 기기 식별자·계정 상태·원본 기기 화면/환경 로그는 로컬에만 보관한다.

실패17개는 모두 이전 구현에서 발생했다. 파일 조건의 첫2실패는 앞선 최초 조회 실패 후 파일 확보가 끝나지 않아 네트워크 요청도 발생한 표본이다. 이를 정상적인 파일 캐시 성공으로 세지 않았다. 성공 표본의 통계는 해당 성공 수에만 적용하며 전체20개의 완료 시간 분포를 뜻하지 않는다.

**완성 경로 P95≤1초는 통과**했다. 최초 조회는 이전 구현14/20개가10초에 중단돼 정확한 완료 시간 중앙값/개선율을 계산할 수 없으므로 **최초 중앙값30% 개선 기준은 판정 보류**다. 실패 표본을10초의 정상 완료로 치환하거나 성공6개만으로 개선율을 확정하지 않는다.

현재 최초 조회 최대는6,144.08ms, 파일 최대3,748.14ms이며 모든 현재 표본이10초 안에 완료됐다. 최초 시작 반경에 따라 이전 구현은9개 파일, 현재는2개 파일을 읽었다. 파일 캐시에서도 도로 읽기/검증/해제 시간이3초 이상으로, 그래프/완성 경로 메모리 재사용과 구분된다.

[집계와 판정](report.json)·[익명 공개 입력 표본160개](samples.json)·[이전 코드/입력 무결성](baseline-integrity.json)을 보존한다. 원본 기기 메타데이터와 절대 관측 시각은 이 공개 표본에서 제외했다. 표본 키(iteration/version/condition)160개가 고유하고 중첩 수집 구간의 동일 키 payload가 같은지 검사했다. 최초 수집기의15분 상한에 대비해 수집기만 시간 기준으로 이어 연결했으며 앱 재실행·추가 측정·표본 교체는 없다.

실제 완료 화면의160개/실패17개를 로컬 원본과 대조했다. 실제 설치 APK SHA256은 `5858127de8e8b9d0370eddf5c2420ffdb4d6312b3bed415c3face0a9ab8e3b4d`, 공개 빌드 소스는 `8244ac754298983d38c32e5baef7862c3aff8273`다. 제품 자료 보존과 종료 상태에 대한 기기별 상세 기록은 로컬 검증 자료로 관리한다.

## 방법

- 이전 planner `6a72e7930e01b5e415bed1eb5ea8bbd90571c5a4`의 원본은 import 상대 경로만 옮겼다. 양쪽 모두 현재 공통 엔진/도로 로더/스케줄러를 사용한다. 이전 APK 전체와의 비교가 아닌 planner 변경 비교다.
- 공개 강남 중심 37.4979/127.0276에서 얻은 하트 2km 코스와 고정 출발/이동 위치를 사용한다. 준비된 첫 합류 경로는 549.333m다. 고정 manifest는 `484c83a6876d993b6a4ac977775c5402a816e929f0c8cf0b73f6d69177a9322c`, release는 `kr-20260930-c8cb96030306-roads-v1`다. 변경되면 실패로 남긴다.
- 두 구현을 매 반복마다 AB/BA 순서로 번갈아 실행한다. 각 구현의 최초 조회·파일·그래프·완성 경로 조건을 20회씩, 총160개 기록한다. 실패를 표본에서 제거하거나 부족한 수를 새 성공 표본으로 대체하지 않는다.
- 최초 조회는 전용 SQLite 캐시를 비운 뒤 실행한다. 앱 프로세스/TLS/DNS/OS 캐시까지 차갑게 만드는 실험은 아니다. 기존 구현의 최초2km와 현재1km 시작 반경은 각 실제 구현의 동작 그대로다.
- 파일 조건은 SQLite 연결을 닫았다가 다시 열고 새 planner를 만든다. 새 네트워크 요청0/다운로드0을 검사한다. 이는 SQLite 영구 자료 재사용이며 OS 페이지 캐시를 제거하지 않는다.
- 그래프 조건은 같은 targetM을 유지하며35m 이상 움직인 공개 위치로 변경해 완성 경로 캐시를 피한다. 현재 구현의 cache=graph·roadMs=0·도로 요청0을 강제한다. 완성 경로 조건은 그 위치/targetM 그대로 재호출해 cache=plan을 확인한다.
- 이전 구현에는 그래프/완성 경로 캐시가 없으므로 그 이름의 조건은 같은 입력의 반복 요청이다. 표본에 남는 도로 로딩과 전체 시간을 비교한다.
- 각 표본은10초 제한과 오류를 기록한다. 집계 시 실제 elapsedMs가10초 이상인 성공 행도 거부한다. 현재 구현은 roadMs/graphMs/searchMs/totalMs와 캐시 판정을 제공하고, 이전 구현은 외부 측정한 roadMs/elapsedMs를 제공한다.
- 기존 `mobileScheduler.yieldToHost`를 두 구현에 동일하게 사용한다. 화면 갱신/로그 기록은 표본 종료 뒤다. 중앙값/P95는 정렬 후 nearest rank, 성공 수와 실패 수를 함께 표시한다.
- 사용자 DB와 기본 도로 캐시는 접근하지 않는다. `running-art-approach-benchmark-v1.db`만 초기화/재개방/종료 후 삭제한다. 생성/저장 API를 호출하지 않는다.

## 사전 검증과 실패 이력

PC의 공개 도로/SQLite 사전16표본은 양쪽 경로·targetM 오차1m 이내, 캐시 출처 조건을 통과했다. PC 시간은 A7 수치로 사용하지 않는다. 타입/린트·합류 회귀15개·화면 분류1개·게스트 차단47개가 통과했다.

초기6389e69의 [draft fast364](https://github.com/ssw3131/running-art-mobile/actions/runs/43717414273)는 새 화면의 회원 전용 경로 등록 누락으로 logic1개가 실패했다. 원본 artifact14163540366/ZIP SHA256 `fd35746170e7e35bed42e8580aac99b08919a5818e2b042f42ea4f44617e59da`를 PC에 보존했다. 같은 소스 [Handset56](https://github.com/ssw3131/running-art-mobile/actions/runs/43717420899)은 npm ci 도중 취소했고 폰에 설치하지 않았다. 경로를 분류한8244ac7에서 검사를 다시 통과했고 [Handset57](https://github.com/ssw3131/running-art-mobile/actions/runs/43717777607)을 준비한다.

기기 화면 전체와 계정 상태는 Git 제외 PC 캐시에만 보관한다. 외부 PR의 개인 계정 상태 포함 업데이트는 자동 승인 검토에서 거부됐고, 해당 메타데이터를 제외한 성능 수치/코드 검사 설명으로 반영했다. 공개 증거에는 고정 공개 입력의 익명 측정 행과 집계만 포함한다.
