# 코스 생성·실제 GPS 안내 검증

상태: **PC·Android 에뮬레이터·설치용 APK 범위 완료** (2026-10-03). 휴대폰 설치·야외 테스트는 사용자 요청으로 수행하지 않았다.

## 자동 검사·빌드

- 최종 `npm test` **249개 통과**, 실패/취소/생략 0. `dev.ps1 check`의 타입·린트 통과.
- 추가 러닝 안내 검사 10개: 출발 소유권/정확도·거리, 정지 완주 일시정지·확인, 계속 달리기, 재개 후 진행 건너뛰기 방지, 매 좌표 체크포인트 복원·중복 발화 방지, 쓰기 실패 원자성, 코스 삭제 후 버전 있는 동기화 파일·빈 SQLite 복원, v4→v5 원본 필드 보존, 화면 꺼짐 설정/새 프로세스 복원, GPS 공백을 이탈·완주 지속 시간에 포함하지 않기.
- v4 자료에 코스·러닝·좌표·메모를 넣고 v5 적용 전후 원래 모든 열을 비교했다. 새 코스 필드는 `null`이고 과거 자유 러닝은 안내 없이 읽힌다.
- 코스 연결 파일 v2의 좌표·경로 사본·완주 여부 복원과 변조 차단을 실제 SQLite로 확인했다. 기존 동기화·소유권·레거시 좌표 배열 검사도 통과했다. **새 형식의 실제 Supabase 업로드/다운로드는 이번 실행에서 재검증하지 않았다.** 기존 서버 계약은 변경하지 않았다.
- `:app:assembleRelease --max-workers=2 -PreactNativeArchitectures=arm64-v8a,x86_64` 성공. 잠금·복원 검증 뒤 집중 화면에서 회전까지 거리·복귀 거리 표시가 빠진 것을 보완하고 타입·린트·release 빌드를 다시 통과했다. GPS·저장·안내 판정·백그라운드 구현은 같으며 최종 APK에서 문구·완주 후 재개·생성 흐름을 추가 확인했다.

## API 36 에뮬레이터 검증

- 기존 API 36 `RunningArt_API_36`을 `emulator-5556`으로 시작했다. 최초 SQLite v4의 모든 사용자/동기화 테이블이 비어 있음을 확인하고 원본을 `.cache/course-gps-qa/original.db`에 백업했다.
- 최초 APK 업데이트·SQLite v5 이행과 UI 표시를 확인했다. 공개 OSM 회귀 좌표의 짧은 경로·반복 경로를 검증용 저장 코스로 추가했다. 이 자료는 권고 코스 결과나 실제 사용자의 야외 기록이 아니며 서버로 전송하지 않는다.
- 초기 준비 화면에서 권한 요청 후 전경 복귀가 위치 요청을 반복하는 문제를 발견했다. 이미 허용된 권한을 읽고 중복 요청을 억제하도록 수정했다.
- 오프라인에서 네트워크 위치 서비스 동의창이 발생하는 경우를 확인했다. 준비 위치 구독·출발 위치 확인에 설치된 Expo Location의 `mayShowUserSettingsDialog:false`를 적용했다.
- 출발점에서 정확도 ±5m로 준비 완료→시작을 확인했다. 약 237m 공개 OSM 경로에 실제 Expo Location으로 위치를 주입해 49개 기록·232.53m 거리와 정지 상태의 완주 자동 일시정지를 확인했다. 종료 확인 뒤 상세에 시작 당시 코스 이름과 **코스 완주**가 표시됐다. 한국어 오프라인 `tts_done`도 확인했다.
- **30분 연속 잠금 통과:** 실제 경과 1,805.6초, 30초 간격 61개 상태에서 모두 화면 꺼짐·`running` 유지. 1,800.5초 시점 959좌표·5,283.35m 기록·5,398.49m 코스 진행을 확인했다. 반복 경로가 출발점을 재통과해도 조기 완주하지 않았다. 잠금 구간 한국어 `tts_done` 110회, Wi-Fi/모바일 데이터 0, `Active default network: none`이었다. 실제 GPS용 `LocationTaskService`가 location foreground service로 유지됐다.
- 거리 재합산: 중간 707좌표의 저장 거리 3,867.3231729891013m와 좌표 재합계 3,867.323172989243m가 부동소수점 오차 약 `1.4e-10m` 내에서 일치했다. 주입 경로와 기록 거리의 차이는 필터·샘플링에 따른 것이며 실제 야외 거리 정확도를 검증한 것은 아니다.
- **설정·복원 통과:** 지도→집중·음성 끄기/켜기와 설정 저장을 확인했다. 화면 꺼짐 안내를 끈 뒤 Home으로 이동하면 일시정지하고 앱 복귀만으로 재개하지 않는다. 명시적 재개 후 강제 종료·재실행에서 좌표 수·진행률·활동 시간을 보존한 `interrupted`로 복원됐다.
- **진행 건너뛰기 방지·이탈/복귀 통과:** 중단 위치에서 약 150m 옮겨 재개했을 때 진행률을 유지하고 미기록 구간을 연결하지 않았다. 마지막 진행 지점 복귀 뒤 약 80m 이탈·되짚기를 주입해 `off-1` 진동/한국어 발화와 `returned-1` 발화·정상 복귀를 확인했다. 중도 종료 시 결과는 `stopped`였다.
- **최종 APK 완주 후 계속 달리기 통과:** 집중 화면의 ‘약 20m 앞에서’ 표시를 확인한 뒤 짧은 경로를 다시 주입했다. 완주 시 `paused / arrival-pending`, 계속 달리기 후 도착 위치에 머물러도 `running / active`를 유지하며 수동 종료는 `completed / stopped`로 보존했다.
- **최종 APK 생성 흐름 통과:** 현재 위치로 계산 중심을 정하고 3→5km·하트를 선택했다. 계산 취소·재계산으로 실제 전국 도로 후보 5개를 얻었다. 2순위 **하트 4.98km / 실제 4.977739883km / 종합 80점**을 선택·저장했고 같은 후보 재저장 시 코스 수 3개를 유지했다(원래 QA 코스 2개 + 신규 1개). 저장 직후 준비 진입, 264m 밖 시작 차단, 출발점 이동 후 시작, 저장 코스와 러닝의 경로 사본 일치, 종료 상세, 저장 코스 상세→같은 준비 화면 재진입을 확인했다.
- 화면 자동화의 상단 복귀 제스처가 지도를 움직이거나 짧은 후보 영역을 건너뛰는 문제는 QA 도구에서 수정했다. 실제 입력과 생성 결과를 바꾸는 앱 수정으로 우회하지 않았다. 최종 조건/후보/중복/준비/기록 캡처를 남겼다.

## 증거와 후속

공유 가능한 자동 검사와 에뮬레이터 제어는 `tests/running-guidance.test.mjs`, `scripts/qa/course-gps-fixture.mjs`, `scripts/qa/course-gps-emulator.py`, `scripts/qa/course-gps-behavior.py`, `scripts/qa/course-gps-flow.py`에 있다. 로컬 캡처·SQLite·로그는 Git 제외 `.cache/course-gps-qa/`에 보관한다. 설치 대상은 에뮬레이터로 고정한다.

재현 시 API 36 에뮬레이터 `emulator-5556`의 root·기존 `scripts/qa/build-running-ui.ps1` UI 도우미 배치를 먼저 준비한다. 새 증거 디렉터리에서 원본 DB 백업→앱 v5 이행→공개 코스 fixture 생성/seed→출발/위치 주입→behavior/flow→원본 복구 순서로 진행한다. 기존 `original.db`는 덮어쓰지 않으며, 계정 동기화가 켜져 있거나 미완료 러닝이 있으면 seed를 중단한다.

검증 종료 전 QA 세션 4개/좌표 1,108개·코스 3개를 로컬 증거로 보존한 뒤, 에뮬레이터의 최초 SQLite v4 백업을 복구했다. **모든 테이블의 개수·내용 해시와 `user_version`이 작업 전과 정확히 같다.** 최초 사용자 테이블은 모두 비어 있었으며, QA 자료는 서버로 전송하지 않았다. 앱 서비스 `(nothing)` 확인 후 시험용 UI 도우미를 제거하고 이번에 시작한 에뮬레이터를 종료했다. 원래 v4 DB는 다음 앱 실행에서 v5로 이행한다.

주요 로컬 증거: `locked-report.json`, `replay-1.json`, `locked-voice.log`, `locked-connectivity.txt`, `locked-service.txt`, `force-stop-stored/`, `force-stop-recovered/`, `resume-outside/`, `off-route/`, `returned/`, `continue-stationary/`, `flow-*`, `final-qa-records.json`, `original-restored.json`. 크래시 로그는 비어 있었다. APK 두 버전의 장시간 검증/최종 화면 검증 범위는 위에 구분했다.

**후속:** 실제 휴대폰의 야외 이탈·복귀·완주, 30분 이상 잠금·거리 오차·GPS 공백·진동 체감·배터리와 새 동기화 파일의 실제 서버/휴대폰 복원을 확인한다. 기존 모의 안내 서비스의 휴대폰 재개 후 `heartbeat_timeout`은 별도 미해결이며 이번 실제 GPS 결과로 해결 처리하지 않는다. 전체 5탭 서비스 UI·추가 도형 입력·배지·공유·과금은 이번 완료 범위 밖이다.
