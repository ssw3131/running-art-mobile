## 재현과 수정

격리 API 36 `RunningArt_Recovery_QA`에서 기존 지형 APK로 합성 위치를 저장하던 중 22:55:09 KST 로컬 `bmgr backupnow`를 실행했다. 백업 성공 직후 `Killing agent host process`·SIGKILL을 확인했고, 새 화면에서 interrupted로 복원됐지만 서비스/기록 중 알림이 남았다. 정상 종료 뒤에도 동일 서비스가 남았다. 실기기 자동 백업과 이번 수동 재현의 트리거는 구분한다.

`android.allowBackup=false`로 Android 클라우드 자동 백업 대상에서 제외한다. 비로그인·미동기화 자료의 자동 백업도 제외되며 Supabase 동기화는 유지한다. 제조사 기기 간 전송까지 막는다는 의미가 아니다. [Android 문서](https://developer.android.com/identity/data/autobackup).

늦은 GPS 콜백/실패한 정리 재시도를 보완하고, Expo Location 57.0.20의 바인딩 해제·늦은 연결 무시·고아 서비스 정리를 버전/소스 해시 고정 패치로 구현했다. TaskManager 등록이 없어도 네이티브 서비스 정리를 호출한다. 새 프로세스에서는 마지막 저장 지점을 보존하고 사용자가 재개하도록 한다. 수신하지 않은 이동/시간을 자동 생성하지 않는다.

첫 수정 APK의 에뮬레이터 검증에서 백업 거절·동일 PID/새 좌표 저장을 확인했지만 일시정지 후 바인딩이 남았다. Gradle이 원래의 사전 컴파일 AAR을 사용한 사실을 확인해 `buildFromSource`를 추가했다. 첫 준비본 해시 `c702299e…`는 최종 검증본으로 취급하지 않는다. [Expo 빌드 설정](https://docs.expo.dev/guides/prebuilt-expo-modules/).

## 증거와 한계

`scripts/qa/verify-gps-recovery.py --final`로 원시 증거를 대조해 [정제 결과](gps-process-recovery-20261011.json)의 `complete=true`를 확인했다. 충전 분리/복귀·최소 60분 사용자 확인·유효한 충전 전 잔량·GPS 시각/최대 공백·동일 PID·종료 정리·원래 자료/계정/동기화·도우미 정리를 검사한다. 저장 간격 60초 이상이나 역전은 자동 통과하지 않는다. 별도로 원시 종료 이력·시각과 60분 구간 220점, 정리 전후 전체 해시를 직접 대조했다.

원시 로그/SQLite 합성 자료는 `.cache/gps-recovery-20261011`, 휴대폰 내부 백업 확인/해시/UI는 `.cache/gps-recovery-phone-20261011`에 보관한다. 실제 GPS 좌표나 인증 자료를 문서/공용 저장소로 내보내지 않는다. `scripts/qa/gps-recovery.py`는 지정된 격리 에뮬레이터만, `gps-recovery-phone.py`는 지정된 고사양폰만 대상으로 한다. 휴대폰 instrumentation은 앱을 종료하므로 **활성 기록 중에는 실행하지 않는다**.

야외 이동 정확도·앱 단독 배터리 소모·제조사별 절전·iOS를 이번 검증으로 통과 처리하지 않는다.
