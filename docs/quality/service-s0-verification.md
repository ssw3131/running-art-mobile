# S0 서비스 구조·5탭 검증

2026-10-12. 사용자 요청으로 S0 목표를 등록하고 기존 모바일 앱의 서비스 구조를 구현했다. [실행 계획](../history/executed-plans/2026-10-12-1942-service-s0.md)·[구조와 경로](../development/service-navigation.md). 물리 휴대폰 설치·클라우드 배포는 이번 범위에 포함하지 않았다.

**20:47~20:54 주요 화면 후속:** 같은 최종 APK에서 5탭·지도·상세/뒤로·설정/안내·입력 유지·코스 준비를 다시 확인했다. [실제 스크린샷 12장](service-s0-screenshots.html)은 클릭해 확대할 수 있다. 공개 시험 코스 1개만 사용했고 시험 후 빈 DB 9개 테이블·권한/설정을 원복하고 에뮬레이터를 종료했다. 실제 로그인·러닝 시작·클라우드 변경은 하지 않았다. [원본 PNG 목록/해시](screenshots/service-s0-20261012/index.json).

## 구현과 디자인 범위

- Expo Router 서비스 5탭: 홈·코스 생성·실시간 러닝·기록 보관함·마이페이지. 생성/러닝/계정은 실제 기존 기능 화면, 보관함은 실제 코스/러닝 목록이다.
- 공통 FontGate/ThemeProvider·상하단 바·안전 영역·안내/상세 스택. 이전 진단 홈은 같은 앱의 `/development`로 이동했다.
- Figma MAIN-1 `2:855`, INFO-1 `36:6724`의 design context와 스크린샷을 재조회했다. 기존 원본 아이콘·80dp 상단 바·Noto를 재사용하고 원본 로고를 로컬 에셋으로 저장했다. 상세 홈 3상태와 안내 콘텐츠는 S1/S6 범위다. 상품 잔량 등 예시 숫자는 표시하지 않는다.
- 인증/동기화/러닝 감시는 기존 루트에서 유지한다. 홈에는 실제 활성 러닝 복귀를 제공하며 탭 진입만으로 GPS 기록을 시작하지 않는다.
- 루트 복원 오류를 상태바 아래에 배치하고 계정별 오류 범위와 재시도를 연결했다. 이번 정상/중단 복원 시나리오에서 오류 배너는 발생하지 않았다. 인위적 저장소 장애 배너 발화는 별도로 주입하지 않았다.

## 발견·수정한 회귀

1. OAuth 취소 콜백에서 루트 탭을 `replace`하면 생성 입력이 초기화됐다. 상세/콜백을 닫은 뒤 기존 탭을 선택하도록 통일하고 3km/별 도형 보존을 재검증했다.
2. 하단 탭의 기본 이동이 `courseId`/`view`를 지워 코스 준비가 일반 러닝으로 바뀌었다. 기존 params를 병합하고 코스 준비 반복 복귀와 보관함 선택을 검증했다.
3. 계속 유지되는 화면 수명에 맞춰 생성 화면 자동 위치 초기화를 최초 진입으로 제한하고, 진행 계산 취소·완료 결과/저장 이름 보존·러닝 busy 해제·위치 요청 세대 구분을 적용했다.
4. 큰 글씨에서 코스 이름 입력칸이 키보드에 일부 가렸다. 상단 바의 실제 화면 위치를 포함한 스크롤 보정을 추가했다. 입력값만 보는 검사에 입력칸 전체가 키보드 위에 있는지 확인하는 조건을 추가했다.

GPS 시험 기록은 10개 좌표로 정상 종료했다. 에뮬레이터 주입 위치이며 야외 정확도·배터리·장시간 휴대폰 검증을 대신하지 않는다. 구형 v1 QA 코스의 시작 차단은 기존 자유 순환 제한의 정상 동작으로 확인했으며, 출발 가능 검증에는 별도 현행 v2 공개 OSM 코스를 사용했다. 첫 부팅의 System UI 응답 지연과 UI dump 재시도는 제품 앱 장애와 구분했다.

큰 글씨의 홈·메뉴·입력 화면을 PNG로 직접 확인했다. 하단 글씨는 폭에 맞춰 두 줄로 표시하고 터치 영역/제스처 영역은 겹치지 않는다. 공통 UI에 Noto를 적용했으며 기존 기능 본문의 전체 글꼴/디자인 전환은 후속이다. 공유 검증은 OS 선택창과 기존 링크 공유 진입까지이며 외부 앱에 실제 메시지를 보내거나 서버 공유 링크를 발행하지 않았다.

최종 키보드 검사: 입력칸 하단 **1434px**, 키보드 상단 **1491px**로 입력칸 전체와 57px 여유를 확인했다. 기본 화면은 1080×2400/420dpi, 작은 폭 검사는 480dpi(360dp)·font scale 1.6이다.

## 자료 보존과 정리

- 자료 유지 업데이트 직전/직후의 공개 시험 코스 1개·메모 1개와 나머지 테이블 전체 내용 해시가 같았다. 종료 직전에도 원래 시험 코스·메모의 행 내용 해시가 같았다.
- 검증으로 생긴 총 3코스·1러닝/10좌표·1메모를 정리하고, 실행 전 백업한 빈 QA DB로 복구했다. 원래 **9개 테이블의 개수/내용 해시 모두 일치**한다. 계정/동기화 행은 처음부터 끝까지 0개다.
- 최종 설치 `base.apk` SHA-256과 배포 폴더 APK의 일치를 기기에서 대조했다. 최종 APK의 5탭/자동 GPS 시작 없음·큰 글씨/입력 가시성을 다시 확인했다. 코드 수정 때 영향받은 흐름을 재검증했으며 각 단계의 증거를 보존했다.
- 글씨 1.0·원래 420dpi로 복귀, 시험 도우미/덤프/기기 임시 DB 제거, 앱 종료·서비스 없음 확인 후 이번에 시작한 emulator-5558을 종료했다. 시험용 화면 꺼짐은 60초로 설정했다. 원래 timeout 값은 사전 기록하지 않아 동일값 복원으로 주장하지 않는다.
- [정제 증거](service-s0-verification.json)에 APK/번들·테스트 수·자료 해시와 주요 화면 증거의 해시를 기록한다. 개인 계정·실제 사용자 위치 자료는 없다.
