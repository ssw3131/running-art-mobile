# S2a 코스 생성 서비스 UI 검증

2026-10-13, 진행 중. [기능 계약](../development/course-generation.md)·[실행 계획](../history/executed-plans/2026-10-13-1747-course-generation-ui.md).

## 범위

기존 중심·9도형·3/5/7km·직접 그리기 → 확인 → 실제 서버/기기 계산 → 후보·점선 → 상세·명시적 저장/GPX/러닝 준비. 운영 DB/서버 배포와 물리 휴대폰은 변경하지 않는다. 기존 엔진/원본 결과·SQLite/동기화 형식을 유지한다.

## 진행 근거와 발견

- 후보 사본·다른 계정/만료 접근·이름/저장 ID 복원·입력 변화 로직 4개 통과. UI는 확인/취소·계산 제한·실제 후보 수·이전 조건·점선·0개/오류·확인 중 조건 변경을 검사한다.
- 최초 타입/린트 통과, 첫 release 빌드 통과. UI 20개 통과 뒤 저장 전 GPX/러닝 차단과 정확한 저장 ID 전달 검사를 추가해 21개 통과.
- 첫 UI 실행은 C 드라이브 여유 없음으로 임시 파일 생성 실패. 프로젝트 D 드라이브 임시 폴더를 사용했다. 테스트 mock factory의 외부 변수 참조와 자산 alias, 부분 문구 matcher를 수정했다. 제품 실패와 환경/검사 코드 실패를 구분한다.
- `.cache/s2a/fast`와 `build-final.log`의 병렬 전체 검사/빌드는 PC 메모리 부족으로 종료됐다. 검사 제한을 완화하지 않고 병렬도를 낮춘 로직·정책 검사와 순차 빌드로 재검증한다. 최초 로그는 보존한다.
- 첫 Android 화면 검토에서 기존 도형 일부의 임시 텍스트와 긴 이름 줄바꿈을 확인했다. 실제 엔진 윤곽 미리보기와 화면 폭/글씨 크기에 따른 열 수를 적용했다. 후보 이름 입력은 기존 저장 상세의 키보드 스크롤 처리를 재사용한다.

## 최종 결과

- 순차 재검증: 로직 431개와 계정/공유 정책 모두 통과. 타입/린트·Python 6개 통과. 저장 준비 중 계정 변경 차단 검사를 추가한 UI 22개 통과.
- 최초 Android 전체 실행은 호스트 메모리 부족 중 `screencap` 45초 제한을 넘었고 뒤의 정리 명령도 응답하지 않았다. 첫 보고서/실패를 보존하고 전용 AVD만 종료·콜드 부팅했다. 기존 합성 코스/메모와 전 테이블의 내용 해시가 최초 기준과 같은 것을 확인했다(`.cache/s2a/recovery/report.json`). 이 실패 실행을 전체 통과로 세지 않는다.
- `.cache/s2a/android-generation`의 생성 흐름은 실제 직접 그리기/취소 복원·확인/취소·탭 이탈 계산 취소·재계산·5개 후보·점선·2순위 상세·키보드 위 이름 입력·탭 이동 후 이름 복원·중복 저장 제거·GPX 선택창·보관함을 통과했다. 이어진 큰 글씨 검사는 표시된 고정 취소 버튼을 본문 ScrollView 내부에서 찾는 QA 동작 때문에 실패했다. 화면/XML에서 버튼 전체가 시스템 영역 위에 있음을 확인하고 고정 버튼 탭으로 수정했다. 정리는 통과, 캡처 경고 0이다.
- 화면 검토에서 토끼/집 미리보기의 범위/방향과 생성 버튼의 잘못 연결된 이용권 아이콘을 발견했다. 기존 도형을 실제 좌표 경계로 맞추고 입력/확인 각각의 원본 Figma 버튼 자산으로 수정했다. 따라서 앞선 실행을 최종 시각 통과로 확대하지 않는다.

최종 Android·PR/main 필수 검사·원본 보존/정리와 Figma 대조는 진행 중이다. 완료 수치는 종료 시 이 문서와 실행 기록에 추가한다.
