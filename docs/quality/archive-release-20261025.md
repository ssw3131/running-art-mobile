# 기록 보관함 통합 운영·SM-S942N 설치 후속

2026-10-24 밤 시작, 10-25 계속 진행 중. 소스·격리 검증의 기준은 [기존 결과](archive-usage-20261024.md)이며 아래는 사용자 후속 승인으로 추가 실행한 범위다. PR/전체 CI 완료 전에는 전체 완료로 해석하지 않는다.

## 승인과 통합

- 사용자가 통합·설치까지 요청했고 설치 대상은 **SM-S942N만**으로 확정했다. 동기화 설정은 유지한다.
- 별도로 Cloud Run 기존 서비스 계정에 두 usage 비밀의 읽기 권한, Supabase 함수의 같은 HMAC 키, 트래픽 0 검증 후 전환을 명시 승인했다. 최초 자동 승인 검토 거부를 기록하고 승인 후 실행했다.
- `feat/archive-usage`에서 가입·20km 통합 소스와 main `27e07d6`을 대조했다. 문서 충돌 4개는 양쪽 최신 사실을 보존했다. 원래 모바일·가입·20km 작업 폴더의 제품 변경은 보존한다.
- [PR #27](https://github.com/ssw3131/running-art-mobile/pull/27)을 만들었다. GitHub 연결 도구의 PR 쓰기 403으로 기존 인증 Git/API를 사용했다. 현재 필수 CI 확인 중이며 아직 병합하지 않았다.

## 운영 적용

- 기존 수동 SQL 이력을 확인한 뒤 `20261024120000_usage_allowances.sql`만 적용했다. 2026-10-24T14:34:51.795063Z. 전체 과거 migration 재실행이나 CLI 이력의 임의 등록은 하지 않았다.

- Edge Function `usage`를 배포했다. 기존 Auth의 실제 사용자 검증을 함수에서 수행하며 legacy JWT gateway 검증은 사용하지 않는다. 익명·잘못된 토큰 모두 HTTP401 `authentication_required`를 확인했다.

- `runpen-route-compute-usage1024`를 트래픽 0으로 생성해 상태/인증 차단을 검증한 뒤 100% 전환했다. 이전 `runpen-route-compute-course1024`는 복구용으로 유지한다. CPU/메모리·동시성·시간 제한·최소/최대 인스턴스·기존 guard 환경이 배포 전과 같음을 비교했다.
- 도메인 Worker의 인증/작업 ID 누락을 수정했다. 계산 POST에만 Authorization·x-operation-id를 고정 Cloud Run으로 전달하며 쿠키·무관한 키·health 인증은 전달하지 않는다. 관련 테스트 5개 통과. Worker 버전 `0b7f47e2-978a-4a01-827d-b2bd90b342e8`.

- 적용 전후 사용자 **3명**, 개인 기록 **35행**, Storage 객체 **14개**, 개인 기록 내용 MD5 **fb3dd6fbb6d81dde20f40b9c1fdc7db1**이 같다. 폰에서 현황을 조회한 뒤 사용 주체 1개가 연결됐으며 사용량 0/0·작업 원장 0개다. 서비스 키의 기존 개인 자료 REST 조회는 권한 403이므로 권한을 넓히지 않고 SQL 읽기 조회로 보존을 확인했다.

## CI·실패 및 수정 이력

1. 첫 CI `40102696235`는 문서의 형제 작업 폴더·미커밋 산출물 상대 링크로 scope 실패했다. 저장소 내 링크와 로컬 산출물 표기로 수정했다.
2. CI/Android의 이전 화면 선택자와 무인증 기기 계산 검사를 새 공통 상세·완주 탭·회원/사용량 서버 계약으로 갱신했다. 전용 loopback Auth DB에만 합성 소셜 identity를 넣고 실제 Auth·회원 동의·사용 원장과 제품 HTTP 계산 핸들러를 통과시킨다. 운영 인증 우회는 추가하지 않았다.
3. 추천 상세에서 이름을 입력한 뒤 탭을 다녀오면 초기화되는 문제를 수정했다. 후보 draft 유지 테스트 포함 관련 4개와 타입 검사 통과.
4. 두 번째 CI `40104051984`는 fast/API 성공, API36 release의 격리 TLS XML `includeSubdomains` 누락으로 린트 실패했다. `false`를 명시해 localhost 범위를 유지했다. API29는 후속 push에 의해 취소됐으므로 통과로 기록하지 않는다.
5. `50c86e3`의 CI `40104777079`는 fast/API·두 release 빌드 성공 후 Android 실행기의 인코딩 이름 `utf8-sig` 오기로 두 API에서 실행 전 실패했다. `utf-8-sig`로 수정하고 QA 스크립트의 명시적 codec 170개를 검사했다. 홈 스크롤 수정 `7022a3d`와 함께 다음 PR head에서 검사한다.
6. `f9d3c40`의 CI `40106130804`에서 로직486·Jest102(17 suites)·타입/린트·HTTP556·실제 DB3·pgTAP5가 통과했다. API29/36 release도 성공했으나 실제 회원 fixture 준비에서 실패하여 Android 시나리오는 실행되지 않았다. 기존 시험 인증 도우미가 이번 합성 Google identity를 같은 실행 ID/역할/이메일로 엄격히 확인하도록 먼저 수정했다. 이후 fixture의 안전한 작업명/오류 코드 진단과 빌드 전 실제 준비·정리 검사를 추가했다. 이 실패를 Android 통과로 집계하지 않는다.
7. `f8e149e` / `40107421861` 사전 검사에서 합성 identity 추가 뒤 Auth 로그인·삭제 HTTP500을 확인했다. 합성 소셜 identity의 생성/갱신/최종 로그인 시각을 명시하도록 보완했다. 이 변경은 전용 loopback 시험 DB에만 적용하며 실제 계정·제품 인증을 우회하지 않는다.
8. `cc032ff` / `40107732973`의 두 Android 사전 검사에서 위 수정 후 실제 Auth 로그인·회원 완료 RPC·가입 대기/완료 세션 전달·계정/정책 정리가 통과했다. fast/API와 두 release·게스트 차단·가입 동의/재시작·Maestro·홈 상태도 통과했다. 이후 S0 이동 검사의 예전 ‘Android back→항상 홈’ 기대가 수정 계획의 직전 탭 복귀와 충돌했다. 실제 API36 화면이 이전 저장 목록으로 정상 복귀한 것을 직접 확인하고, 이전 탭 복귀 및 홈 더보기→목록→헤더 back→홈 검증으로 갱신했다. 두 환경 모두 시험 자료 정리 성공, 전체 통과는 아니다.
9. `b152070` / `40109637136`에서 두 Android의 위 이동 검사는 통과했다. OAuth 취소 뒤 홈 이동은 성공했으나 코스 조건이 3km/별에서 기본값으로 초기화됐다. 실제 XML/화면과 controller 구독 상태로, 회원 갱신의 중간 `required` 상태가 navigator를 다시 구성하는 결함을 확인했다. 정책/회원 응답 순서 두 가지 모두 수정 전 실패하는 회귀 검사를 추가하고, 이미 완료한 회원은 두 응답 확정까지 loading을 유지하도록 수정했다. 정책 변경·미가입·계정 전환 차단은 유지하며 관련 로직18개 통과. 앱 수정이므로 최종 APK 재빌드·SM-S942N 추가 업데이트 대상으로 관리한다.
10. 격리 서버 연결에 맞춰 저장 확정은 20초 한도 내 실제 행 노출을 기다리고, 오프라인 공지 검사는 Wi-Fi/데이터 외 ADB loopback 전달도 끊는다. 7km 취소 시나리오에는 5초 이내의 실제 계산 전 대기 구간과 연결 종료 전달을 둔다. 제품 인증·원장·엔진 결과를 조작하거나 가짜 성공을 반환하지 않는다.

운영·폰 증거는 로컬 `.cache/archive-release/`, 앞선 격리 증거는 `test-results/archive/`에 있다. 비밀·개인 자료·전체 폰 화면은 저장소에 올리지 않는다.
