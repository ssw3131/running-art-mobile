# 새 지역 탐색·지도 이동 후 결과 유지 검증

검증일: 2026-09-29 (Asia/Seoul). 상태: 구현·자동 검사·Android 릴리스 APK 검증 완료.

## 재현과 수정

- 변경 전 기본 도로 API에 공개 테스트 좌표를 보냈다. 광화문은 6.17초·11,266요소, 부산시청은 4.54초·2,971요소로 응답했으나 강남역은 95초에 클라이언트 시간 초과였다. 특정 지역을 하드코딩해 차단하는 문제가 아니라 저장 표본 밖에서 공급자 지연에 취약했다.
- 별도 직접 조회에서 앱 식별 User-Agent 없는 요청은 공급자별 406/429였다. 식별 헤더를 포함한 강남 조회는 `overpass-api.de`에서 2.32초·6,597요소로 성공했고 다른 공급자는 35초에 시간 초과였다. 단일 공급자의 일시 가용성에 의존하지 않도록 앱에서 순서대로 대체 조회한다.
- 수정된 앱 로더로 강남역 도로 조회를 실행했다. 기본 공급자 대기 후 대체 조회까지 29.48초, Node의 실제 v0.2 엔진 계산 8.30초, 후보 5개였다. 원래 앱 로더와 엔진으로 부산시청도 도로 2,971요소·후보 5개를 확인했다. 이 수치는 PC Node이며 휴대폰 성능이 아니다.
- 완료 결과는 지도 이동·내 위치·도형/거리 변경에서 유지하고 다음 계산 시작 시 초기화한다. 좌표 변환은 완료 당시 원점을 계속 사용한다. 데이터 종류 전환과 진행 중 계산 취소의 기존 의미는 유지한다.

## Android 검증

실제 휴대폰은 연결되지 않아 기존 Pixel 7 에뮬레이터를 실행했다. arm64-v8a·x86_64 공용 릴리스 APK를 업데이트 설치하고 Metro 포트 전달 없이 실행했다. 최초 에뮬레이터 시작 시 System UI ANR은 대기 후 복구됐다. 최초 강남 조회는 모든 공급자 실패로 시간 초과였으며, 이를 숨기지 않고 공급자별 진단 로그를 추가했다. 이후 기본 조회 성공과 의도적으로 기본 공급자를 차단한 대체 조회 성공을 각각 확인했다.

| 시나리오 | 실제 결과 |
| --- | --- |
| 강남역 모의 위치·하트 3km | 도로 조회 8.94초·계산 37.11초·전체 46.05초, 후보 5개 |
| 완료 후 지도 이동 | 선택 중심 경도 127.02760 → 127.03043. 경로 실선·출발점·후보·시간·원래 계산 기준 127.02760 유지. 화면에 이전 결과 표시 안내 |
| 재탐색 후 지도 이동으로 취소 | 이전 결과 초기화, 진행 중 계산 취소, 늦은 결과 없음 |
| 이동한 중심에서 재시작 | 계산 기준 경도 127.03337, 메모리 캐시 재사용, 전체 24.44초, 새로운 후보 5개. 1순위 3.00km·79점 |
| 기본 공급자 장애·부산시청 모의 위치 | 테스트 프록시가 기본 호스트만 차단. 기본 조회 실패 0.86초 후 `overpass-api.de` 4.86초 성공. 전체 도로 준비 5.72초·계산 19.54초·전체 25.26초, 후보 5개·지도 표시 |

테스트 프록시는 허용한 공개 지도/OSM 호스트의 TLS를 그대로 전달했고 내용을 해독하거나 응답을 만들어 대체하지 않았다. 검증 후 에뮬레이터 `http_proxy`를 원래 `null`로 복원하고 테스트 프록시 프로세스를 종료했다. 앱 로그 `ROAD_DATA_ATTEMPT`는 공급자 호스트·응답 코드·시간·성공 여부만 기록하고 좌표·쿼리·지도 키는 기록하지 않는다.

UI XML 비교로 지도 이동 전후 선택 좌표 변경과 결과 좌표 유지를 확인했고, 캡처에서 경로 실선·출발점이 지도와 함께 이동하며 남아 있는 것을 확인했다. 소스맵에 번들된 세 구현 파일과 현재 소스의 코드 일치도 검사했다.

## 로컬 근거와 제한

- `.cache/route-fix-qa/`: 공급자 원본 응답·헤더, 공개 표본 계산 결과, 자동 테스트 로그, 빌드 로그, 기기 화면을 보관한다. 공유 소스에 실제 사용자 위치나 지도 키를 넣지 않는다.
- 공개 OSM 공급자 장애·도로 자료가 부족한 위치의 후보 없음은 발생할 수 있다. 영구 지역 파일·오프라인 조회는 후속이다.
- 기존 웹 API와 직접 조회는 같은 Overpass 서버에 의존한다. 부산 테스트는 중계 서버만 차단한 우회 검증이며, 독립 공급원 확보·Overpass 자체 장애 해소·조회 속도 개선의 증거는 아니다. 기본 API 95초 시간 초과와 별도 직접 요청 2.32초 성공도 서로 다른 시점의 관측이므로 서버 내부 지연 원인을 확정하지 않는다.
- 실제 사용자가 실패한 위치는 아직 전달받지 않았다. 공개 테스트 위치를 사용하며, 실제 휴대폰 GPS와 야외 사용은 이번 검증 범위에 포함하지 않는다.
