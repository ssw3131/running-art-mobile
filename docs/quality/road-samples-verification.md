# 4-1 로컬 도로 표본 검증

검증일: 2026-09-30 (Asia/Seoul). 상태: **PC 표본 가공·연결/결과 검증과 Android 에뮬레이터 검증 완료, 실제 휴대폰 측정 미완료**.

후속 사용자 결정: 휴대폰 연결 테스트는 나중에 진행한다. 측정 목표는 일시정지했으며 아래 미검증 항목은 보류 상태로 유지한다.

독립 클라우드 구축·배포·운영 API 전환·영구 캐시는 이번 범위에 없다. 실행 전 계획은 [실행 기록](../history/executed-plans/2026-09-30-1516-road-samples.md), 재현은 [사용법](../development/road-samples.md), 수치는 [기계 판독 보고서](road-samples-report.json)를 따른다.

## 원본과 가공

- [Geofabrik 한국 자료](https://download.geofabrik.de/asia/south-korea.html)의 `south-korea-260929.osm.pbf`, 288,242,629바이트.
- 자료 기준 시각: `2026-09-29T20:22:51Z`, replication sequence `4447`.
- SHA-256: `9d436449e16fcf78866eb50caec91fca5067e494a6914130f869332297a8cd5a`.
- 공식 MD5 파일의 `7775afecd9ccbf3285ace3f1fa2ec7f4`와 실제 파일 일치. 이후 재현은 SHA-256·크기·헤더 시각을 모두 확인한다.
- Python 3.12.14 / pyosmium 4.3.1. 한국 highway 1,816,595개를 순회해 표본 후보 범위의 전체 way 25,243개 추출, 약 57.20초. 현재 v0.2의 보행 필터 통과 22,645개.
- 서울 강남역, 부산시청, 구로·광명 인근의 격자 경계 교점을 중심으로 반경 2km의 외접 사각형을 조회한다. 추출은 모든 비교 격자 전체를 덮으며 way를 자르지 않는다.

**잠정 선택은 0.02도 + gzip level 6.** 0.01도보다 파일 수가 약 69% 줄고 gzip 총량은 약 9% 늘어난다. 0.04도는 0.02도보다 전송량이 약 54% 늘어난다. Brotli q5는 0.02도에서 gzip보다 약 11.5% 작지만, 이번 검증의 모바일 해제 경로는 gzip이다. Brotli의 휴대폰 해제 시간·메모리는 측정하지 않아 크기만으로 채택하지 않는다. 최종 결정은 휴대폰 검증 후다.

## 연결성과 전체 계산 결과

세 지역 × 세 격자, 총 9개 조합에서 분할 전후 입력·전체 그래프·모든 후보 경로·반올림 전 점수·순위·통계가 정확히 같다. 하트 3km / 검색 반경 2km / v0.2로 각 지역 후보 5개를 얻었다.

| 표본 | 조회 way | 그래프 노드 | edge | 약연결 성분 | 최대 성분 노드 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 서울 | 3,454 | 13,614 | 15,363 | 26 | 13,450 |
| 부산 | 2,008 | 9,181 | 9,972 | 37 | 8,884 |
| 경계 | 2,929 | 11,189 | 12,384 | 26 | 10,960 |

원본에 있는 작은 단절 성분도 동일하게 보존했다. 분할 뒤 모든 도로가 한 덩어리로 연결된다는 뜻은 아니다. 전체 방향별 링크도 비교했다. 결과 SHA-256은 JSON 보고서에 있다. 경계를 통과하되 내부 노드가 없는 선분, 동일 좌표·서로 다른 노드, 공유 ID 좌표 충돌, 누락·중복·손상·버전 혼합은 별도 합성 검사로 확인했다.

초기 검증 도구는 엔진 `search()`가 그래프에 덧붙인 `reachable` 집합을 새 그래프와 비교해 실패했고, 거대한 차이 출력 중 ArrayBuffer 할당 오류가 발생했다. 검색 전 그래프 상태끼리 비교하도록 도구를 수정했다. 엔진·도로 데이터를 바꾸지 않았으며 수정 후 9개 조합이 모두 통과했다.

## PC 로컬 전송·처리

Windows Node 24.21.0, loopback HTTP, 순차 다운로드, 표본/격자별 별도 프로세스, 각 3회 측정. 아래는 0.02도 중앙값이다. 전체 시간에는 해시 검사·JSON 파싱·병합·그래프 구성도 포함된다.

| 표본 | 파일 수 | gzip 다운로드 바이트 | gzip 해제 | 전체 전송·입력·그래프 |
| --- | ---: | ---: | ---: | ---: |
| 서울 | 9 | 476,751 | 6.17ms | 139.65ms |
| 부산 | 6 | 287,058 | 3.56ms | 87.77ms |
| 경계 | 8 | 430,705 | 5.31ms | 118.31ms |

Node 프로세스의 관측 최대 RSS는 서울 212.61MiB, 부산 145.52MiB, 경계 175.45MiB다. 런타임·HTTP·전체 프로세스를 포함하는 high-water 값이며 도로 자료만의 메모리나 휴대폰 메모리가 아니다. 단계별 heap/RSS와 원시 3회 기록은 `build/road-data/local-transfer-report.json`에 있다. 운영 CDN·모바일 통신망 성능으로 사용하지 않는다.

## 자동 검사와 Android

- 현재 전체 Node 자동 검사 84개 통과, Python 경계 검사 4개 통과.
- 새 공급 계약·모바일 codec 관련 10개 검사 통과. SHA-256·gzip·UTF-8은 Node 표준 라이브러리와 대조했다.
- `dev.ps1 check` 타입·린트 통과. Android debug arm64/x86_64 빌드 성공, production JavaScript·Hermes 번들 export 성공.
- Expo doctor는 공식 API 접근 허용 후 20/21 통과. 기존 Expo 57.0.25→57.0.26, constants 57.0.19→57.0.20, router 57.0.23→57.0.24 패치 갱신 안내 1개가 남았다. 이번 두 라이브러리의 호환성 오류는 없으며 SDK 갱신은 범위 밖으로 유지했다.
- Metro DevTools 최신 버전 설치는 로컬 dotslash 캐시 오류로 fallback을 사용했다. Metro 번들·에뮬레이터 앱 실행에는 영향이 없었으며 별도 개발 도구 수리는 진행하지 않았다.
- 최초 `adb devices -l`에는 연결된 실제 휴대폰이 없었다. 사용자에게 USB 연결 가능 여부를 물었으며, 실제 휴대폰의 해제·처리 시간·메모리는 아직 측정하지 않았다.

### Android 에뮬레이터의 실제 실행

API 36 / `sdk_gphone64_x86_64`, debug APK + production JavaScript, Hermes=true / `__DEV__`=false를 로그로 확인했다. PC 로컬 서버에 adb reverse로 연결했다. 0.02도 표본을 각 3회, 총 9회 실행해 입력 SHA-256·way 수·그래프 노드/edge 수가 PC 기준과 모두 일치했다. 완료 화면을 읽고 스크린샷을 검토했으며, 별도 재실행의 취소가 완료 결과를 표시하지 않는 것도 확인했다. [원시 측정 JSON](road-samples-android-report.json)

| 표본 | gzip 해제 중앙값 | 파일 해시 검사 중앙값 | 전체 전송·입력·그래프 중앙값 |
| --- | ---: | ---: | ---: |
| 서울 | 237.16ms | 2,703.52ms | 5,735.65ms |
| 부산 | 130.17ms | 1,447.34ms | 2,937.95ms |
| 경계 | 197.91ms | 2,289.90ms | 4,304.98ms |

전체 시간에는 검증 도구만의 병합 입력 지문 계산과 호스트에 제어를 양보하는 시간도 포함된다. 순수 JavaScript SHA-256 검사가 주요 비용이므로 실제 휴대폰에서 확인하고 필요 시 네이티브 해시 경로를 비교한다. 검사 생략으로 성능을 맞추지 않는다. 에뮬레이터의 수치를 휴대폰 성능으로 일반화하지 않는다. 0.01/0.04도는 이번 Android 실행에서 측정하지 않았다.

앱 전체 PSS/RSS는 시작 전 344,522/447,844KiB, 종료 후 405,372/513,724KiB였다. 초반 서울 구간 12개 스냅샷 중 최대 PSS/RSS는 415,152/523,688KiB다. 이는 debug 앱·네이티브 런타임까지 포함하며 전체 실행의 순간 최대값은 아니다. 실제 휴대폰에서는 각 격자 전체 구간을 측정해야 한다.

측정 후 에뮬레이터는 9월 30일 기존 로컬 릴리스 APK로 되돌리고 종료했다. 이번 Metro·표본 서버와 포트 전달도 정리했다. 실제 휴대폰 APK는 변경하지 않았다. 검증용 debug APK는 `android/app/build/outputs/apk/debug/app-debug.apk`에 남아 있으며 실행에는 Metro가 필요하다.

## 남은 종료 조건

실제 휴대폰에서 3개 격자의 반복 시간·메모리를 확인하고 공급 형식 선택을 확정한다. 그 전에는 4-1 전체 완료나 4-2 서버 구축 완료로 보고하지 않는다. 전국 규모·경계 다양성·작업 메모리 한도·운영 CDN·영구 캐시·업데이트 실패 복구는 후속 단계다.
