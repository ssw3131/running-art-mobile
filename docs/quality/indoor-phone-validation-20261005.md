## 휴대폰 Chrome 공유 화면

공개 서울 좌표로 만든 합성 코스 1개·러닝 1개만 검증 ID로 추가했다. `QA phone indoor synthetic`, GPS 232좌표/2구간, 계획 코스·원래 도형 각각 241점을 사용했다. 실제 사용자 GPS는 공개하지 않았으며 새 계정을 만들거나 수신자에게 링크를 보내지 않았다.

1. RunPen 러닝 상세에서 합성 기록 이름을 확인하고 링크 공유→공유 확인→OS 공유 선택창을 실행했다. 수신자를 선택하지 않고 닫았다.
2. 익명 조회 응답의 제목·232좌표/2구간·계획/원형 241점과 모든 좌표의 합성 서울 범위를 검사했다.
3. 실제 휴대폰 Chrome에서 로그인 없이 제목·3.67km·00:58:00, 배경 지도와 세 경로를 확인했다. 지도 이동 뒤 `전체 경로 보기`로 전체 경로 복원도 확인했다.
4. 실제 경로·계획 코스·원래 도형을 각각 OFF→ON으로 전환했다. 화면 체크 표시와 지도 영역의 해당 색상 픽셀 감소/복원을 함께 검사했다.
5. RunPen에서 합성 기록의 공유를 중단한 뒤 익명 API가 null을 반환함을 확인했다. 기존 Chrome 탭을 새로고침해 **“이 경로를 볼 수 없어요”와 지도 없음**을 직접 시각 확인했다.
6. 주소가 해당 시험 링크인 것을 확인한 뒤 시험 탭 1개만 닫았다. Chrome 탭 수 5→4를 확인했고 사용자의 다른 탭 내용은 출력/보존하지 않았다.

픽셀 대조는 지도 영역 안의 지정 색상 근접값을 세므로 배경 지도 등의 잔여 픽셀이 포함된다. 지도 위치·크기를 고정한 전후 비교이며 OFF가 0이어야 하는 검사가 아니다.

Chrome의 UIAutomator 정보는 체크 상태를 모두 false로 보고했고 새로고침 후 본문을 노출하지 않았다. 체크박스는 실제 픽셀을 대조했고, 차단 문구는 스크린샷을 직접 확인해 그 이미지 해시와 수동 확인 방식을 별도 기록했다. 이 결과를 스크린리더 접근성 검증으로 확장하지 않는다. PC의 Python urllib 공개 설정 요청은 403이었으나 실제 휴대폰은 정상 표시됐고 기존 Node fetch는 HTTP 200으로 실제 익명 응답을 검증했다.
