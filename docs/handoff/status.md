후속으로 사용자가 USB 휴대폰에서 **서울 하트 5km 계산을 59.95초에 완료**했습니다(SM-S942N·Android 16, 2026-09-27 16:34 KST). 16:41 KST에 확인한 에뮬레이터의 **같은 5km 입력은 301.05초**여서 이번 관측에서는 휴대폰이 약 5.02배 빠르게 완료했습니다. 후보 5개·지도 표시를 확인했고 두 기기의 순위별 raw 점수 5개가 보존 원본과 정확히 일치했습니다. 휴대폰 화면 거리도 일치하지만 전체 경로 좌표 비교는 미완료입니다. 휴대폰 최대 연속 연산 24.63ms·타이머 최대 지연 33.70ms였습니다. 각 1회 개발용 앱 관측이며 실기기 계산 중 입력·취소, 반복 측정·릴리스 성능은 후속 검증입니다.

## 이전 작업 목적과 지도·위치 — 핵심 기능 검증 당시

2026-09-26에는 **핵심 기능 테스트용 개발**을 요청받았습니다. 이후 2026-10-03 서비스 기획을 전달받아 Figma UI 기준의 RunPen 전환을 결정했습니다. 아래 지도·위치 내용은 기존 기술 검증 이력이며 당시 테스트 화면을 최종 서비스 화면으로 확정하지 않습니다.

지도 화면·MapLibre/MapTiler 연결·전경 현재 위치 확인·권한 거부 및 설정 이동·시간 초과·요청 취소를 구현했습니다. 타입·린트, 위치·설정 테스트 17개, Expo 진단 21개, Android JS 번들·개발용 APK 빌드·서명 검증이 통과했습니다. Pixel 7 에뮬레이터에서 지도·지명, 권한 거부와 설정 이동, 설정 허용 후 복귀, 모의 GPS 위치 점·지도 이동, 기기 위치 꺼짐 안내를 확인했습니다. 실제 휴대폰 GPS는 미검증입니다. 사용자 로컬 MapTiler 키 연결은 HTTP 200을 확인했습니다. 자세한 내용은 [사용법](../development/map-location.md), [검증 기록](../quality/map-location-verification.md), [실행 계획](../history/executed-plans/2026-09-26-1518-map-location.md)에 있습니다.

현재 Android 지도는 에뮬레이터 OpenGL의 글자 누락 문제를 해결한 Vulkan 설정입니다. `prebuild:android`에 `--no-clean`을 적용했고 지도 단계에서 기존 IDE/JDK/SDK 로컬 설정 보존을 확인했습니다. 지도 단계는 Metro 8082로 검증했으며 최신 SQLite APK·검증 연결은 아래 저장소 항목을 따릅니다. 아래 Studio 검증 이력은 이전 환경 단계의 결과이며 이번 설정 복원 후 Studio UI Sync·Run을 다시 확인한 것은 아닙니다.

## SQLite 저장 기반

Expo SQLite `~57.0.3`으로 앱 전용 `running-art.db`를 추가했습니다. 지연 초기화·동시 요청 공유·스키마 버전 1·트랜잭션 마이그레이션·실패 롤백·미래 버전 보호·재시도를 구현했습니다. 홈의 **저장소 테스트**에서 테스트 메모를 저장·조회·수정·삭제할 수 있습니다. 테스트 메모만 저장하며 코스·러닝 기록 스키마는 아직 구현하지 않았습니다.

전체 로직 테스트 29개(저장소 12개 + 기존 위치·설정 17개), 타입·린트, Expo 진단 21개, Android JS 번들·개발용 APK 빌드·서명 검증이 통과했습니다. Pixel 7 Android 16 에뮬레이터에서 빈 입력·CRUD·삭제 취소를 확인했고, 프로세스 강제 종료·새 PID 재실행 후 수정 내용과 삭제 결과가 유지됐습니다. 실제 Android DB를 읽어 `user_version=1`, `integrity_check=ok`, 수정한 메모 1개를 확인했습니다. 기존 지도·모의 GPS 현재 위치도 정상입니다. 실제 휴대폰·iOS는 미검증입니다.

최신 APK는 `android/app/build/outputs/apk/debug/app-debug.apk`, 검증용 Metro는 **8083**입니다. SQLite 네이티브 모듈 추가 전 APK를 사용하는 경우 다시 빌드·설치해야 합니다. 사용법·DB 위치는 [저장소 안내](../development/storage.md), 증거·제한은 [저장소 검증](../quality/storage-verification.md), 계획 원문·실행 결과는 [실행 기록](../history/executed-plans/2026-09-26-1745-sqlite-storage.md)에 있습니다.

2026-09-30 재시도·설치 기록 변경을 저장소별로 커밋하고 모바일의 기존 9개 커밋 제목을 `feat:`, `fix:`, `docs:` 같은 프리픽스와 한글 설명으로 정리했다. 후속 사용자 정정에 따라 `running-art`의 기존 8개 커밋은 원래 메시지·해시로 복원했으며 새 서버 수정은 그 뒤에 유지했다. 프리픽스와 한글 설명은 이후 새 커밋에도 적용하되 웹 저장소의 기존 이력은 변경하지 않는다. 기존 파일 내용·작성자·시각·본문과 로컬 복구 자료를 보존했다. 원격에는 push하지 않았으며 모바일은 이력 정리로 원격과 달라졌고 웹은 기존 원격 이력 뒤에 새 커밋이 이어진다. 공개 APK 소스 태그는 기존 `076d368`을 유지한다. 복구 위치·검증은 [후속 실행 기록](../history/executed-plans/2026-09-29-0815-road-search-results.md)에 있다.

최초 커밋을 생성하고 [GitHub 저장소](https://github.com/ssw3131/running-art-mobile)에 업로드했습니다. 원격 이름은 `origin`이며 로컬 `main`이 `origin/main`을 추적합니다. `.env.local`의 실제 지도 키와 로컬 도구·생성물은 제외했습니다. 타입·린트 검사가 통과했으며 자세한 결과는 [Git 업로드 실행 기록](../history/executed-plans/2026-09-26-1644-git-publication.md)에 있습니다.

## 미구현·미검증과 보류 범위 — 2026-10-03 정리

- [제품 기획](../product/overview.md)의 화면별 ‘현재’와 ‘추가 개발’을 기준으로 구현 차이를 확인한다. 기존 지도·저장·계산·GPS·Google 로그인 기반과 RunPen 서비스 화면 전체의 완료를 구분한다.
- 개인 자료 소유권·접근 정책·동기화는 별도 진행 중이다. 현재 작업 트리의 변경과 실제 서버 적용·검증·휴대폰 설치를 구분하며 이번 문서 정리로 동기화를 완료 처리하지 않는다.
- 전국 다른 지역·저사양 기기, 시뮬레이션 휴대폰 검증, 장시간 잠금·배터리·실제 이동 거리 정확도, 다른 PC 최초 설치·iOS·스토어 배포는 후속이다. 기존 저장 코스 재생·강남 계산·야외 기록의 내부 거리 합산 검증은 과거 성과로 유지한다.
- CI/CD는 **계획 저장·실행 보류**다. 별도 preview 앱 ID·서명 분리안은 단일 앱 결정으로 대체했다. 워크플로 구성이나 자동 배포를 이번 작업에서 실행하지 않았다.
- RunPen 로고·테마·서비스 화면 적용은 후속 개발이다. 현재 앱 ID·서명·기존 자료는 유지하며 별도 개발용·배포용 앱을 만들지 않는다. 출시 필수 범위·서버 환경 분리 여부는 미정이다.
- MapTiler 키는 로컬 설정으로 관리하고 도로 데이터는 모바일 전용 R2 전국 채널을 사용한다. 운영 도메인/CDN은 후속이다. 기존 GPS 검증본의 사용자 DB는 버전 3이며 진행 중인 동기화 스키마를 설치 완료된 것으로 간주하지 않는다.
- 과금안은 검토 중이며 결제·횟수 차감·저장 제한은 구현하지 않았다. 커뮤니티는 후속 확장이다. API·스키마·가격·미정 정책을 문서 정리만으로 확정하지 않는다.
- v0.2 참조 원본·고정 자료·기준 결과와 검증 증거를 보존한다. [프로토타입 출처](../architecture/prototype-migration.md)의 AI Studio 자료는 참고용이며 서비스 화면·흐름은 Figma UI를 우선한다. 의존성 취약점 수치는 [환경 검증 기록](../quality/setup-verification.md)의 측정일 기준이다.
