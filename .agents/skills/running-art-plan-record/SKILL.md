# 실행한 계획 기록

사용자의 별도 기록 요청 없이 작업 흐름의 일부로 적용한다. 기록 대상은 **실제로 실행에 들어간 계획**이다. 모든 대화·초안·향후 계획을 수집하지 않는다. [기록 규칙과 목록](../../../docs/history/executed-plans/README.md)을 기준으로 한다.

## 실행 시작

1. 실제 파일 변경 등 계획의 실행이 시작되는지 확인한다. 읽기·검토만 했거나 승인을 받았어도 실행하지 않으면 기록하지 않는다. 기존 기록이 있으면 이어 쓴다.
2. 첫 구현 변경 직전에 [템플릿](assets/executed-plan-template.md)으로 `docs/history/executed-plans/YYYY-MM-DD-HHmm-주제.md`를 생성한다. 파일명 주제는 짧은 영문 소문자·하이픈으로 쓴다. 충돌하면 초 또는 순번을 붙인다.
3. 시스템 시각을 확인해 Asia/Seoul 기준 ISO 8601과 `+09:00`을 기록한다. 기억으로 시각을 만들지 않는다. 상태는 ‘진행 중’으로 둔다.
4. 실행 직전에 확정된 계획 원문이 있으면 그대로 보존하고 출처를 남긴다. 원문이 없으면 실제 실행할 계획을 적고 ‘실행 시작 시 계획 작성’으로 표시한다. 비밀 값·개인 위치 자료는 포함하지 않는다.
5. 같은 실행 작업에서 실제 변경을 진행하고 기록 목록에 추가한다. 기록 파일만 만들고 본 실행을 전혀 시작하지 않았다면 자신이 방금 만든 파일·목록 항목을 제거하여 미실행 계획이 이력에 남지 않게 한다.

## 실행 종료 또는 후속 재개

- 실행 전 계획 본문은 유지하고 실행 결과·변경 경로·검증 명령과 결과·미검증·남은 작업을 덧붙인다.
- 현재 범위를 완료했다면 ‘완료’, 필수 작업이 남으면 ‘부분 완료’, 중단했다면 ‘중단’으로 표기한다. 작업을 계속 수행 중일 때만 ‘진행 중’으로 둔다. 종료 시각 또는 마지막 갱신 시각을 남긴다.
- 재개와 범위 변경은 해당 시각에 새 절을 추가한다. 결과에 맞춰 원래 계획을 다시 쓰지 않는다.
- 목록의 상태와 `docs/handoff/status.md`를 갱신한다. 과거 다른 작업의 미완료를 이번 작업의 완료로 덮지 않는다.
- 실행 후에야 기록을 복원하면 ‘사후 복원’, 근거 파일, 확인 가능한 날짜만 남긴다. 원래 계획 원문·시각을 알고 있었던 것처럼 쓰지 않는다.
- 기록 작업에 대해 또 기록을 만들지 않는다. 스킬 적용은 계획 실행을 승인하거나 CI/CD·배포를 재개하는 행위가 아니다.

이는 Codex가 작업 중 따르는 절차다. 예약 작업·백그라운드 감시가 아니며 Codex 밖에서 한 변경을 자동 감지한다고 주장하지 않는다.
